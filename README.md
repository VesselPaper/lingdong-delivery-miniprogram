## 项目简介

- 用户端：学生点餐小程序（18 页）——浏览商品、加购、下单、微信支付、订单管理（取消/取消申请/退款投诉）、机器人配送追踪、取餐码取餐、地址管理、活动查看。
- 商家端：商家管理小程序（19 页）——登录、工作台统计、接单（含模拟扫码配单）、一车多单配单/上货、订单管理、售后（退款/投诉）、取消申请处理、商品管理、活动发布、配送监控（真实机器人状态）、店铺营业/自动接单设置。
- 后端：Node.js + Express + SQLite，位于 backend/，配送层对接开放物流平台真实接口（可切换本地 Mock 演示），支持**一车多单配送批次**。

## 技术栈

- 小程序：微信原生，UI 全自绘（仅用 tdesign-miniprogram 的 icon 图标组件）。
- 后端：Node.js（22+，内置 node:sqlite）+ Express；轻量 .env 配置加载，零外部数据库依赖。
- 安全：小程序端不存放开放物流平台凭据与微信支付商户凭据，凭据仅后端持有。

## 一、启动后端服务器

### 1. 环境要求
- Node.js 22+（项目使用 Node 内置的 node:sqlite，Node 22.5+ 可用；本地已验证 v22 正常）。

### 2. 配置（可选，本地演示可不配）
将 `backend/.env.example` 复制为 `backend/.env` 并按需填写：
- WX_APPID / WX_SECRET：微信登录（测试阶段可不配，走演示登录）
- WXPAY_*：微信支付（未配置时支付接口返回 501）
- PLATFORM_*：开放物流平台（未配置时真实配送不下发，任务有明确提示）
- PLATFORM_MOCK=true：使用本地模拟配送状态机（本地无网络演示推荐）

### 3. 启动
方式一（命令行）：
```
cd backend
node server.js
```
方式二（快捷方式）：双击项目根目录的 `启动服务器.bat`。

看到 `[lingdong-backend] listening on http://127.0.0.1:3000` 即成功。首次启动自动建库并写入种子数据（10 个商品、10 个点位、1 个店铺）。

### 4. 验证
浏览器访问 http://127.0.0.1:3000/api/goods/list ，返回 `{"code":0,...,"data":[...]}` 即正常。
（若设置 PLATFORM_MOCK=true，控制台会提示"配送层：本地 Mock 状态机"。）

## 二、新环境首次运行并预览

> 完整流程：克隆 → 启动后端 → 开发者工具导入编译 → 预览/真机。

### 1. 前置
- Node.js 22+（后端用内置 node:sqlite）
- 微信开发者工具（稳定版）：下载 https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html ，首次使用需微信扫码登录。

### 2. 克隆并启动后端
```bash
git clone https://github.com/VesselPaper/lingdong-delivery-miniprogram.git
cd lingdong-delivery-miniprogram/backend

# ① 装依赖（node_modules 未进仓库）
npm install

# ② 建本地 .env：想完整演示配送闭环就开 Mock（机器人自动推进）
echo "PLATFORM_MOCK=true" > .env

# ③ 启动（首次自动建库+种子数据）
node server.js
```

### 3. 导入项目并编译
- 打开微信开发者工具 → 「导入项目」（或新建 → 从目录导入）。
- 目录：选择本项目的 `用户端`（或 `商家端`）文件夹。
- **AppID**：可选择「测试号」（无需注册；测试号无法真机预览与使用部分真实能力），或填写你自己的小程序 AppID。仓库里是别人的 AppID，无权限时无法导入。
- 点「导入/编译」即可看到页面；`miniprogram_npm` 已随仓库提交，无需构建 npm。

> 提示：先启动后端，再编译小程序；否则页面会提示网络异常。

### 4. 开箱即用 vs 需要配置

| 项 | 说明 |
| --- | --- |
| 数据库 | 自动建库 + 种子数据，无需配置 |
| 登录 | 演示登录，点微信登录直接成功 |
| 接口地址 | config.js 默认 http://localhost:3000/api，无需改 |
| UI 组件 | miniprogram_npm 已提交，直接编译 |
| 支付 | 未配微信支付商户 → 支付提示"通道未开通"（浏览/下单/订单/配送演示不受影响） |
| 真实配送 | 未配平台凭据 → 任务不下发；开 `PLATFORM_MOCK=true` 用本地状态机演示 |
| 开放平台点位 | 真实接入才需点位同步（商家端 → /api/merchant/landmarks/sync） |

> 真实凭据（平台 appid/secret、微信支付商户、微信 AppSecret）不进仓库，由项目负责人在线下发，各成员填到本地 backend/.env。

### 5. 预览体验流程
用户端（先编译 用户端）：
1. 「我的」→ 登录 → 微信一键登录（测试阶段直接成功）。
2. 首页浏览商品 → 加购 → 购物车结算 → 选收货地址/送达点位/送达时间 → 提交订单。
3. 支付：已配置微信支付则拉起收银台；未配置会提示支付通道未开通（订单仍生成，可稍后支付）。
4. 配送追踪：机器人推进（Mock 模式每几秒自动前进），到达后扫码/输入取餐码取餐。

商家端（再编译 商家端，工具支持多项目打开）：
1. 首次进入显示登录页 → 微信一键登录。
2. 工作台查看统计 → 订单处理「待接单」接单（店铺营业状态下）→ 配送监控查看任务与机器人。

> 双端闭环演示：用户端下单支付后 → 商家端订单出现待接单 → 接单 → 用户端配送追踪可见机器人推进 → 到达后取餐。

### 6. 真机预览
- 工具点「预览」→ 生成二维码 → 手机微信扫码打开。
- 手机访问本机后端：把 `用户端/utils/config.js`、`商家端/utils/config.js` 的 `baseUrl` 改为电脑的局域网 IP（如 `http://192.168.x.x:3000/api`），并保证手机与电脑同一 WiFi；真机需在小程序后台把该地址加入 request 合法域名（或开发阶段勾选"不校验合法域名"）。

### 7. 常见问题
- 页面提示网络异常：确认后端已启动，且 config.js 的 baseUrl 正确。
- 登录报错：测试阶段应为演示登录直接成功；若提示"未配置"说明后端非最新代码。
- 支付提示未开通：.env 未配置微信支付商户参数。
- 商品图片是色块：项目未内置真实商品图，前端用分类主题色块占位，替换商品图后自动显示。

### 8. 已有代码的成员：同步更新

项目负责人每次推送后，成员在**本地项目文件夹**（你 git clone 的那个目录）里执行即可同步到最新：

```bash
cd 校内快递配送机器人
git pull        # 拉取最新代码
```

- 后端有改动时重启后端生效：`cd backend && node server.js`（依赖没变可跳过 `npm install`）。
- `git pull` 报错说明你本地改过文件，按需二选一：
  - **想保留本地改动**（如 config.js 的 baseUrl、project.config.json 的 appid 等本机配置）：`git stash` → `git pull` → `git stash pop`
  - **不想要本地改动**：`git checkout .` → `git pull`（⚠️ 会丢弃本机未提交的改动）
- `.env` 不会随代码同步（已 gitignore）：本地演示保持 `PLATFORM_MOCK=true` 即可；要跑真实配送需线下获取平台凭据填到本地 `backend/.env`。

### 9. 成员提交改动：请用「合并」流程（不要覆盖）

> 多人协作约定：**推送前必先 pull，绝不 force 覆盖远端**。force push 会丢弃其他成员的提交。

标准提交流程（在本地项目文件夹里）：

```bash
git add .                    # 暂存你的改动
git commit -m "改动说明"      # 本地提交
git pull origin main         # ★ 先拉取合并（有冲突先手动解决再继续）
git push origin main         # 再推送（普通推送，不要加 --force）
```

- **有冲突时**：`git pull` 会提示冲突文件，手动改好 → `git add .` → `git commit -m "解决冲突"` → `git push origin main`。
- 改文件前建议先 `git pull` 再动手，减少冲突；`config.js` 的 baseUrl、`backend/.env` 这类本机配置尽量不提交（如已提交，成员用 `git stash` 保留本机值）。
- 提交信息写清楚改了什么（一句话中文即可），方便成员快速了解每次变更。

## 真实业务逻辑说明

- 登录：测试阶段为演示登录（未配置 WX_APPID/WX_SECRET 时点击微信登录直接成功）；正式环境启用真实 code2session（server.js 中注释保留，配置 .env 后取消注释）。
- 支付：微信支付 V3 JSAPI，必须配置微信支付商户参数；支付成功后前端轮询订单确认已收款（试点 PAY_MOCK=true 模拟支付）。
- 配送：后端默认调开放物流平台真实接口（queue/create 排队任务、basicList 状态轮询、eviz 位置、feedbackDeliveryTaskUrl 回调）；PLATFORM_MOCK=true 时用本地模拟状态机。
- **一车多单（配送批次）**：无人车单仓最多放 12 件商品（BATCH_MAX_ITEMS，容量按商品件数计）。商家接单（含自动接单）后订单按商品总件数以 **best-fit 最优分批**并入「组单中」批次（件数 <12 整单同批、>12 独占新批）；批次派车时按送达点位做贪心最近邻路径规划（近似最小化顾客总等待），为每单创建独立平台任务（同一机器人/货仓、每单独立取餐码）；商家整批上货（开舱→放货→关舱→整批派发）；机器人按路线逐点位配送，用户凭本单取餐码开舱取走自己那份（orders.picked_up_at），**仓内全部取完 → 批次完成**。详见 doc/03 §1.1 与 doc/07 链路 7.1/7.2/18/19。
- 店铺状态：营业/自动接单为后端真实状态（shops 表 + /api/merchant/shop）；**歇业状态同步用户端**（GET /api/shop/status 公开接口），用户端结算按钮置灰、禁止下单、店铺标签标「歇业」，后端 /api/order/create 兜底拒绝。**自动接单**：营业中且开启自动接单时，用户支付即自动接单并入配送批次（无需商家点击）。
- 订单取消：免费取消窗口内（默认 10 分钟，FREE_CANCEL_WINDOW_MS 可配）可直接取消（不论商家是否接单、未真正开始配送即可）；超时未配送须提交「取消申请」由商家判断（同意→取消、拒绝→继续）；配送中不支持取消，送达后可走退款/投诉（退货退款）。取消订单会从配送批次计数移除。
- 售后：用户可对已送达/已完成/配送异常订单申请退款或投诉；商家在售后列表处理（同意退款可改金额/拒绝需理由/回复投诉）。
- 扫码（测试阶段全为模拟）：商家「模拟扫码配单/模拟扫码识别机器人」、用户「模拟扫码取餐」均不调用真实相机，直接走对应业务逻辑；正式上线替换为 wx.scanCode 真实扫码（用户扫机器人屏二维码、商家扫机器人机身二维码）。
- 我的页红点：**进行中的订单数**（待接单/配送中/已送达待取餐）在「我的」页**全部订单/配送中图标内右上角**常驻显示红点+数字（/api/user/order/badge），点开订单列表/详情**不清除**，订单全部处理完（完成/取消/退款）才消失。
- 任务页（商家订单列表）：底部四分类「待接单/待上货/配送中/待取货」（stage 过滤 + stage_text 分类文案着色；待上货/配送中/待取货按**批次分组**——一个批次一个卡面、批次内嵌套多单，点单进详情）；**四个分类卡面均完整展示商品图/价格/数量**（与上货配单页一致）；右上角「配单上货」直达配单页。**商铺首页主面板「待上货/配送中」点击直接进入任务页对应分类**（不再跳配送监控/配单页）。
- **配送监控·真实地图**：监控页顶部用**平台真实校园地图**（building/mapInfo 的 map.png + 可通行路网 graph）绘制配送点/上货点/机器人实时位置（eviz robotpose）/活跃配送路线，底部图例；`GET /api/merchant/map` 返回地图与坐标数据（bbox 映射）。
- **配送异常订单处理**：独立「配送异常」页（分类：全部/待处理/已处理 + 搜索 + 商品卡面），机器人超时未接单/上货失败/送货失败 → 订单「配送异常(6)」，商家二选一——①「重新配送」作废旧任务并并入新组单批次再派车；②「取消并退款」置已退款、写售后记录、回补未售库存（`/api/merchant/order/exception/retry|refund`，orders.exception_handled 记录处理态）。
- **模拟开舱 + 模拟送达（测试阶段）**：上货配单页「模拟打开舱门」开舱/关舱本地模拟；「开始配送」后**模拟 ~10 秒到达**（`DEVICE_MOCK=true` + `MOCK_ARRIVE_MS` 默认 10s，后端自动把批次内订单标记为已送达进入待取货，提示「测试阶段配送时间模拟为10秒」）；配送中订单详情**无任何操作按钮**（真实阶段由平台回调推进）。
- **组件库**：`商家端/components/`（search-box / empty-view / goods-row / status-text / batch-card / order-card），全局注册，核心页已接入，保证风格统一、缩减主代码量。
- UI 风格统一（商家端）：以 app.wxss 设计系统为准——卡片 12rpx 圆角+描边（不用大圆角重投影）、按钮 8rpx 圆角（box-sizing:border-box 防溢出）、统一搜索框、状态色/标签色全局 class（st-*/tag-*）。
- 商品库存/销量：**下单即扣库存**（防超卖，售罄商品拒绝下单）；**收货完成（已送达/已完成）时已售 +数量**（orders.goods_settled 幂等）；取消/退款且未售出时**回补库存**。商家「标记售罄」= 库存置 0；库存 0 时用户端商品列表/详情/购物车显示「售罄」、加号置灰、结算拦截。
- 商品分类：新增/编辑商品时分类为**选择器**（`/api/merchant/goods/categories`），可点选现有分类或「＋新增分类」直接输入。

## 一车多单配送说明

1. **一车多单**：一个配送批次最多 12 件商品，一次装载、一条路线逐点位配送，降低单车空驶、摊薄配送成本。
2. **一个仓多个人拿（拿完判断）**：每单独立取餐码；`orders.picked_up_at` 记录每单是否已取走；仓内全部取完 → 批次「已完成」。用户端展示「本车共 N 单 · 已取 X 单」。
3. **多地点配送规划**：按送达点位分组，从上货点做贪心最近邻排序（近似最小化顾客总等待时间），生成停靠顺序；每单创建独立平台任务并指定同一机器人，priority 按停靠顺序递减提示平台排程；同点位多单合并为一站。
4. **取餐码策略**：同一车不同用户取餐码**各不相同**（防拿错、按任务匹配开舱）。
5. **接口实现**：`delivery_batches` 表 + 批次接口（列表/派车/详情）、批量上货接口（整批开舱/关舱/派发）、自动派车调度、同批次进度接口；详见 doc/02 §9.29~9.33 与 doc/04 §8.1。
6. **商家流程优化**：接单后弹窗直达「配单/上货」页；商铺首页底部固定居中圆形「配单上货」按钮（带待上货+组单中批次数角标）一键进入上货页；任务页右上角「配单上货」直达；**上货配单页**顶部搜索框（批次/订单/商品/点位），批次→订单→商品三层卡面分明，商品一行一个（价格在数量前），批次内全部订单全部商品完整展示；页面只展示**组单中（可派车）+ 待上货（可上货）**两类批次，配送中/待取货由配送监控与任务页展示；点「选择该批次上货」进入**批次上货详情页**（完整批次编号弱化显示、模拟打开舱门→关舱→立即配送，左上角返回回到批次列表、派发完成自动返回），无任何页面内冗余返回按钮。
7. **当日序号**：批次与订单均有 `daily_seq`（每天从 1 重置累计，历史数据按创建日回填）——商家端卡面显示「批次 N / 订单 N」便于辨认，完整批次编号只在单批次详情弱化显示、完整订单号只在订单详情页显示。
8. **商铺首页主面板**：依次展示「待接单 / 待上货 / 配送中 / 待取货」四态（无待办数字弱化显示；异常、售后放主面板下方次面板），`/api/merchant/stats` 返回对应计数；任务页底部四分类「待接单/待上货/配送中/待取货」按 stage 过滤（后端 /api/merchant/orders?stage=）。
9. **配送监控按批次分组**：配送中（批次状态=2）在监控页与任务页「配送中」分类均以**一个批次一个卡面**展示，卡内嵌套多单与「已取 X/N」进度；待取货分类同样按批次分组。
10. **用户订单详情配送进度条**：上方展示「已接单 → 配送中 → 已送达」三段进度条（每段下方圆圈，到达即填满），已删除「查看配送位置」按钮。
11. **配送监控真实地图**：监控页地图用平台 mapInfo（真实校园地图图片 + 路网 graph），叠加配送点/上货点/机器人位置/配送路线，5 秒轮询刷新。

白灰底 + 品牌蓝 #3078C0 + 黑灰文字 + 浅蓝辅助 #DCE9F8，干净整洁的电商蓝风格。设计变量与自绘组件层（btn/cell/field/nav/stepper/popup）见双端 app.wxss。

## 核心功能

- 用户端：登录、商品浏览/搜索/分类、购物车、选点位下单、微信支付、订单管理（直接取消/取消申请/退款投诉）、取餐码、机器人配送追踪（含同车进度）、模拟扫码取餐、售后记录、地址管理、活动查看、我的页订单红点。
- 商家端：登录、工作台统计、接单（自动/手动，接单后直达配单）、一车多单配单/上货（组单→派车→整批开舱/关舱/派发）、订单管理、商品管理、活动管理、售后处理（退款/投诉）、取消申请处理、配送监控（真实机器人状态）、店铺营业/自动接单。
- 后端：用户/商品/购物车/订单/地址/配送/售后/取消申请/配送批次/商家/活动接口 + 开放物流平台对接（任务创建、状态轮询、位置获取、回调接收、点位同步、批次批量建任务/批量上货）+ 微信支付/登录。
