## 9. 给下一个 Agent 的操作注意事项（踩坑记录）

- **PowerShell**：无 `&&` 链式；用 `;` 或分步。内联 `node -e "..."` 的引号/`$` 容易炸 → **写临时脚本文件再执行**。
- **git commit 消息**：PowerShell 传多行 `-m` 会被按空白拆分 → **用 `git commit -F 消息文件`**。
- **LF/CRLF 警告**：git 提示 "LF will be replaced by CRLF" 无害（autocrlf）。
- **后端进程**：启动/重启用后台任务（`run_in_background`）；重启前先 `Stop-Process` 掉旧的 `node server.js`（只杀含 server.js 的进程，别杀 DSH web 的 node）。
- **node:sqlite**：`new DatabaseSync(path)`；并发读写 WAL 模式 OK；临时诊断脚本用 `{ readOnly: true }`。
- **微信小程序**：组件 `styleIsolation:"apply-shared"` 才能用 app.wxss 全局类；图片防拉伸固定写法 = 「定尺寸容器 overflow:hidden + 内部 image width/height:100% display:block」（不要把 flex 直接放 image 上）；`data-*="{{obj}}"` 可传对象；组件事件用 `triggerEvent`，页面用 `bind:事件`。
- **接口约定**：成功 `{code:0,msg:'success',data}`；商家接口 `merchantGuard`、用户 `auth`；登录演示 `POST /auth/login {code:'任意', role:'merchant'|'student'}` 返回 token 放 `Authorization: Bearer`。
- **订单状态**：0 待支付/1 待接单/2 配送中/3 已送达/4 已完成/5 已取消/6 配送异常/7 已退款；**批次状态**：0 组单中/1 待上货/2 配送中/3 已完成/4 异常。任务状态码见 doc/06 或 platform.js STATUS_TEXT。
- **测试阶段开关**：商家端 `DEVICE_MOCK=true`（loading.js / batchDetail.js 顶部）；后端 `MOCK_ARRIVE_MS` 默认 10s。
- **临时脚本一律用后删除**（`_*.js` 开头），避免误提交。
