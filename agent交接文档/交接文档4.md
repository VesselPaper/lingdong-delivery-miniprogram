## 4. 关键架构与代码位置（本会话更新点）

- **无可用车友好提示**：`server.js` `doDispatchBatch`（~1333）真机档先 `pickAvailableRobot`，无车则查 `getDeviceList` 拼设备状态抛「暂无可用无人车：…」（1336-1358）；前端 `商家端\pages\device\loading.js selectBatch` 失败用 `wx.showModal`（非 toast）
- **登录链路**：`商家端\pages\user\login.js` 与 `用户端\pages\user\login.js` 的登录 POST 都带 `{ needAuth: false }`；双端 `utils\request.js` 无 token 且 needAuth=true 时直接 reLaunch/navigateTo 登录页，不发请求
- **取餐超时两段式**：`services\platform.js recreatePickupTask`（~501）一段超时「回来再等」（不把订单改回配送中、不重新 loading）；二段超时（`pickup_revisit_at` + `PICKUP_RETRY_TIMEOUT_MS`）驳回退款
- **路线规划推迟**：`doDispatchBatch` 定型时只建平台任务不传 route（1375-1377 注释）；关舱后 `/merchant/device/batch/dispatch` 时用 `batch.planRoute` 计算并写 `batch.route`
- **送达点位过滤**：结算页/地址页按送达点类型过滤（排除 type='loadingPoint' 的上货点）
- **召唤**：`platform.summonToLoadingPoint`（platform.js ~461）POST `/open-api/v1/lightTask`，`expireTime=now+10min` 毫秒时间戳字符串，空闲车优先（idle/standby/charging/returnChargingPile/returnStandby），召唤成功不打印

## 5. 平台实测结论（沿用交接文档3 §5，接替者勿违背）

1. **排队任务 queue/create**：完整上货流程，但**机器人充电中不拉取**（待机自动回充电桩 → 排队任务永远等不到车）
2. **直接下发 create/direct**：充电中能执行，但**语义 = 货已在舱**（busyStocks 占用）→ loadingVerify 报「机器人当前不在取货阶段」；机器人去上货点**卡住转圈**（已紧急关闭）
3. **drawerCtrl 可独立开关舱门**（不受任务状态限制）
4. 结论：派车走 **queue/create（排队）+ lightTask 召唤待命 + 商家点上货按钮定型**。**不要改回 create/direct**
