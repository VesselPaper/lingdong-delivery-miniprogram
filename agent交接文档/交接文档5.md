3. **坐标系**：eviz `robotpose` 与点位坐标（平台局部米）不是同一坐标系。已标定相似变换（`robotposeToMeters`：s=182.67, rot=-55.37°, t=(-2144.6,4649.8)，两组实测对应点：商铺上货(18.262,6.537)↔(733,2583)、充电点1(19.931,8.125)↔(1145,2497)，自洽验证通过）。**注意**：平台重标定地图后需重新标定。点位已重新 `syncLandmarks`（上货点现为 18.262,6.537）。

## 3. ⚠️ 用户报的两个问题（明天修，今晚不动代码）

### 问题 1：已有订单时车不移动到上货点
- 现象：批次已有订单（组单中/待上货），但车没去上货点；用户怀疑「原本有订单+改完代码后没检测到」。
- 待查：15s 召唤扫描（server.js setInterval BATCH_SCAN_MS）对**服务重启前就存在**的组单中批次是否生效；以及机器人当时是否处于召唤被拒的状态（returnChargingPile/lightTask）。**可能方向**：①召唤扫描失败静默，需在诊断期加临时日志确认；②车被卡在 returnChargingPile 时召唤被拒（§1）；③考虑让扫描对 status=1（待上货）批次也补召唤（当前只在 status=0 组单中召唤）。

### 问题 2：batchDetail 页面 phase 状态不恢复（重进页面按钮错乱）
- 现象：上货定型→开舱（舱门开）→关舱（create/direct 建任务，自动关舱）→点「稍后」→**退出页面重进**→页面只显示「打开舱门」（没有「立即配送」）→再点开舱→报「有任务正在执行」开不了。
- 根因：`商家端/pages/device/batchDetail.js` 的 `phase`（scanned/open/loaded/dispatched）是**前端本地状态**，`onLoad` 只读 options 的 at/dist/lmsg，**不根据后端批次/任务状态恢复**。重进后 phase='scanned' → 显示「打开舱门」。
- 修复方向：`batchDetail.js load()` 拉批次详情后，**按后端状态计算初始 phase**：批次 status=2 → dispatched；任务已创建（platform_task_id 非空 / task_status=50）→ loaded（显示「开始配送」）；已预创建/持控制权 → open；否则 scanned。需后端 `batchDetail` 返回任务状态信息（确认已含 task 的 platform_task_id/task_status）。
- 附带：重复开舱应有后端守卫/清晰文案（已有 create/direct 任务时禁 preCreate，报「任务已创建，请开始配送」而非泛化的「有任务正在执行」）。
