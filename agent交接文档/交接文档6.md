### 2.1 商家邀请码方案A（收紧加固）—— 核心

目标：**不再信任客户端自报角色，让"邀请码"从共享口令收紧为"按商家一个、绑定 openid、可吊销"**。用户已明确不再采用"商家端免码登录"的临时放开。

- **表** `merchant_invites`（`db.js`，`CREATE TABLE IF NOT EXISTS`）：`code_hash`（= sha256(码.toUpperCase())，**纯哈希，明文不落库**）、`name`、`note`、`bound_openid`、`active`、`created_at`。`code_hash` 有 UNIQUE。
- **服务** `backend/services/merchantInvite.js`：
  - `verify(store, code, openid, bind)`：大小写不敏感；优先查 `merchant_invites`；`bind=true`（真实登录态）时**首次使用绑定 openid**、且已绑定为他人→ `bound_other`；`MERCHANT_INVITE_CODE` 仅作旧单一码兜底。
  - `configuredCount(store)`：有效条数 + env 旧码，供启动日志。
  - `message(reason)`：给登录接口返回中文提示；`generate()`：生成随机码（去掉 0/O/1/I）。
- **维护脚本** `backend/tools/merchant_invite.js`（在 `backend` 目录跑）：`add --name … [--code …][--note …]` / `list` / `revoke --id` / `activate --id` / `unbind --id`。**add 生成时明文只打印一次**；`--code` 不传则自动生成随机码。
- **登录接口** `server.js` `/api/auth/login`：
  - 商家端（client=merchant）：老商家 openid 免码续登；否则**必填且校验**邀请码 → 错误对应 `403`（请填写商家邀请码 / 不正确 / 已绑定其他账号）。
  - 用户端：填正确邀请码可升级为商家；填错/他人绑定不报错、保持学生。
  - **登录限流**：`loginFail`（按来源 IP，内存态，`LOGIN_LIMIT=20/10min`），失败累计、成功回降——防暴力试码。

```bat
cd C:\Users\82652\Desktop\lingdong-delivery\backend
node tools\merchant_invite.js add --name "零栋铺子"      :: 生成随机码，明文只打印这一次

node tools\merchant_invite.js revoke --id 1             :: 吊销（作废）
node tools\merchant_invite.js unbind --id 1             :: 解绑，允许另一微信再用
node tools\merchant_invite.js activate --id 1           :: 重新启用
```

- **同一码表里只能一条记录**：`revoke` 只是 `active=0`。若想"换店名复用同码"，直接再 `add --code 同码`即可——工具会检测到已吊销同码并**自动重新启用 + 清空绑定 + 更新店名**（不会 UNIQUE 报错）。同码已**有效**时再 add 会提示"该码已存在且有效"。
- **首次绑定**：真实登录态下一个码绑定一个 openid。给某个商家前不要自己同码先试，否则码会绑定到测试号（商家登录报"已绑定其他账号"）。
- **重启后端**才生效：关旧进程 → 双击 `启动服务器.bat`。

### 3.1 商家邀请码「添加 / 更换」全流程

**A. 给新商家发首码（add）**

```bat
cd C:\Users\82652\Desktop\lingdong-delivery\backend
node tools\merchant_invite.js add --name "东苑1栋" --code 123456   :: 指定固定码
node tools\merchant_invite.js add --name "东苑1栋"                 :: 不传 --code 则自动生成随机码
```

输出示例：
```
[OK] 已生成邀请码 id=1  商家=东苑1栋
[码] 123456
      ---- 明文只显示这一次，系统只保存其哈希；请线下交给对应商家。
```
- **`--code` 可不传**，自动生成随机码（去掉 0/O/1/I）。
- **明文只打印这一次**，系统只存哈希、明文找不回；务必线下把码交给对应商家本人，丢码只能 revoke 重发。
- 同一个商家只分配一个码（一码一 openid）；码→商家的对应关系靠 `--name` 记录。
- **之后给商家前先 `list` 确认**，避免重复 add 撞 UNIQUE 或误绑。

**B. 换码 / 重发生效（换店名、码泄露或丢码时）**

```bat
node tools\merchant_invite.js revoke --id 1    # ① 先吊销旧码（作废，商家登不进）
node tools\merchant_invite.js add --name "东苑1栋"   # ② 生成/自定义新码，把新码发给商家
node tools\merchant_invite.js list              # ③ 核对新码 id / 有效 / 未绑定
```
- `revoke` 只作废，不删记录；旧码立刻失效（登录被拒）。
- 新 add 会新建一条记录拿到新 id；若加的是**已吊销的同码**，工具会自动重新启用 + 清空旧绑定 + 更新店名（不会 UNIQUE 报错）。
- **重启后端后才生效**（关旧进程 → 双击 `启动服务器.bat`），重启日志应显示 `商家邀请码已启用：N 个有效`。

**C. 交付后的验证**
- 让商家在**真实商家端**凭新码首次登录 → 码自动绑定其 openid，成功进入商家态。
- 不要自己拿新码先登录测试，否则会绑到自己测试号（之后商家登录报"已绑定其他账号"）；确需自测请先用 `unbind` 清绑定。
