最后更新：2026-09-04
适用范围：送餐无人车微信小程序（用户端 + 商家端 + 后端）
来源：项目进度/04\_需求清单.md（R1~R6）、文档/小程序技术方案草案.md、沟通记录

## 1. 项目概述

四川师范大学校内引入无人送餐车，面向师生提供无人化外卖配送。本小程序是核心下单与配送追踪载体，分为：
用户端：学生点餐、支付、查看配送进度与机器人位置、取餐验证。
商家端：零栋铺子管理商品、处理订单、上货确认、配送监控、活动发布。

## 1.1 一车多单（配送批次）需求

现实中无人车单仓可放多份商品（最多 12 份）。需求将单次出车扩展为「一个配送批次」，一次装载并配送最多 12 单：

1. **一车多单**：商家接单（含自动接单）后订单并入「组单中」批次；批次满 12 单或自动接单模式等待期满自动派车，商家也可手动派车。
2. **一个仓多个人拿（拿完判断）**：每单独立取餐码，用户凭本单取餐码开舱取走自己那份；`orders.picked_up_at` 记录每单是否已取走，仓内全部取完 → 批次完成。
3. **多地点配送规划**：按送达点位分组 + 从上货点贪心最近邻排序（近似最小化顾客总等待时间），生成停靠顺序并据此为每单创建平台任务（同一机器人/货仓、priority 递减提示排程）；同点位多单合并为一站。
4. **取餐码策略**：同一车不同用户的取餐码**各不相同**（防拿错、按任务匹配开舱）。
5. **接口实现**：后端新增配送批次表与批次接口（列表/派车/详情）、批量上货接口（整批开舱/关舱/派发）、用户端同批次进度接口；前端「配单/上货」页按批次操作，接单后直达配单页。

## 3. 核心业务流程

### 3.1 主流程：下单配送闭环

学生下单 → 微信支付 → 商家接单/自动接单（并入配送批次，一车≤12单）→ 批次派车（路径规划+批量创建平台任务）→ 机器人到店 → 商家整批上货 → 机器人按路线逐点位配送 → 到达取餐点 → 学生凭本单取餐码开舱取走自己那份 → 仓内全部取完 → 批次完成

1. 学生浏览商品，加购 / 立即购买。
2. 确认订单：选收货地址（自动带出点位/姓名/电话）→ 选送达点位 → 提交。
3. 微信支付（JSAPI，试点 PAY_MOCK 模拟）；支付成功后订单「待接单」；**营业中且开启自动接单时自动接单并入配送批次**。
4. 商家端收到待接单 → 接单（订单并入「组单中」批次，店铺歇业时拒绝）；接单后直达「配单/上货」页。
5. 批次派车：路径规划 + 为每单创建平台任务（同一机器人）→ 机器人前往上货点。
6. 商家整批上货：模拟扫码识别机器人 → 整批开舱 → 放货 → 关舱 → 整批确认出发。
7. 开放物流平台调度机器人按路线逐点位配送；到达某点位该点位订单「已送达」。
8. 学生端配送追踪页查看进度与位置（含同车进度：本车共N单/已取X单）；学生在机器人屏幕输入本单取餐码 → 开舱取走自己那份 → 本单「已完成」。
9. 仓内全部订单取走 → 批次「已完成」。

### 3.2 支付流程

后端统一下单（微信支付 V3 JSAPI）→ 返回 payParams → 前端拉起收银台 → 微信服务器回调 /api/pay/notify → 订单置为已支付 → 前端轮询确认已收款。

### 3.3 配送状态联动

平台任务状态 → 订单状态：

- 任务 70 到达取餐点 → 订单 3 已送达
- 任务 80 完成 → 订单 4 已完成
- 任务 110/150 取消/关闭 → 订单 5 已取消
- 任务 90/100 失败系 → 订单 6 配送异常

## 6. 交互逻辑要点

- 未登录：用户端访问需登录接口时跳登录页；商家端启动无 token 跳登录页；接口 401 清 token 回登录页。
- 结算页与收货地址联动：进入自动选默认地址，回填点位+姓名+电话；从地址管理返回自动刷新。
- 店铺歇业：商家端后端拒绝接单，前端按钮置灰提示。
- 店铺歇业同步到用户端：商城店铺卡与确认订单页店铺标签旁展示「歇业」，确认页结算（支付）按钮置灰、不可提交；后端 /api/order/create 兜底拒绝（400 店铺歇业中，暂无法下单）。
- 配送追踪：用户端每 3 秒轮询；商家配送监控每 5 秒轮询；机器人接口失败以错误卡呈现（静默不弹 toast）。
- 支付成功：前端轮询订单确认已收款（支付回调可能延迟）。
- 取餐码：机器人到达后须匹配本单 pickup_code 才能确认取餐；**同一车不同用户取餐码不同**（防拿错）。
- 购物车数量（商城/详情/购物车页三处统一）：数量为 1 时点「−」= 移除该商品（调 /cart/remove）；仅数量为 0 时「−」置灰不可点。
- 商城页交互：整页不滚动、搜索框/店铺名固定，左分类栏与右商品栏各自独立滚动；左分类选中高亮（白底药丸+蓝指示条）并随右栏滚动联动；卡片右侧「+」加购、加购后变「− 1 +」步进器，−/+ 用 catchtap 阻止冒泡、不跳详情；底部购物车栏悬浮于 tabBar 之上，列表内容预留底部滚动余量。
- 自动接单：营业中且开启自动接单时，用户支付即自动接单并入配送批次（无需商家点击）；自动接单模式下批次成立超 90s（BATCH_WAIT_MS）或满 12 单自动派车。
- 我的页红点：订单到达（待接单）或状态已接单（配送中）等未读动态在「我的」页订单图标显示红点；进入订单列表/详情即已读清除。
- 模拟扫码（测试阶段）：商家「模拟扫码配单/模拟扫码识别机器人」、用户「模拟扫码取餐」均不调用真实相机，直接走对应业务逻辑；正式上线替换为 wx.scanCode 真实扫码。
- 一车多单同车进度：用户配送追踪/订单详情展示「本车共 N 单 · 已取 X 单」，提示凭本单取餐码取走自己那份。
- 取餐（取餐页）：打开舱门→取餐→关舱门；40 秒未关舱平台自动关，可重新打开舱门（防未取到餐）；开舱即标记本单已取走。
- 订单取消规则：下单后免费取消窗口内（默认 10 分钟）可直接取消，**不论商家是否接单**、只要未真正开始配送（任务状态 < 50）；超过窗口且未配送（待支付/待接单）须提交「取消申请」由商家判断（同意→订单取消，拒绝→订单继续，用户可再次申请）；配送中不支持取消，送达后可走退款/投诉（退货退款）。取消订单会从配送批次计数移除。

## 7. 异常场景

| 场景                            | 处理                                                    |
| ------------------------------- | ------------------------------------------------------- |
| 支付失败 / 用户取消支付         | 订单保持「待支付」，可在订单列表/详情继续支付           |
| 支付回调未达                    | 前端轮询订单状态兜底确认已收款                          |
| 店铺歇业时接单                  | 后端拒绝（400 店铺歇业中），前端置灰                    |
| 机器人配送失败（上货/送货失败） | 订单转「配送异常」（6），任务列表展示失败状态           |
| 机器人还未送达就点取餐          | 后端拒绝（机器人还未送达）                              |
| 取餐码不匹配                    | 后端拒绝（取餐码不匹配）                                |
| 配送中订单取消                  | 后端拒绝；仅免费窗口内且未真正开始配送可取消；配送中须送达后走退款/投诉 |
| 超过免费取消窗口               | 不可直接取消，引导提交「取消申请」，由商家判断是否同意                  |
| 平台未配置 / 机器人接口失败     | 商家机器人页显示错误卡 + 重试按钮                       |
| 开放物流平台凭据缺失            | 接单创建任务提示「未配置平台凭据」，任务不下发          |
| 批次派车时无可指派机器人        | 未指定 deviceSn 且无在线空闲机器人时由平台队列分配       |
| 批次组单中订单全部取消          | 批次计数归零标记异常（4），下一单新建批次               |
| 仓内有人已取走自己那份          | 同批次其它用户仍可正常取餐；全部取完批次才完成          |
| 商品库存为 0                    | 商品不可加购（前端售罄态）                              |
