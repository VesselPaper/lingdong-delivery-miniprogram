# 04 · 核心业务链路 · 06 取餐超时与管理会话

## 10. 取餐超时两段式（送达未取 → 一段返程 → 二段驳回退款）

触发点：订单已送达(3)后无人取餐，由 `backend/domains/delivery/timers.js` 第③定时器驱动（PICKUP_SCAN_MS 默认 30s，**恒开**，demo 档也生效）。

后端处理：`backend/domains/delivery/service.js → scanPickupTimeouts(store, deps)`，四步：
1. **取餐守卫**：`picking_up_at` 超过 PICKUP_PICKING_GUARD_MS（默认 5 分钟）未关舱 → 视为「打开后没取」，清 `picking_up_at` 回待取货（计时恢复，防打开舱门永久暂停超时）；
2. **一段超时**：status=3、未取、未在取餐、`pickup_timeout_stage=0` 且 `delivered_at` 超 PICKUP_TIMEOUT_MS（默认 15 分钟）→ CAS 置 `pickup_timeout_stage=1`；批次还有其他在送/待取订单 → `moveStopToEnd`（本单停靠点移到批次路线末尾，「先送其他单」，展示与地图顺序同步调整）；无其他单 → 继续等待；
3. **返程再等**：一段超时单所在批次不再有「配送中 / 未超时待取」的其他单 → `revisitUnpickedOrder`（delivery/service.js）CAS 置 `pickup_timeout_stage=2 + pickup_revisit_at` → 作废旧任务（`voidTaskByOrderRevisit`）→ 召唤模式 `deps.platform.summonToPoint` 直接召唤到该单取餐点位再等（不重建配送任务，避免与无任务召唤模型冲突）；直发模式 `deps.platform.recreatePickupTask` 重建任务让机器人回来等；
4. **二段驳回**：`pickup_revisit_at` 超 PICKUP_RETRY_TIMEOUT_MS（默认 15 分钟）仍没取 → `rejectUnpickedOrder`（delivery/service.js）：`deps.order.realRefundOrLocal` 全额退款 → `deps.order.applyOrderCancelled({finalStatus:7, reason:'取餐超时，订单驳回退款'})`（作废任务/摘批次/回补库存）→ 插 refunds 自动退款记录（status=3，reply='取餐超时自动退款'）→ 订单置 `pickup_timeout_stage=3`。

状态流转：3 已送达 →（一段）stage=1 →（返程）stage=2 →（二段超时）7 已退款；全程 picked_up_at 为空。

落库字段：orders.pickup_timeout_stage/pickup_revisit_at/picking_up_at（清空）；delivery_batches.route（重排）；refunds 自动退款行。

用户端提示：track 接口按 stage 给文案——正在取餐 /「取餐超时，先送其他单，稍后返回本点位」/「已再次到达等待，即将取消订单，请尽快取餐」。

## 11. 管理员会话（登录限流 → session token → /me → 登出吊销）

触发点：管理员网页登录页输入用户名+密码（方案A 账号体系，替代旧共享静态 ADMIN_TOKEN）。

### 11.1 登录（限流 5 次锁 10 分钟）

请求接口：POST /api/admin/login（username、password）。

后端处理：`backend/domains/admin/routes.js → /admin/login`：
1. 限流：`loginFails` Map（键 = 用户名小写 + ':' + IP），`loginLocked(key)` 命中锁定窗口直接 429「尝试次数过多，请 10 分钟后再试」；`recordLoginFail(key)`——同一「账号+IP」连续失败 `ADMIN_LOGIN_MAX(5)` 次后锁 `LOGIN_WINDOW_MS(10 分钟)`（Map 上限 10000 防泄漏）；
2. 校验：`backend/services/adminAuth.js → findByUsername` + `verifyPassword`（scrypt 加盐哈希，恒定时间比较）+ 账号 status=1；任一失败记限流并 401；
3. 签发：成功清计数 → `q` 更新 last_login_at → `adminAuth.issueSession(store, admin.id)`——`crypto.randomBytes(32).toString('hex')` 随机 token 插入 admin_sessions（expires_at = `datetime('now','localtime','+N days')`，ADMIN_SESSION_DAYS 默认 7 天）→ `audit('admin/login')`。

状态流转：无业务状态；admin_sessions 新增一行。

落库字段：admin_users.last_login_at；admin_sessions（token、admin_user_id、expires_at）；audit_logs。

结果返回/后续：返回 `{ token, admin }`，前端存 localStorage，后续请求带 `x-admin-token` 头（**只认请求头，不接受 query 参数**，防令牌进访问日志/浏览器历史）。

### 11.2 会话校验（/me）与中间件

请求接口：GET /api/admin/me。

后端处理：`adminGuard`（`backend/domains/_shared.js`）：取 `x-admin-token` → `adminAuth.resolveSession(store, token)`（JOIN admin_users，`expires_at > now` 且 status=1）→ 失败 401「未登录或登录已过期」。/me 返回 `{ admin }`，前端启动/刷新时校验会话有效性。

### 11.3 登出吊销

请求接口：POST /api/admin/logout。

后端处理：`adminAuth.revokeSession(store, token)`——`DELETE FROM admin_sessions WHERE token=?` 删行即吊销（旧 token 立即失效），audit 落账。改密码（POST /admin/password）后 `revokeAllSessions` 吊销该账号全部 session 强制重新登录。
