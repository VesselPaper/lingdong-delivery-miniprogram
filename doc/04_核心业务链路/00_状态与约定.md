两条配送模式（由 `SUMMON_DELIVERY` 环境变量切换，见 backend/services/runtime.js）：
- 召唤多单配送（summonDelivery=true）：不创建逐单配送任务，机器人按轻任务（lightTask）逐站召唤推进，开/关舱走 drawerCtrl 直接控制；
- 直发模式（默认 false）：派车时为每单创建独立平台配送任务（queue/create），开/关舱走 loadingVerify/unloadingVerify 任务态接口。

## 0.1 运行模式与通用鉴权约定

运行模式三档（backend/services/runtime.js → check/assertBootable，启动强约束，非法组合直接拒绝启动）：
- demo（默认）：要求 `PLATFORM_MOCK=true`，禁止连接任何真实物流平台；设备控制走本地模拟（deviceMock=true）；登录/支付可走演示；
- pilot（试点）：允许连测试物流平台（主机名以 test- 开头）与真实设备，`PAY_MOCK=true` 模拟支付；连生产平台需 `ALLOW_UNSAFE_PROD_PLATFORM=true` 显式担责；
- production（正式）：启动守卫强制用户端/商家端真实微信登录（WX_APPID/WX_SECRET、MERCHANT_WX_APPID/MERCHANT_WX_SECRET）、真实支付（微信支付四要素）、真实配送（禁 PLATFORM_MOCK）——演示登录 + 模拟支付的组合在正式档不成立。

通用鉴权约定（backend/domains/_shared.js）：
- `auth` 中间件：`Authorization: Bearer <token>`，token 即 openid，直接查 users.openid 识别用户（401 未登录/登录失效）；商家接口叠加 `merchantGuard` 校验 role=merchant（403 无权限）；管理员接口走 `adminGuard` + `x-admin-token`（见链路 11）；
- 统一返回：`ok()` → `{ code:0, msg, data }`；业务错误返回对应 HTTP 状态码 + `{ code, msg }`，业务异常统一 400 JSON 而非裸 500；
- 审计：接单/派车/设备控制/退款/取消等敏感操作写 audit_logs（user_id、user_role、action、target、detail），操作可追溯。

数据库与运行环境：SQLite（backend/data/lingdong.db，node:sqlite 内置驱动，单文件、同步 API）；所有时间戳统一 `datetime('now','localtime')` 本地时钟源；编号/状态/审计三张辅助表（seq_counters、audit_logs、pay_notifications）随业务写入。配置均来自 backend/.env（复制 .env.example 填写），运行模式三档见上。
