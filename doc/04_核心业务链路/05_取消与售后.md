# 04 · 核心业务链路 · 05 取消与售后

## 8. 取消链路（免费窗口直接取消 → 超时取消申请）

### 8.1 免费窗口直接取消

规则：下单后 FREE_CANCEL_WINDOW_MS（默认 10 分钟，order/service.js）内，待支付(0)/待接单(1)/未真正开始配送的配送中(2)订单可一键取消。

前端按钮计算（GET /api/order/detail 内联逻辑，order/routes.js）：返回 `free_cancel_left_ms`（剩余窗口毫秒）与三个布尔位——`direct_cancelable`（st=0，或 st=1 且窗口内，或 st=2 且未真正配送且窗口内）、`request_cancelable`（st=1 且已超窗口）、配送中且已真正配送/送达则两按钮均不展示（走售后）。订单列表/详情按此渲染「取消订单 / 提交取消申请」入口。

请求接口：POST /api/order/cancel（id）。

后端处理：`backend/domains/order/routes.js → /order/cancel`：
1. 状态校验：3/4/6 → 提示走「退款/投诉」；2 且 `s.orderTrulyDelivering`（订单 status=2 且任务 task_status ≥ 50 已上货出发，order/service.js）→ 「配送中不支持取消」；非 0/1/2 → 拒绝；非 0 且 `!s.withinFreeCancelWindow`（按下单时间计）→ 「请提交取消申请」；
2. `s.applyOrderCancelled(store, deps, order)`（order/service.js）：
   - `deps.orderCancel.cancelLocal`（services/orderCancel.js，**本地副作用唯一入口**，内部无 await）：`claimCancelled` CAS 抢占（`WHERE cancelled_at IS NULL AND status IN (0,1,2,3,6)` → status=5 + cancelled_at，并发/重推只有一次成功）→ `voidTasks` 作废本单非终态任务（task_status=110 + void_at）→ `goodsStats.restoreStock` 回补库存（幂等）→ `batch.removeOrderFromBatch` 摘批次（幂等）→ `stopMock` 停本地模拟推进；
   - 平台召回：排队中任务（task_status<10 且有 platform_task_id）走 `deps.platform.cancelQueueTask`；已上设备任务走 `deps.platform.closeTask(device_sn, platform_task_id, reason)`；召回结果写 delivery_tasks.recall_status/recall_error（失败置 2 待人工，不回滚本地取消）；
   - 车辆释放：批次有 device_sn 且无其他待上货订单时 `deps.settleRobot`（`settleRobotAtLoading` 事件驱动释放）。

状态流转：orders 0/1/2 → 5 已取消；delivery_tasks → 110（void_at）。

落库字段：orders.status/cancelled_at/updated_at；delivery_tasks.task_status/void_at/recall_status；goods.stock 回补；delivery_batches.total_orders/total_items 摘除计数。

### 8.2 超时取消申请

触发点：超过免费窗口的待接单(1)/待支付(0)订单，用户点「提交取消申请」填原因。

请求接口：POST /api/order/cancel-request（order_id、reason）。

后端处理：`backend/domains/order/routes.js → /order/cancel-request`：状态须 ∈ {0,1}；非 0 且仍在窗口内 → 「仍可直接取消」；已有待处理申请（`pendingCancelRequestByOrder`）→ 拒绝；通过 `q.insertCancelRequest` 落 cancel_requests（status=0 待处理）。订单详情/列表接口按 `direct_cancelable` / `request_cancelable` 计算前端按钮显隐（detail 路由内联逻辑）。

### 8.3 商家处理取消申请

请求接口：POST /api/merchant/cancel-request/handle（id、action=approve|reject、reply）。

后端处理：`backend/domains/order/routes.js`：申请须 status=0 未处理。
- approve：先 `s.applyOrderCancelled`（订单若在 0/1/2 直接取消成功，409 防并发），再 `q.approveCancelRequest` 申请置 3 已同意取消（订单同步 5）；
- reject：必填理由（reply），`q.rejectCancelRequest` 置 2 已拒绝，订单继续。

落库字段：cancel_requests.status/merchant_reply；orders.status（approve 时 →5）；audit_logs 落审计。

## 9. 售后（退款 / 投诉）

### 9.1 用户申请

触发点：订单详情「退款/投诉」（我的-售后记录可查）。

请求接口：POST /api/refund/apply（order_id、type=refund|complaint、reason）。

后端处理：`backend/domains/order/routes.js → /refund/apply`：订单状态须 ∈ {3,4,6}，或 status=2 且 `s.orderStuckDelivering`（任务停留非终态超 DELIVERY_TIMEOUT_MS，order/service.js）；**一单只允许一条待处理售后**（`pendingRefundByOrder`，P2-9）；`q.insertRefund` 落 refunds（type、reason、amount=退款全额/投诉 0、status=0 待处理）。

### 9.2 商家处理（同意改金额 / 拒绝理由 / 投诉回复）

请求接口：POST /api/merchant/refund/handle（id、action、amount、reply）。

后端处理：`backend/domains/order/routes.js → /merchant/refund/handle`（售后须 status=0）：
- 退款 approve：订单白名单 [3,4,6]（已退款 7 不得再次同意）；退款金额上限 = 订单实付 total_amount（可改，部分退款）；`s.realRefundOrLocal`（真实微信渠道且凭据就绪时 `deps.wxpay.refund` 真正退钱，出 out_refund_no；PAY_MOCK/未配置时本地标记 + 告警日志）；退款成功后才 `s.applyOrderCancelled({finalStatus:7})` 置订单 7（CAS claimRefunded：作废任务/回补库存/摘批次统一走 orderCancel），再 `q.markRefunded` 售后置 3 已退款并记 wx_refund_no；
- 退款 reject：必填理由，售后置 2 已拒绝；
- 投诉 reply：售后置 4 已处理（type=complaint）。

状态流转：refunds 0 → 3（已退款）/ 2（已拒绝）/ 4（已处理）；同意退款时 orders → 7 已退款。

落库字段：refunds.status/refund_amount/merchant_reply/handled_at/wx_refund_no；orders.status/cancelled_at；goods.stock 回补；delivery_tasks 作废。

列表/详情接口：用户端 GET /api/refund/list（我的售后记录，附 status_text）；商家端 GET /api/merchant/refunds（待处理优先）+ GET /api/merchant/refund/detail（售后详情）；工作台售后角标来自 /api/merchant/stats 的 aftersale 计数（`order/service.js → computeStats`：refunds.status=0 待处理数）。

### 9.3 异常配送（status=6）处理

触发点：工作台「异常」→ 独立配送异常页（分类 全部/待处理/已处理，orders.exception_handled 记录处理态）。

请求接口（均在 `backend/domains/order/routes.js`，merchantGuard）：
- 重新配送：POST /api/merchant/order/exception/retry——订单须 6；按 order_id 精确作废旧任务（`task_status=110 + void_at`，注释强调不能按 batch_id 写会误伤同批其他单）→ `deps.batch.removeOrderFromBatch` 摘除 → `deps.batch.addOrderToBatch` 并入新的组单中批次（订单 →2）→ `q.setExceptionHandled(order.id,'retry')`。商家随后在新批次「派车 → 上货 → 配送」；
- 取消并退款：POST /api/merchant/order/exception/refund——`s.realRefundOrLocal` 全额退款 → `s.applyOrderCancelled({finalStatus:7, reason:'异常退款，任务作废'})` → `setExceptionHandled 'refund'` → `q.insertAutoRefund` 写一条自动已退款售后记录（status=3）。

状态流转：6 配送异常 → 2 配送中（retry）/ 7 已退款（refund）。
