最后更新：2026-09-22（与 README 及双端 app.json 复核一致）

## 1. 产品定位与背景

### 1.1 一句话定位

面向四川师范大学校内师生的无人化外卖配送系统，由「学生用户端小程序 + 商家管理小程序 + Node.js 单进程后端」三端构成，核心能力是**一车多单**的配送批次机制：机器人一次装载最多 12 件商品，沿规划路线逐点位配送，学生凭本单取餐码开舱取走自己那份。

### 1.2 校园场景

- **场景**：封闭校园内单商家（零栋铺子）向师生供餐，配送覆盖各教学楼、宿舍楼点位（deliverPoint），商家店铺为上货点（loadingPoint）。
- **业务节奏**：学生随时下单 → 商家接单（手动/自动）并入配送批次 → 批次派车、机器人到上货点 → 商家整批上货 → 机器人按路线逐点位配送 → 学生凭取餐码取餐 → 仓内全部取完批次完成。
- **试点特征**：测试阶段用模拟登录、模拟支付（PAY_MOCK）、模拟扫码、模拟送达（DEVICE_MOCK）跑通完整闭环；正式上线替换为微信 code2session、微信支付 V3 JSAPI、wx.scanCode 真实扫码与开放物流平台真实配送。

### 1.3 三端构成与角色

| 端 | 载体 | 角色 | 职责 |
| --- | --- | --- | --- |
| 用户端 | 微信小程序（20 页） | 学生 | 浏览商品、加购、下单支付、订单管理（取消/取消申请/退款投诉）、配送追踪、取餐码取餐、收货地址管理、活动查看 |
| 商家端 | 微信小程序（22 页） | 商家（零栋铺子） | 商品与库存管理、接单、组单与派车、整批上货、配送监控、售后与取消申请处理、店铺营业/自动接单、活动发布 |
| 后端 | Node.js + Express + SQLite（单进程，端口 3000） | 管理员 | 同端口托管三服务：小程序接口 `/api`、管理员网页 `/admin`（账号密码登录）、可视化大屏 `/dashboard`（免登录只读） |
| 外部系统 | 开放物流平台（robox） | - | 机器人任务调度、状态上报、位置数据（eviz），后端统一对接 |

管理员职责：在 `/admin` 查看订单/批次/任务/机器人实时状态，执行召唤、停驶、恢复、开关舱、任务取消/关闭、批量操作等修复性操作（WebSocket 事件驱动，无轮询）；账号由 `backend/tools/admin_user.js` 管理，操作落审计日志。

## 4. 导航与 tab 结构

双端均使用**自定义 tabBar**（app.json `tabBar.custom=true`，由 `custom-tab-bar/` 目录实现）：白底通栏贴底并覆盖安全区，图标统一使用本地化子集字体（t-icon，约 48 字形 / 10KB，不走 CDN）。

**用户端 4 tab**：

| tab | 页面路径 |
| --- | --- |
| 首页 | pages/index/index |
| 商城 | pages/goods/list |
| 活动 | pages/activity/index |
| 我的 | pages/user/profile |

**商家端 2 tab**：

| tab | 页面路径 |
| --- | --- |
| 首页 | pages/index/index |
| 我的 | pages/user/profile |

导航规则：

- 登录页为非 tab 页：登录成功 switchTab 到首页；退出登录 reLaunch 到登录页；接口 401/403 统一清 token 回登录页。
- 各 tab 页 onShow 时同步 `selected` 下标，保证自定义 tabBar 高亮与页面一致。
- 用户端商城页底部购物车栏悬浮于 tabBar 上沿（`bottom: calc(116rpx + env(safe-area-inset-bottom))`），列表内容预留底部滚动余量。
- 商家端首页启动（或刚登录）后自动进入商铺工作台页一次，返回后不再重复弹出。

## 5. 核心术语表

| 术语 | 一句话解释 |
| --- | --- |
| 配送批次（delivery_batches） | 一次出车装载并配送的订单集合，容量按商品件数计（默认上限 12 件，BATCH_MAX_ITEMS），生命周期：组单中 → 待上货 → 配送中 → 已完成（或异常）。 |
| 组单 | 商家接单（含自动接单）后，订单按商品总件数 best-fit 分批并入「组单中」批次的过程（件数 ≤12 整单同批，超限独占新批）；组单中批次持续收单。 |
| 派车 / 定型 | 商家在组单中批次点「派车配送（上货N件）」后，批次锁定为「待上货」并为每单创建平台配送任务（同一机器人/货仓），定型后批次不再收单。 |
| 召唤待命 | 后端周期（15 秒）扫描组单中/待上货批次，向机器人下发 lightTask 召唤其先到上货点待命，不创建配送任务、不锁批次。 |
| 取餐码 | 每单独立的取餐验证码，**同一车各单互不相同**（防拿错）；机器人到达后须匹配本单取餐码才能确认取餐开舱，支持「车 + 取餐码」定位本人订单。 |
| 点位（landmark） | 校园内的配送站点，分上货点（loadingPoint）与配送点（deliverPoint）；用户首页楼栋选择与下单只面对配送点。 |
| 上货点 | 商家（零栋铺子）装货点位，机器人到店后商家整批开舱 → 放货 → 关舱 → 派发。 |
| 配送中 | 订单状态 2 / 批次状态 2 的展示口径：已确认上货，机器人沿路线逐点位配送，用户可追踪并等待取餐。 |
| 待取货 | 商家任务页对订单状态 3「已送达」的展示口径：机器人已到达点位、等待用户取餐。 |
| 同车进度 | 批次内「本车共 N 单 · 已取 X 单」，按各单 picked_up_at 动态统计；仓内全部取完批次才完成。 |
| daily_seq / 短号 | 批次与订单每天从 1 重置的当日序号（历史数据按创建日回填），商家端卡面用「批次 N / 订单 N」短号辨认，完整批次/订单编号仅在详情页弱化显示。 |
| 已售 / 售罄 | 下单即扣库存（防超卖），收货完成（已送达/已完成）才结算已售（幂等），取消/退款且未售出时回补库存；售罄 = 库存 0，用户端置灰不可加购、后端兜底拒单。 |
| 免费取消窗口 | FREE_CANCEL_WINDOW_MS（默认 10 分钟）：窗口内且未真正开始配送（任务状态 <50）可直接取消，超时未配送须提交「取消申请」由商家判断。 |
| 自动接单 | 营业中且开启自动接单时，用户支付即自动接单并入配送批次；自动接单模式下批次成立超 90 秒（BATCH_WAIT_MS）或满件数自动派车。 |
| 配送异常 | 订单状态 6：平台任务失败（上货/送货失败）或机器人超时未接单；商家可「重新配送」并入新批次再派车，或「取消并退款」。 |
