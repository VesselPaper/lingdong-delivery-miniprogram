# 05 · 数据备份与运维

最后更新：2026-09-26

## 1. 要备份什么

| 数据 | 位置 | 重要度 |
|---|---|---|
| SQLite 数据库 | backend/data/lingdong.db + WAL | 核心 |
| 商家上传图片 | backend/uploads/ | 可重建但麻烦 |
| 服务器 .env | 手动维护，不进 git | 凭据 |
| 代码 | git 仓库 | 已覆盖 |

## 2. 备份方案（cron 每日）

```bash
# /opt/lingdong/deploy/backup.sh
#!/bin/bash
set -euo pipefail
STAMP=$(date +%Y%m%d_%H%M%S)
DEST=/opt/lingdong/backup
mkdir -p "$DEST"
cd /opt/lingdong/backend

# SQLite 在线安全备份
sqlite3 data/lingdong.db ".backup '$DEST/lingdong_$STAMP.db'"

# uploads 图片
tar -czf "$DEST/uploads_$STAMP.tar.gz" uploads 2>/dev/null || true

# 保留最近 14 份，删旧
ls -1t "$DEST"/lingdong_*.db 2>/dev/null | tail -n +15 | xargs -r rm -f
ls -1t "$DEST"/uploads_*.tar.gz 2>/dev/null | tail -n +15 | xargs -r rm -f
```

```bash
chmod +x /opt/lingdong/deploy/backup.sh
crontab -e
# 每天 03:30 备份
30 3 * * * /opt/lingdong/deploy/backup.sh >> /var/log/lingdong-backup.log 2>&1
```

异地副本：把 $DEST 最近一份上传到 OSS/COS 或云盘，用 rclone 或云厂商 CLI 加一条 cron。

## 3. 代码更新 / 发布流程（后端）

```bash
cd /opt/lingdong
git pull
cd backend
npm install        # 依赖变化时才需要
pm2 reload lingdong-backend
curl http://127.0.0.1:3000/api/goods/list   # 冒烟验证
```

更新前先跑一次 backup.sh。数据库结构变更由 db.js 幂等迁移自动处理，大改动前一定先备份。回滚：git revert 或 checkout → pm2 reload → 必要时恢复备份。

## 4. 日志与监控

| 工具 | 用途 |
|---|---|
| pm2 logs / journalctl -u lingdong -f | 实时/历史日志 |
| pm2 status | 进程状态 |
| df -h | 磁盘（uploads 增长） |
| 可用性探测 | cron：curl -s https://api.lingdong.cn/api/goods/list \| grep -q '"code":0' \|\| 报警 |

后端自带兜底：unhandledRejection/uncaughtException 只记录不退出，配合 Restart=always 双保险。

- [ ] https://api.lingdong.cn/api/goods/list 可用
