# 05 · 数据备份与运维

最后更新：2026-09-24
依据代码：`backend/db.js`（SQLite 单文件 `backend/data/lingdong.db`）、`backend/server.js`（uploads 目录）、`README.md` §一/§三。

## 1. 要备份什么

| 数据 | 位置 | 重要度 |
|---|---|---|
| SQLite 数据库（订单/用户/商品/批次/审计等全部业务数据） | `backend/data/lingdong.db`（+ WAL 文件） | ★★★ 核心 |
| 商家上传图片 | `backend/uploads/` | ★★ 可重建但麻烦 |
| 服务器 .env | 手动维护，**不要备份进 git** | ★★★ 凭据 |
| 代码 | git 仓库（云端 GitHub） | 已覆盖 |

## 2. 备份方案（cron 每日）

```bash
# /opt/lingdong/deploy/backup.sh
#!/bin/bash
set -euo pipefail
STAMP=$(date +%Y%m%d_%H%M%S)
DEST=/opt/lingdong/backup
mkdir -p "$DEST"
cd /opt/lingdong/backend

# 1) SQLite 在线安全备份（WAL 模式下直接拷文件可能漏最近提交，用 sqlite3 .backup 最稳）
sqlite3 data/lingdong.db ".backup '$DEST/lingdong_$STAMP.db'"
# 或 Node 内置方式：
# node -e "const{DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('data/lingdong.db');db.exec(\"VACUUM INTO '${DEST}/lingdong_${STAMP}.db'\");db.close()"

# 2) uploads 图片
tar -czf "$DEST/uploads_$STAMP.tar.gz" uploads 2>/dev/null || true

# 3) 保留最近 14 份，删旧
ls -1t "$DEST"/lingdong_*.db 2>/dev/null | tail -n +15 | xargs -r rm -f
ls -1t "$DEST"/uploads_*.tar.gz 2>/dev/null | tail -n +15 | xargs -r rm -f
```

```bash
chmod +x /opt/lingdong/deploy/backup.sh
crontab -e
# 每天 03:30 备份
30 3 * * * /opt/lingdong/deploy/backup.sh >> /var/log/lingdong-backup.log 2>&1
```

- **异地副本**（防服务器宕机/误删）：把 `$DEST` 最近一份上传到云对象存储（阿里 OSS / 腾讯 COS，或 GitHub 私有仓库私有文件、云盘）。可用 `rclone` 或云厂商 CLI 加一条 cron。
- 手动即时备份：`node -e "...VACUUM INTO ..."` 或直接复制文件（先停写更稳，但对本项目低峰期直接拷也可接受）。

## 3. 代码更新 / 发布流程（后端）

```bash
# 服务器上（以 pm2 为例）
cd /opt/lingdong
git pull                      # 拉最新代码（先看 git status 确认工作树干净）
cd backend
npm install                   # 依赖变化时才需要（本次只加了业务代码可跳过）
pm2 reload lingdong-backend   # 秒级重启
curl http://127.0.0.1:3000/api/goods/list   # 冒烟验证
```

- **更新前先备份**（跑一次 backup.sh），避免 pull 后数据库结构/代码不兼容时需要回滚。
- 数据库结构变更（db.js 迁移）：本项目 db.js 用 `CREATE TABLE IF NOT EXISTS` + 幂等迁移，重启自动处理；但**大改动前一定先备份**。
- 回滚：`git revert <坏提交>` 或 `git checkout <上一版本>` → `pm2 reload` → 恢复备份（若数据受损）。

## 4. 日志与监控

| 工具 | 用途 |
|---|---|
| `pm2 logs lingdong-backend` / `journalctl -u lingdong -f` | 实时/历史日志（启动摘要、派车、回调、异常） |
| `pm2 status` | 进程状态（重启次数、内存） |
| 磁盘 | `df -h` 定期看（uploads 图片增长） |
| 可用性 | 简单 cron 探测：`curl -s https://api.lingdong.cn/api/goods/list | grep -q '"code":0' || 报警`（可接企业微信/邮件通知） |

后端自带兜底：`server.js` 尾部 `unhandledRejection/uncaughtException` 只记录不退出（保证校园服务可用），配合 `Restart=always` 双保险。

- [ ] `https://api.lingdong.cn/api/goods/list` 可用
