# 01 · 部署架构与服务器选型

最后更新：2026-09-24
依据代码：`backend/server.js`（单进程三服务）、`backend/package.json`（依赖仅 cors + express）、`backend/db.js`（node:sqlite）、`README.md` §一（Node 22+）。

## 1. 部署拓扑（上线后）

```
                     学生微信 · 商家微信（扫小程序码/普通打开）
                                  │ HTTPS（443）
                                  ▼
                         ┌───────────────────┐
                         │  云服务器（1 台）    │
                         │  Nginx（443 终止TLS）│
                         │     │ 反向代理        │
                         │     ▼                │
                         │  node server.js      │  ← pm2/systemd 守护
                         │  监听 127.0.0.1:3000  │
                         │  ┌─────────────────┐ │
                         │  │ /api/* 小程序 API │ │
                         │  │ /admin/* 管理员页 │ │
                         │  │ /dashboard/* 大屏 │ │
                         │  │ /ws  WebSocket    │ │
                         │  │ /uploads 图片     │ │
                         │  │ SQLite 单文件     │ │
                         │  └─────────────────┘ │
                         └───────────────────┘
                                  │ HTTPS
                                  ▼
                        robox 开放物流平台（已对接）
                        微信支付（生产必配）
                        微信 code2session（真实登录）
```

- **单进程三服务同端口**（`backend/server.js`）：API + 管理员网页 + 大屏全部由 3000 端口一个进程托管，Nginx 只需把 `/` 转发给 3000 即可，三端一起上线，无需拆服务。
- 数据库 **SQLite 单文件**（`backend/data/lingdong.db`）：零外部数据库服务、零额外费用、备份就是拷文件。
- 对外只暴露 **443**；3000 绑在 127.0.0.1，不直接暴露（`BIND_HOST=127.0.0.1`）。

## 2. 服务器选型（川师学生规模）

| 项 | 建议 | 说明 |
|---|---|---|
| CPU/内存 | **2 核 4G 起步**（预算允许 4 核 8G） | Node 单进程 + SQLite，数百~数千学生并发绰绰有余；WebSocket 与定时器都在同一进程，2 核 4G 已覆盖 |
| 带宽 | **5Mbps 起步**，按需升 | 图片上传（商家）/ 大屏加载 / 多用户同时访问；5M 足够起步，观察监控再升 |
| 系统 | Ubuntu 22.04 LTS | Node 22+ 官方支持良好，包管理器 apt 齐全 |
| 磁盘 | 40G 起步（SSD） | 代码 + SQLite + uploads 图片 + 备份副本 |
| 厂商 | 腾讯云/阿里云轻量应用服务器 | 约 ¥50-100/月档；学生项目可走学生优惠（如腾讯云学生机/轻量学生套餐，通常更便宜） |
| 地域 | 成都（川师所在地，就近） | 降低延迟；与备案无冲突（备案看服务器厂商与主体，不看地域） |

> 结论：**一台轻量云服务器即可**，无需负载均衡、无需数据库服务、无需对象存储起步（备份用云盘/OSS 均可，见 05 篇）。

## 3. Node 版本要求（硬约束）

- 本项目后端使用 **Node 内置 `node:sqlite`**（`backend/db.js` 第 2 行 `require('node:sqlite')`），**必须 Node 22.5+**（README §一 注明"本地已验证 v22 正常"）。
- 建议装 **Node 22 LTS 最新小版本**（如 22.13+，`node:sqlite` 已稳定可用）。
- 安装方式（Ubuntu）：
  ```bash
  # 方式一：nvm（推荐，可随时切版本）
  curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
  source ~/.bashrc
  nvm install 22
  node -v   # 应 ≥ v22.5.0

  # 方式二：apt 官方源（Debian/Ubuntu 有 nodejs 22 包）
  curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
  sudo apt-get install -y nodejs
  node -v
  ```

## 4. 依赖安装与首次启动

```bash
cd backend
npm install          # 依赖仅 cors + express，秒装
# 首次启动自动建库 + 种子数据（db.js → init/seed）
node server.js
# 看到 listening on http://127.0.0.1:3000 即成功
# 验证：
curl http://127.0.0.1:3000/api/goods/list
# 应返回 {"code":0,"msg":"success",...}
```

> 注意：`backend/.env` 不入库，服务器上需手动创建（内容见 04 篇）；管理员账号需在服务器上执行
> `node backend/tools/admin_user.js add --username <账号> --password <密码>`（非 demo 档没有管理员账号会拒绝启动，`server.js` 启动日志段）。

## 5. 进程守护（pm2，推荐）

```bash
sudo npm install -g pm2
cd backend
pm2 start server.js --name lingdong-backend
pm2 save && pm2 startup   # 开机自启（按提示执行输出的命令）
pm2 logs lingdong-backend  # 看线上日志
pm2 reload lingdong-backend # 更新代码后秒级重启
pm2 status
```

或 systemd（无需 npm 全局包）：

```ini
# /etc/systemd/system/lingdong.service
[Unit]
Description=Lingdong Backend
After=network.target
[Service]
WorkingDirectory=/opt/lingdong/backend
ExecStart=/usr/bin/node server.js
Restart=always
RestartSec=3
Environment=NODE_ENV=production
[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now lingdong
sudo journalctl -u lingdong -f   # 看日志
```
