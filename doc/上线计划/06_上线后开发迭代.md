# 06 · 上线后开发迭代（改 bug / 调试）

最后更新：2026-09-24
说明：上线后团队最关心的问题——"还方便改点、改 bug、调试吗"。结论：**方便，且与现在几乎一致**，仅"正式发布"多一道微信审核。本片讲透三版本机制、后端迭代、紧急回退与常见坑。

## 1. 小程序三版本机制（日常迭代的核心）

| 版本 | 谁在用 | 是否要审核 | 用途 |
|---|---|---|---|
| **开发版** | 只有开发者工具里 | 否 | 日常改代码/调试；继续连本机/局域网后端，与现在完全一致 |
| **体验版** | 团队成员（后台加体验成员） | **否，上传即秒级可用** | 改 bug 后的快速复测链路（无需等审核） |
| **正式版** | 全体学生 | 是（几小时~1 天，首审慢） | 确认无误后才发布 |

- 开发者工具勾选「不校验合法域名」后，开发版可连 `http://本机IP:3000` 的本地后端调试（`README.md` §二），体验与现在零差别。
- 双端 `utils/config.js` 保留 ENV 机制：`CURRENT='dev'`（本机 IP）/ `'prod'`（正式域名）一键切换——本地改 bug 用 dev，验证通过切 prod 重新编译上传。

## 2. 标准迭代节奏（推荐）

```
本地开发（照旧）→ 回归测试全绿（test_batch_flow.js + test_summon_flow.js）
   → 上传体验版（团队复测，免审）→ 提交正式版审核 → 发布（可灰度）→ 监控 pm2 日志
```

紧急 bug：
```
体验版快速验证 → 正式版加急审核 / 必要时先在后台回退上一正式版
```

## 3. 后端迭代（与现在几乎相同）

```
本地改代码 → node --check / 跑回归（临时库隔离） → git push
   → 服务器 git pull → pm2 reload（秒级重启） → curl 冒烟
```

- 本地调试、测试脚本、临时库隔离（`test_batch_flow.js` 用独立端口 3100/3101 + 临时库）全部照旧；
- 线上日志：`pm2 logs` 一行命令；
- 线上专属 bug 本地复现不了时：看日志定位 + 服务器**只读**查生产库（如 `sqlite3 data/lingdong.db 'SELECT ...'`），绝不直接改生产数据；
- 生产库修改必须走「备份 → 脚本/接口 → 验证」流程（见 05 篇）。

## 4. 上线后会"变麻烦"的 4 点（及应对）

| 变化 | 应对 |
|---|---|
| 改版要过审，不能改完立刻全体生效 | 体验版免审联调 → 正式版审核发布，节奏安排好；非紧急需求攒批发布 |
| 生产库不能随便动 | 本地临时库复现 → 确认修复 → 再上服务器；每日备份 |
| 线上专属 bug 本地复现不了 | pm2 logs + 服务器只读查库；必要时加临时日志再部署一次 |
| 双端正式域名后本地要用回本机 IP | ENV 机制 `CURRENT='dev'/'prod'` 切换（现有设计已支持） |

## 5. 回退预案（出大事时）

| 层 | 回退方式 |
|---|---|
| 小程序正式版 | 微信后台「版本管理 → 线上版本」一键回退上一版本（秒级） |
| 后端代码 | `git revert <坏提交>` / `git checkout <上一版本>` → `pm2 reload` |
| 数据 | 用每日备份恢复 `.db`（05 篇 backup.sh 保留 14 份） |

## 6. 常见坑（上线后必读）

1. **域名别写错**：双端 config.js、PUBLIC_ORIGIN、WXPAY_NOTIFY_URL、PLATFORM_CALLBACK_BASE 四处的域名必须完全一致（http/https、有无尾斜杠）。
2. **小程序码 page 路径不能改**：`getwxacodeunlimit` 生成的小程序码绑定了 `pages/delivery/scanPickup`；页面改名/删路径后旧码全部失效，需重新生成并重贴车身（生成逻辑见扫码直达取餐功能文档）。
3. **access_token 有 IP 白名单**：若小程序后台开了「IP 白名单」，需把服务器公网 IP 加入，否则后端调微信接口（code2session/小程序码）会 401。
4. **WebSocket 反向代理**：Nginx 必须转发 `Upgrade`/`Connection` 头（02 篇配置已含），否则商家端/管理员实时推送断连。
5. **上传图片大小**：Nginx `client_max_body_size` 已设 20m，与后端 8mb json 对齐；再大则商家端上传失败。
6. **审核被拒常见原因**：隐私政策未填、类目与内容不符、测试账号进不去、页面有"演示/测试"字样。上线前把演示登录、测试按钮隐藏或标注清楚。
7. **时间/时区**：后端 `datetime('now','localtime')` 依赖服务器时区，Ubuntu 务必 `timedatectl set-timezone Asia/Shanghai`，否则订单时间差 8 小时。

- [ ] 本地 dev / 线上 prod 双环境切换验证过一次
- [ ] 回退预案（小程序后台回退 + git revert + 备份恢复）演练过一次
- [ ] 服务器时区 Asia/Shanghai，订单时间显示正确
