# 06 · 上线后开发迭代

最后更新：2026-09-26

结论：上线后改 bug 与现在几乎一致，仅"正式发布"多一道微信审核。

## 1. 小程序三版本机制

| 版本 | 谁在用 | 是否要审核 | 用途 |
|---|---|---|---|
| 开发版 | 只有开发者工具里 | 否 | 日常调试，继续连本机/局域网后端 |
| 体验版 | 团队成员 | 否，上传即秒级可用 | 改 bug 后快速复测 |
| 正式版 | 全体学生 | 是 | 确认无误后才发布 |

双端 config.js 保留 ENV 机制，CURRENT='dev'/'prod' 一键切换。

## 2. 标准迭代节奏

```
本地开发 → 回归测试全绿（test_batch_flow.js + test_summon_flow.js）
   → 上传体验版（团队复测，免审）→ 提交正式版审核 → 发布（可灰度）→ 监控 pm2 日志
```

紧急 bug：体验版快速验证 → 正式版加急审核 / 必要时先在后台回退上一正式版。

## 3. 后端迭代

```
本地改代码 → node --check / 回归测试 → git push
   → 服务器 git pull → pm2 reload → curl 冒烟
```

线上专属 bug 本地复现不了时：pm2 logs 定位 + 服务器只读查库（sqlite3 查询），绝不直接改生产数据。生产库修改必须走「备份 → 脚本/接口 → 验证」流程。

## 4. 上线后变化与应对

| 变化 | 应对 |
|---|---|
| 改版要过审，不能改完立刻生效 | 体验版免审联调 → 正式版审核发布；非紧急需求攒批发布 |
| 生产库不能随便动 | 本地临时库复现 → 确认修复 → 再上服务器；每日备份 |
| 线上 bug 本地复现不了 | pm2 logs + 只读查库；必要时加临时日志再部署 |
| 本地要用回本机 IP | ENV 机制切换 |

## 5. 回退预案

| 层 | 方式 |
|---|---|
| 小程序正式版 | 微信后台一键回退上一版本（秒级） |
| 后端代码 | git revert / checkout → pm2 reload |
| 数据 | 用每日备份恢复 .db |

## 6. 常见坑

1. 域名别写错：双端 config.js、PUBLIC_ORIGIN、WXPAY_NOTIFY_URL、PLATFORM_CALLBACK_BASE 四处必须完全一致。
2. 小程序码 page 路径不能改：getwxacodeunlimit 绑定 pages/delivery/scanPickup，改路径后旧码全部失效。
3. access_token 有 IP 白名单：若后台开了白名单，需加服务器公网 IP，否则微信接口 401。
4. WebSocket 反代：Nginx 必须转发 Upgrade/Connection 头，否则实时推送断连。
5. 上传图片大小：Nginx client_max_body_size 20m 与后端 8mb json 对齐。
6. 审核被拒常见原因：隐私政策未填、类目与内容不符、测试账号进不去、页面有"演示/测试"字样。
7. 时区：后端 datetime('now','localtime') 依赖服务器时区，务必 timedatectl set-timezone Asia/Shanghai。
