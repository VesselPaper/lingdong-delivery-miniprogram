# 04 · 生产环境配置（服务器 .env + 双端 config.js）

最后更新：2026-09-24
依据代码：`backend/server.js`（.env 加载）、`backend/services/runtime.js`（运行模式守卫与环境变量全表）、`backend/.env.example`、`用户端/utils/config.js`、`商家端/utils/config.js`、`doc/02_系统架构与运行.md` §2。

## 1. 运行模式选择（先想清楚再配）

| 档位 | 登录 | 支付 | 配送 | 适用 |
|---|---|---|---|---|
| `demo` | 演示 | 模拟 | 本地Mock | 本地演示，**禁止上生产** |
| `pilot` | 可真实可演示 | 可模拟 | **真实平台** | 试点：真实配送 + 可先不开真实支付 |
| `production` | **必须真实** | **必须真实** | 真实平台 | 正式上线（支付/登录/平台全真） |

- 启动守卫（`runtime.js → assertBootable`）会强制约束：`production` 禁止 `PLATFORM_MOCK/PAY_MOCK=true`、要求双端真实微信登录凭据 + 微信支付四要素齐备。
- **如果微信支付商户还没办好**：可用 `RUN_MODE=pilot` + `PAY_MOCK=true` 过渡上线（真实配送 + 演示支付），但要在交付文档明确「当前为演示支付，收款未真实发生」；微信支付办好后切 `production`。
- 无论哪档：`PLATFORM_MOCK=false`（真实配送平台），`SUMMON_DELIVERY` 保持当前值（true=召唤多单配送，当前生产配置）。

## 2. 服务器 `backend/.env` 全量模板

```ini
# ---------- 运行模式 ----------
RUN_MODE=production              # 或 pilot（过渡，见上）
PLATFORM_MOCK=false
PAY_MOCK=false                   # pilot 过渡期可 true
SUMMON_DELIVERY=true             # 与当前生产配置一致（召唤多单配送）

# ---------- 登录（真实微信 code2session）----------
WX_APPID=wxab08bb09bee883ef              # 用户端零栋GO（后端已配置，照抄）
WX_SECRET=<用户端 AppSecret，后台获取，线下分发>
MERCHANT_WX_APPID=wx69fddbd975779978     # 商家端零栋商家
MERCHANT_WX_SECRET=<商家端 AppSecret>

# ---------- 微信支付 V3（production 必配；pilot 过渡可留空+PAY_MOCK=true）----------
WXPAY_MCHID=<商户号>
WXPAY_SERIAL_NO=<API证书序列号>
WXPAY_PRIVATE_KEY=<API私钥 PEM 内容（或文件路径）>
WXPAY_APIV3_KEY=<APIv3 密钥 32位>
WXPAY_NOTIFY_URL=https://api.lingdong.cn/api/pay/notify

# ---------- 开放物流平台（robox）----------
PLATFORM_BASE=https://robox.eventec.cn/service-open-logis   # 生产主机（非 test- 开头）
PLATFORM_APPID=<平台appid>
PLATFORM_SECRET=<平台secret>
PLATFORM_PRINCIPALID=<平台principalId>
# 回调公网地址（有域名后必配；无则 basicList 轮询兜底）
PLATFORM_CALLBACK_BASE=https://api.lingdong.cn

# ---------- 网络/代理 ----------
BIND_HOST=127.0.0.1              # 只监听本机（Nginx 转发），生产安全
TRUST_PROXY=1                    # 采信 X-Forwarded-For（登录限流取真实 IP）
PUBLIC_ORIGIN=https://api.lingdong.cn   # 图片等资源绝对地址基址

# ---------- 管理员 ----------
ADMIN_TOKEN=<强随机串，可删>     # 旧令牌已不参与鉴权（runtime.js check 提示可移除）
# 管理员账号用命令创建（非 demo 档必须存在，否则拒绝启动）：
#   node backend/tools/admin_user.js add --username <账号> --password <密码>

# ---------- 商家邀请码 ----------
# 已停用 env 共享码（MERCHANT_INVITE_CODE 不再生效，配置会启动告警）。
# 商家入驻统一走管理员网页「商家管理」页（/admin → 商家管理）创建表码：
# 一码一店、首绑微信 openid、可吊销/解绑，明文只显示一次（库中只存 sha256）。
# 等价命令行：node backend/tools/merchant_invite.js add --name <店名> [--code 自定码]

# ---------- 大屏 ----------
TIANDITU_TK=<天地图浏览器端 key>  # 大屏在线底图（不配只影响地图）

# ---------- 可调业务参数（保持与本地一致，按需微调）----------
# BATCH_WAIT_MS / BATCH_SCAN_MS / PLATFORM_POLL_MS / DELIVERY_TIMEOUT_MS /
# FREE_CANCEL_WINDOW_MS / SUMMON_* 等，全部见 doc/02 §2.2 C 组，默认值即可。
```

> ⚠️ 凭据管理（铁律）：`.env` **不入 git、不进任何文档**；仅项目负责人掌握，服务器上手动创建，成员如需改动走线下分发。交接文档只写"哪些 key 已配"，不写值。

## 3. 双端 `utils/config.js` 切换（上线必改）

### 用户端（`用户端/utils/config.js`）
```js
const ENV = {
  dev:  { baseUrl: 'http://<本机IP>:3000/api' },   // 本地调试用（不提交）
  prod: { baseUrl: 'https://api.lingdong.cn/api' } // 正式域名
}
const CURRENT = 'prod'   // 上线切 prod；本地开发切回 dev
```

### 商家端（`商家端/utils/config.js`，结构类似）
```js
// LAN_BASE 为本地局域网 IP（不提交）；上线切到 https 正式域名
const CURRENT = 'prod'
```

- **提交策略**：正式域名是全队统一值（区别于本机 IP），上线后随代码提交；提交前按铁律第 6 条先展示清单、经负责人确认。本机 IP 值一律不提交（`git add` 指定文件，勿 `git add .`）。
