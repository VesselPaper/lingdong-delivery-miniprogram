# 管理员网页 · 商家管理页

商家管理页（`#page-merchants`）是侧栏第 4 个导航项「商家管理」（`navTo('merchants')`），
用于**商家账号**管理：管理员在网页创建商家登录账号（用户名+密码+角色），商家端凭账号密码登录。
2026-09-24 起邀请码机制彻底退役（`merchant_invites` 表保留仅查历史，不再参与鉴权），本页是商家账号的唯一管理入口。

## 页面布局（tabs：创建 / 已创建）

| 区域 | 元素 | 内容 |
|---|---|---|
| 页头 | `#merchantsTabs` | 子页面 tabs（创建 / 已创建），与其他页一致 |
| 创建面板 | `#merchantUsername` | 用户名（2~32 位字母/数字/下划线，唯一） |
| | `#merchantPassword` | 初始密码（至少 6 位，scrypt 落库，不存明文） |
| | `#merchantName` | 店名（选填，展示用） |
| | `name=merchantRole` | 角色单选：店主（owner）/ 店员（staff），默认店员 |
| | `#merchantCreate` | 「创建账号」按钮 |
| | `#merchantCreateMsg` | 创建结果提示 |
| 列表面板 | `#merchantCount` | 账号总数 |
| | `#merchantReload` | 刷新按钮 → `loadMerchants()` |
| | `#merchantList` | 账号行：用户名、角色标签、启用状态、店名、创建时间 + 操作按钮（改角色/重置密码/停用/启用） |

## 前端逻辑（`管理员网页/js/parts/admin/09-merchants.js`）

- `loadMerchants()` → `GET /api/admin/merchants` → `renderMerchants()`；进入本页（`navTo('merchants')`）、切到「已创建」tab 或点刷新时调用。
- `merchantCreate()` → `POST /api/admin/merchants/create { username, password, merchant_role, nickname? }`：
  本地先校验用户名非空、密码 ≥6 位；成功后清空表单并重载列表。
- `merchantRole(id)` → `PUT /api/admin/merchants/role { id, merchant_role }`（店主↔店员，走 `openConfirmModal` 二次确认）。
- `merchantPassword(id)` → `POST /api/admin/merchants/password { id, password }`：弹窗输入新密码（≥6 位），重置后**吊销该账号全部已登录 token**（强制重新登录）。
- `merchantDisable(id)` / `merchantEnable(id)` → `POST /api/admin/merchants/disable|enable { id }`：停用立即失效已登录 token，启用后可重新登录。
- 后端全部接口经 `adminGuard` 鉴权 + `audit` 审计（动作 `admin/merchant-create|role|password|disable|enable`）。
- 列表接口**绝不返回密码与 token**（`merchantList` 查询只取 id/username/nickname/merchant_role/status/created_at）。

## 后端接口（`backend/domains/admin/routes.js`）

| 接口 | 说明 |
|---|---|
| `GET /api/admin/merchants` | 列表：id / username / name（昵称）/ merchant_role / active / created_at |
| `POST /api/admin/merchants/create` | 创建账号：用户名 `/^[A-Za-z0-9_]{2,32}$/` 且唯一；密码 ≥6 位（scrypt 加盐哈希）；角色默认 staff |
| `PUT /api/admin/merchants/role` | 改角色（owner/staff） |
| `POST /api/admin/merchants/password` | 重置密码：新密码 scrypt 落库，同时 `token=NULL` 吊销全部会话 |
| `POST /api/admin/merchants/disable` | 停用：status=0，`token=NULL`，登录与已登录会话均失效 |
| `POST /api/admin/merchants/enable` | 启用：status=1，可重新登录 |

## 账号与权限模型（单店多操作员）

- 账号存 `users` 表（与微信登录的学生用户同一张表）：`username UNIQUE` + `password_hash`（复用 `services/adminAuth.js` 的 scrypt 方案）+ `merchant_role` + `token` + `status`。
- `merchantGuard`：`role='merchant'` 且 `username` 非空 且 `status=1` —— 旧微信 openid 商家路径封死（无法再登商家端）。
- `ownerGuard`（店主专属）：店铺设置、商品新建/编辑/改价、活动管理、点位同步；店员可做上货（stock/status）、订单处理、设备日常、配送监控只读。
- 商家端登录（`client='merchant'`）只认 `{username, password}`；`client='user'` 微信登录不受影响，学生也不能再凭码升级商家。
