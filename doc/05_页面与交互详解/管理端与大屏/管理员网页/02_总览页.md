# 管理员网页 · 总览页

总览页（`#page-overview`）包含两个标签：**机器人（机器人卡 + 校园实时地图 + 异常与死锁告警）/ 操作日志
（管理员操作日志 + 状态字典 + 本次会话回显）**，是调度台的默认落地页，重点监控机器人状态、异常与死锁。

标签由 `02-nav.js → wireTabs('overviewTabs')` 绑定，面板 id 为 `overviewPanelRobot / overviewPanelLog`
（`showPanel('overviewPanel', tab, ['robot','log'])`）；切到「操作日志」时调 `08-audit.js → loadAudit()`，
切回「机器人」时调 `window.invalidateAdminMap()` 让地图重新量尺寸。

## 标签一：机器人（`#overviewPanelRobot`）

`.grid` 一行两块，下面再加一张横跨整行的告警卡：

| 区块 | 类 / 元素 | 内容 |
|---|---|---|
| 机器人卡 | `.card.col-6.stretch` | 设备编号、在线、电量、机器状态与停留、舱位占用、地图、楼层楼栋、状态更新时间；底部三个操作按钮 |
| 校园实时地图 | `.card.col-6` | `.map-stage > #adminMap` + 加载遮罩 `#mapMask`，卡头有图例与「回到校园」`#mapResetBtn`，卡脚 `#mapFoot` |
| 异常与死锁告警 | `.card` + `#alertCount / #alertsBox` | 后端死锁/异常检测结果（`state.alerts`），warn/bad 分级着色；无告警时显示「未检测到异常或死锁」 |

> 告警原先挂在日志标签，2026-09 重构后移到「机器人」标签：告警属运维信息，应与机器人状态同屏。

### 机器人卡片字段

`04-overview-ws.js → renderRobotCard`，WS `live` 事件每 ~2.5s 原地刷新（不整页重绘）：

| 字段元素 | 内容 |
|---|---|
| `#rSn / #robotTag` | 设备编号；在线 / 离线 / 无设备（无设备时 `#rSn` 显示 `state.robot_error`） |
| `#rBattery` | 电量百分比 |
| `#rMachine / #rMachineAge` | 机器状态（`machine_status` + `MACHINE_TEXT` 中文）与状态停留时长（`ageLabel`） |
| `#rStocks / #rMap / #rFloor / #rStatusTime` | 舱位占用（`busy_stocks`）、地图 id（`curr_map_id`）、楼层与楼栋、状态更新时间 |

### 机器人卡片操作（交互清单）

卡片上直出两个高频按钮，其余收进「更多操作」菜单（`#robotMoreBtn` → `03-menu.js → showRobotMenu`，
复用右键菜单组件 `#ctxMenu`，标题为「机器人 <设备编号>」）：

| 操作 | 触发 | 函数（文件） | 接口（均 `/api/admin` 前缀） |
|---|---|---|---|
| 召唤机器人 | 机器人卡「召唤」 | `09-ops.js → actSummon` | `GET /robot/summon-targets` 取上货/充电/取货点 → `openPickModal` 弹窗选择 → `POST /robot/summon { device_sn, landmark_id }`（会中断正在执行的配送任务） |
| 开关舱门 | 机器人卡「开关舱」 | `09-ops.js → actDrawerPick` | 弹窗选开/关舱 → `POST /drawer { device_sn, cmd }`（drawerCtrl 独立控制，不影响任务状态） |
| 停止（驻停 30 秒） | 更多操作菜单 | `09-ops.js → actStop` | `POST /robot/stop { device_sn, stop_time: 30 }`，原地驻停 30 秒后自动恢复 |
| 继续工作（恢复任务） | 更多操作菜单 | `09-ops.js → actRecover` | `POST /robot/recover { device_sn }`，恢复该设备当前任务执行 |
| 停止并取消任务（危险） | 更多操作菜单 | `09-ops.js → actStopCancel` | `POST /robot/cancel-tasks { device_sn }`：关闭该设备全部活跃平台任务 + 关联本地订单统一落账 + 批次置 4，不可撤销 |

> 后端另有 `POST /robot/stop-cancel`（先关活跃任务再驻停，对应 `admin/robot-stop-cancel` 审计动作），
> 当前管理页不再使用；菜单里的「停止并取消任务」走的是 `/robot/cancel-tasks`。

## 标签二：操作日志（`#overviewPanelLog`）

三块内容，前两块与审计有关，最后一块只是本次会话回显：

### 1. 管理员操作日志（服务端持久化审计）

读 `GET /api/admin/audit`，数据来自后端 `audit_logs` 表——由 `domains/_shared.js → auditMw` 中间件在响应时统一落库，
**成功与失败都记**，不依赖前端上报（前端也从未上报）。

| 操作 | 触发 | 函数（文件） | 接口（均 `/api/admin` 前缀） |
|---|---|---|---|
| 加载 / 翻页日志 | 切到「操作日志」标签、翻页、改筛选 | `08-audit.js → loadAudit` | `GET /audit?limit=50&offset=&role=&ok=&action=` |
| 按操作者筛选 | `#auditRole`（`admin` 仅管理员 / `all` 含商家·用户） | `loadAudit(true)` | 同上（`role` 参数） |
| 按结果筛选 | `#auditResult`（空=全部 / `1` 仅成功 / `0` 仅失败） | `loadAudit(true)` | 同上（`ok` 参数） |
| 按动作筛选 | `#auditAction` 输入框（220ms 防抖，如 `order-cancel`） | `loadAudit(true)` | 同上（`action` 参数） |
| 刷新日志 | `#auditReload` | `loadAudit(false)` | 同上（保持当前 offset） |
| 上一页 / 下一页 | `#auditPrev / #auditNext` | `loadAudit(false)` | offset 加减 `limit`，按钮在首/末页置灰 |

渲染由 `08-audit.js → renderAudit` 负责，每行显示：时间 `created_at`、成功/失败徽标（`ok`）、操作者
（`auditWho`：管理员 / 商家 / 用户 + `user_id`）、动作 `action`、目标 `target`、详情 `detail`、来源 IP 与耗时 `ms`；
底部 `#auditInfo` 显示「共 N 条，显示 a–b」。

### 2. 折叠卡「状态字典」（`#dictBox`）

低频参考资料，默认折叠（`.card.fold`，`<details>`）。由 `04-overview-ws.js → renderOverview` 渲染
`TASK_STATUS`（任务状态码）+ 分隔行「机器状态」+ `MACHINE_TEXT`（机器状态码）两份字典。

### 3. 折叠卡「本次会话回显」（`#log`）

`01-core.js → log` 写入的**前端内存日志**（时间戳 + 分级样式），只记录本次页面会话发生的事，
刷新即清空，**不是审计**，与上面的 `audit_logs` 无关。需要追责时看「管理员操作日志」。

## 总览页校园实时地图（admin-map.js）

「机器人」标签右侧是 Leaflet 实时地图，由 `管理员网页/js/parts/map/*.js` 五片实现（与 admin.js 同构的 IIFE 分片）：

- **坐标系**（`01-init.js`）：Leaflet `CRS.Simple` 像素坐标，平台雷达地图 PNG 为唯一底图；按平台 map 元数据
  `{ width, height, resolution, origin }` 做像素级对齐，`toPixel` 把世界坐标（米）线性映射为图像像素（y 翻转），
  点位 / 路网 / 无人车 / 配送站位与雷达图严格对齐，不再用 bbox 外包框或经纬度近似；
- **底图**：`/api/dashboard/map-image`（与可视化大屏同一后端代理地址）；首次 `fitBounds` 显示全图并把最小缩放锁为全图大小（`applyRadar`）；
- **静态层**（`02-static.js`）：`updateLandmarks` 按类型分色渲染平台点位——取货点蓝 `#1d5bd6`、上货点橙 `#e8890c`、
  充电点绿 `#2f9e44`、巡逻点紫（circleMarker + 悬停泡泡），名字文字常驻可见；`usableLandmarks` 剔除名为「固定路径」的噪音点位；
  `updateRoutes` 把配送站位按停靠顺序画成编号钉（`stopSvg`）；
- **车辆层**（`03-cars.js`）：`updateCars` 按 `device_sn` 复用标记，SVG 铲形俯视车图标 + 车名（尾 6 位），车头随航向
  `deg = HEADING_OFFSET - θ` 旋转；`applyRouteFocus` 与 `highlightBatchDetail / clearBatchFocus` 实现批次聚焦
  （目标批次站位高亮、其余降透明，并 fitBounds 定位）；
- **渲染与拉取**（`04-render.js`）：`poll` 拉 `GET /api/admin/map`（adminGuard 鉴权，服务端 3 秒缓存）→ `renderMap`
  （写 `META`、铺雷达图、更新静态层与车辆、刷新底栏 `#mapFoot` 统计）；`setMask` 控制加载/失败遮罩；
- **实时层**（`05-live.js`）：`window.mapOnLive` 由 admin.js 的 WS live 事件调用，原地只更新小车与实时心跳底栏
  （`#mapFoot` 显示各车坐标与时间戳），不整体重拉；`trackCar` 记录每台车最近 80 个位置画绿色虚线轨迹；
  `ensureFollowBtn` 提供「跟随小车」按钮（约 12m×12m 视野 + 边沿跟随，小车驶出中部 33% 安全区才平移追过去）；
  `invalidateAdminMap` 在标签切回时刷新尺寸；`reloadAdminMap`（= poll）在 WS 重连/初次加载时拉一次完整地图；
  `adminMapDebug` 为排障钩子；「回到校园」按钮 `#mapResetBtn` 复位到全图。

地图块高度在 `css/map.css` 里固定为 `height: clamp(320px, 42vh, 520px)`。原先是 `aspect-ratio: 1/1`，
会把总览整行撑得很高、机器人卡被迫留大片空白，故改为固定区间。
