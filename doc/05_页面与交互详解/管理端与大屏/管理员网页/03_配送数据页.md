# 管理员网页 · 配送数据页

配送数据页（`#page-data`）是**批次 / 订单 / 任务**三类数据在**活跃 / 历史 / 全部**三种口径下的统一视图，
用卡片而不是表格展示，整卡点击开详情抽屉、右键开操作菜单。点击左侧导航「配送数据」进入（`navTo('data')`）。

> **为什么合并**：原「配送任务」页与「历史记录」页本是同一批数据的不同过滤——配送任务·订单页展示的是全部订单，
> 与历史·订单完全重叠，两页工具栏还逐字重复。2026-09 重构后合并为一页，用分段切换口径。

## 页面结构

| 位置 | 元素 | 说明 |
|---|---|---|
| 页面头·标签 | `#dataTabs` | `批次`(batch) / `订单`(order) / `任务`(task)，面板 id 前缀 `dataPanel`（`dataPanelBatch / dataPanelOrder / dataPanelTask`） |
| 页面头·分段 | `#dataScope`（`.seg`） | `活跃`(active) / `历史`(history) / `全部`(all)，默认「活跃」 |
| 页面头·搜索 | `#dataSearch` | 单一搜索框，160ms 防抖（`02-nav.js → wireSearch`），跨批次号 / 订单号 / 任务号 / 点位 / 商品名 |
| 页面头·筛选 | `#dataStatus` | 按当前标签的实体类型填充状态选项（`02-nav.js → fillStatusOptions`） |
| 页面头·计数 | `#dataCount` | 由 `05-render-cards.js → renderDataPage` 回填「共 N 张卡」 |
| 页面体 | `.page-body` | 唯一滚动区，三个面板在此切换 |

标签切换由 `02-nav.js → wireTabs('dataTabs')` 处理：换标签时清空状态筛选、按新类型重填 `#dataStatus`、`showPanel` 换面板并重渲染；
分段点击直接写 `dataScope` 后重渲染；`#dataStatus` 的 `change` 写 `statusFilter` 后重渲染。

## 活跃 / 历史口径

`05-render-cards.js → inScope(kind, row)`，与后端 admin 域的 active/history 判定完全一致：

| 实体 | 活跃判定 | 历史判定 | 「全部」 |
|---|---|---|---|
| 批次 batch | `status IN (0,1,2)` | 其余（3 已完成 / 4 已取消） | 不过滤 |
| 订单 order | `status IN (2,3,6)`（配送中 / 已送达 / 配送异常） | 其余 | 不过滤 |
| 任务 task | `void_at` 为空且 `task_status < 80` | 其余 | 不过滤 |

同口径也用于 `01-core.js → ACTIVE_STATUS` 常量与 `04-overview-ws.js → renderNavCount` 的侧栏徽标计数。

数据来源：`06-refresh-token.js → refresh` 拉 `GET /api/admin/state`，前端本地过滤。
后端聚合口径为「活跃全量 + 终态最近 100 条」（活跃 LIMIT 50、历史 LIMIT 100），
所以「历史 / 全部」看到的是近期终态数据而非全库历史。

## 卡片式展示（取代原表格）

`05-render-cards.js`，外层 `.cards` 栅格（`repeat(auto-fill, minmax(400px, 1fr))`），空结果渲染 `.empty` 提示。

### 批次卡（`.bcard`，内含订单子卡）

`batchCardHtml(b, ordersOfBatch)`：整行头部底色按状态取色（`01-core.js → batchHeadColor` 注入 `--bh`：
配送中蓝 / 已完成绿 / 组单中·待上货橙 / 其余灰），头部为「批次短号 + 完整批次号（弱化）+ 状态标签 + N 单」；
信息行按存在与否渲染：

| 信息行 | 数据 |
|---|---|
| 机器人 | `device_sn`（有才显示） |
| 件数 | `total_items`（非 0 才显示） |
| 路线 | `03-menu.js → batchRouteText`（`route` JSON 解析成「点位A → 点位B」） |
| 当前停靠 / 进度 | 仅 `status === 2` 时显示：`currentStopText`（第 N 站 / 共 M 站）+「已取 x / y 单」 |
| 创建 / 最近变更 | `created_at`；`last_event`（后端 `status_events` 最新一条，`01-core.js → lastEventText`） |

信息行下面内嵌订单子卡 `.bcard-order`（`orderSubCardHtml`）：订单短号 + 点位标签 + 状态标签 +
商品行（`orderGoodsRows`，批次内每单最多 4 行，超出折叠为「等 N 项商品」）+ 取餐码 + 金额。
该批次在 `state.orders` 里没有可展示的订单时显示「该批次暂无可展示的订单明细」。

> **注意**：子卡数据取自 `state.orders`（活跃 50 / 终态 100 的窗口），不是「批次内订单全量」接口，
> 因此很老的批次可能只显示上面这句提示；后端 `GET /api/admin/batch/orders` 已无前端调用方。

### 订单卡（`.bcard`，扁平列表）

`renderOrderCards`：头部底色固定 `--ink-3`，头部为「订单短号 + 完整订单号 + 状态标签」；
信息行：送达点位 `landmark_name`、批次 `batch_id`（经 `state.batches` 映射成批次号）、机器人 `device_sn`（后端按批次回填）、
取餐码 `pickup_code`、金额 `total_amount`、创建 `created_at`、最近变更 `last_event`；
再嵌一个「商品明细」子块（`orderGoodsRows(o, 8)`，标题右侧显示 `item_count` 件）。

> **已知差异**：`state.orders` 的 SQL（`backend/domains/admin/queries.js → activeOrders / historyOrders`）
> 没有 select `pickup_code`，所以订单卡与批次子卡上的「取餐码」目前恒显示「—」；
> 详情抽屉的取餐码走 `GET /admin/timeline` 的 `context.pickup_code`，是真值。

### 任务卡（`.tcard`，扁平列表）

`renderTaskCards`：头部「任务 #id + 状态标签」，信息行：订单（`order_id` 映射订单号）、批次（`batch_id` 映射批次号）、
平台任务 `platform_task_id`、设备 `device_sn`、停留（`ageCell(updated_at)`，超时加陈旧色）、最近变更 `last_event`；
`void_at` 非空时额外显示「作废于」。

### 卡片交互（两种入口）

- **整卡点击 / 回车** → 打开详情抽屉（`onclick="openDrawer('batch',id)"`，`onkeydown` 支持 Enter，卡片带 `tabindex="0"`）；
- **右键** → 上下文菜单（`oncontextmenu="window.ctxBatch(id,event)"`）。

## 右键上下文菜单（`#ctxMenu`，破坏性操作的唯一入口）

`03-menu.js → showCtx / hideCtx`，按实体挂接 `ctxBatch / ctxOrder / ctxTask`；
菜单自动贴边收敛，窗口外点击 / Esc / 失焦自动关闭。**卡片上没有任何行内破坏性按钮。**

| 实体 | 菜单项 | 出现条件 | 函数（文件） | 接口（均 `/api/admin` 前缀） |
|---|---|---|---|---|
| 订单 | 复制订单号 | 始终 | `copyText(o.order_no)` | 纯前端 |
| 订单 | 查看详情与时间线 | 始终 | `openDrawer('order', id)` | `GET /timeline?type=order&id=` |
| 订单 | 删除订单（危险） | `status IN (0,1,2,3,6)` | `09-ops.js → actCancelOrder` | `POST /order/cancel { order_id }` |
| 批次 | 复制批次号 | 始终 | `copyText(b.batch_no)` | 纯前端 |
| 批次 | 查看详情与时间线 | 始终 | `openDrawer('batch', id)` | `GET /timeline?type=batch&id=` |
| 批次 | 在地图查看配送站位 | `status === 2` 且 `route` 有站位 | `03-menu.js → goBatchMap` | 跳总览并 `highlightBatchDetail` 高亮，无接口 |
| 批次 | 清理批次（危险） | `status IN (0,1,2)` | `09-ops.js → actCancelBatch` | `POST /batch/cancel { batch_id }` |
| 任务 | 复制任务号 | 始终 | `copyText(String(t.id))` | 纯前端 |
| 任务 | 查看详情与时间线 | 始终 | `openDrawer('task', id)` | `GET /timeline?type=task&id=` |
| 任务 | 关闭并作废（危险） | `task_status ∉ (80,110,150)` 且未作废 | `09-ops.js → actCloseVoid` | `POST /task/close-void { task_id }` |
| 任务 | 仅作废（不关平台任务）（危险） | 同上 | `09-ops.js → actVoid` | `POST /task/void { task_id }` |

危险项均由 `09-ops.js → confirmRun` 走 `window.confirm` 二次确认后执行，成功后统一 `refresh()`（统一落账：
作废任务 + 回补库存 + 摘批次 + 平台召回）。

## 详情抽屉（`#detailDrawer`）

`07-drawer.js`：`window.openDrawer(type, id)` 打开、`window.closeDrawer()` 关闭（Esc、点遮罩 `.drawer-mask` 均可关；
抽屉打开期间切到别的卡片会丢弃过期响应）。标题为「批次 / 订单 / 任务 #id」，内容按小节依次渲染：

| 小节 | 内容 |
|---|---|
| 概要 | `kvLine` 行：批次（批次号 / 状态 / 机器人 / 单数·件数 / 已取 / 路线 / 当前停靠 / 创建时间）、订单（订单号 / 状态 / 送达点位 / 批次 / 取餐码 / 金额 / 创建时间）、任务（任务号 / 状态 / 平台任务 / 设备） |
| 商品明细 | 仅订单：`orderGoodsRows(o, 20)` |
| 状态时间线 | `drawerTimelineHtml`，见下 |
| 实时位置 | `drawerLiveHtml`，见下 |
| 操作 | 「复制编号」`window.drawerCopy`、「刷新时间线」`window.drawerRefresh`；并提示破坏性操作请右键卡片 |

### 状态时间线

数据来自 `GET /api/admin/timeline?type=order|batch|task&id=`（`backend/domains/admin/service.js → buildTimeline`），
返回 `{ type, id, current, context, events, legacy }`：

- `events`：`status_events` 里的**真实事件**，按时间正序。字段 `from_status / to_status / status_text / actor_type /
  actor_name / note / created_at`；`actor_type` 取值 `system | admin | merchant | user | platform`，
  前端显示为「系统 / 管理员·名 / 商家 / 用户 / 平台」；
- `type=batch` 时后端会**合并批内订单事件**，事件带 `order_short` 标注归属订单，前端在时间行尾显示「订单 xxx」；
- `legacy`：**推断节点**。该对象产生于状态流水上线之前（没有任何真实事件）时，后端用既有时间列拼出节点
  （订单：创建/送达/已取餐/取消/最后变更；批次：创建/派车/上货完成/完成/最后变更；任务：最后变更/作废），
  前端给每个节点打「推断」标签并提示「可能不完整」；**有真实事件时 `legacy` 为空数组**（新旧不混排）；
- 节点圆点配色由 `01-core.js → statusDotClass` 按类型与目标状态决定。

### 实时位置

不新增接口：复用 WS `live` 推送的机器人坐标（闭包变量 `liveRobots`）+ 批次 `current_stop`。

- 设备来源：批次 / 任务取 `timeline.current.device_sn`；订单本身没有设备，取所属批次的 `device_sn`；
  都没有时提示「该对象当前没有关联的机器人（未派车或已释放）」；
- 命中 `liveRobots` 时显示实时坐标 `x/y`、航向 `θ` 与「位置更新 <时间>（实时推送）」；
  未命中提示「位置暂不可用（机器人离线或未上报）」；
- 批次配送中（`status === 2`）时给一个「在总览地图查看」按钮 → `window.goBatchMap(id)`（跳总览并高亮配送站位）；
- WS `live` 事件到达时若抽屉正开着，只原地刷新本段（`renderDrawerLive`），不整页重绘。

## 已删除的旧机制（别再找）

- **表格渲染**：`renderTasksPage / renderExec / renderBatchPanel / renderOrderPanel / renderLocalTaskPanel` 全部删除，
  改由 `05-render-cards.js` 的卡片渲染承担；
- **多选与批量**：`sel` / `toggleSel` / `toggleSelAll` / `clearSel` / `updateSelUI` / `runBulkOrder` / `runBulkBatch` / `runBulkTask`
  与批量栏、勾选框、全选列全部删除（历史态本就只读，那些按钮是无效 UI）；后端 `orders/bulk-cancel` 等接口保留但页面不再调用；
- **批次展开箭头**：`toggleExpand / expandRow / batchOrdersCache` 删除，改为批次卡内嵌订单子卡；
- **平台任务表**：`renderPlatformPanel`、容器 `#tasksPanelPlatform`、`ctxPlat`、`runBulkPlat`、`sel.plat` 删除
  （`state.platform_tasks` 仍在，只用于刷新日志计数与后端告警检测）；
- `#histCount`、`#tasksSearch`、`#historySearch`、`#tasksKind / #historyKind` 等历史遗留 id 与 `maybeAutoExpandByOrderNo` 一并删除，
  统一为 `#dataSearch / #dataStatus / #dataCount`。
