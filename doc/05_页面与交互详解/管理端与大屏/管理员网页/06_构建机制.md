# 管理员网页 · 构建机制

`管理员网页/build.js` 是「拆分式构建」脚本，把按数据域拆散的小文件拼成两个浏览器直接引用的产物。

## 为什么 parts 不能单独运行

- 每个 parts 文件只是同一个 IIFE 闭包里的「一段」：`01-core.js` 开头是 `(function () { 'use strict' …` 与闭包共享变量
  （`state / liveRobots / busy / currentAdmin / onUnauthorized / overviewTab / drawerCtx / TOKEN_KEY`），
  `09b-ops.js` 末尾才是启动逻辑与 `})()` 收尾；
- 中间片段无导出、无独立入口，且互相交叉引用（示例）：
  - `02-nav.js` 用 `01-core.js` 的 `$ / api`，用 `08-audit.js → loadAudit`，用 `09a-merchants.js → loadMerchants`；
  - `03-menu.js` 调 `09b-ops.js → actStop / actRecover / actStopCancel`，还调 `02-nav.js → navTo`（右键菜单只剩机器人卡的「更多操作」）；
  - `04-overview-ws.js` 调 `08-audit.js → loadAudit`、`07-drawer.js → renderDrawerLive`，并调用 `admin-map.js` 暴露的 `window.mapOnLive / reloadAdminMap / invalidateAdminMap`；
  - `06-refresh-token.js` 给 `01-core.js` 声明的 `onUnauthorized` 赋值，并调 `04-overview-ws.js → connectWS`、`07-drawer.js → closeDrawer`；
  - `07-drawer.js` 自带 `orderGoodsRows`（2026-10-12 随 `05-render-cards.js` 删除一并搬入，抽屉是它唯一调用方），
    并用 `03-menu.js` 的 `copyText / batchRouteText / currentStopText / goBatchMap`；
  - `09b-ops.js`（启动与收尾）使用上述全部片段中的函数与变量；
- 单独加载任何一个片段都会因引用未定义变量抛 ReferenceError；只有 `01-core.js` 的 IIFE 头与 `09b-ops.js` 的 IIFE 尾合起来才构成完整脚本。
  （注意：`02 / 03 / 04 / 06 / 07 / 08` 等片段恰好自身语法闭合，`node --check` 单查也会通过，但那不代表能独立运行。）

## CUTS 常量作用

```js
const CUTS = {
  'admin.js':     [119, 193, 282, 389, 514, 723, 944, 1156, 1381],
  'admin-map.js': [100, 158, 220, 273, 382],
}
```

- `CUTS` 记录每个输出文件各 parts 片段的「末行号」（1-based），即切块边界，单调递增；
- **正向构建 `node build.js` 只依赖 TARGETS**，按顺序把各片用 `'\n'` 相连后写出，完全不读 CUTS；
- `node build.js --gen` 才按 CUTS 边界把输出文件重新切回 parts（逐字节等价），供首次生成或直接改了产物后回拆使用；
- 行数换算式：`cut_i = 前 i 个 parts 的行数之和 + i`——每片文件以换行结尾，按 `split(/\r?\n/)` 计数时每片会多出一个空串元素；
  拼接时用 `'\n'` 相连，分隔符正好被行边界吸收，所以不再额外 `+1`。
  例：`01-core` 118 行 → `cut₁ = 119`；累计到 `09b-ops`（224 行）得 `cut₉ = 1381`（正好等于产物 `admin.js` 的总行数）。
- 日常约定：只改 `js/parts/` 下的源文件，改完执行 `node build.js` 重新拼接；改过 parts 后若要继续用 `--gen`，先按上式刷新 CUTS 表。
