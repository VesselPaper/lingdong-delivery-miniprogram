# 管理员网页 · 构建机制

`管理员网页/build.js` 是「拆分式构建」脚本，把按数据域拆散的小文件拼成两个浏览器直接引用的产物。

## TARGETS 清单（顺序即拼接顺序）

| 输出文件 | parts 清单 | 内容划分 |
|---|---|---|
| `admin.js` | `01-core → 07-ops` 共 7 片 | 头部 IIFE/常量/工具（`esc / log / toast / api / 状态字典`）→ 导航 → 选择与批量 → 总览与 WS → 表格渲染 → 刷新与认证 → 操作与启动 |
| `admin-map.js` | `map/01-init → 05-live` 共 5 片 | 地图初始化（元数据/坐标映射/雷达底图）→ 静态点位与配送站位 → 无人车图层 → 渲染与拉取 → 实时层 |

## 为什么 parts 不能单独运行

- 每个 parts 文件只是同一个 IIFE 闭包里的「一段」：`01-core.js` 开头是 `(function () { 'use strict' …` 与闭包共享变量
  （`state / sel / expandedSet / batchOrdersCache / statusFilter / searchQ / busy / onUnauthorized / TOKEN_KEY`），
  `07-ops.js` 末尾才是启动逻辑与 `})()` 收尾；
- 中间片段无导出、无独立入口，且互相交叉引用：`02-nav.js` 用 `api / state / expandedSet`；
  `03-select.js` 调 `refresh / renderTasksPage`（分别定义于 06、05 片）；`04-overview-ws.js` 调 `renderTasksPage / renderHistoryPage`；
  `06-refresh-token.js` 给 `01-core.js` 声明的 `onUnauthorized` 赋值；`07-ops.js` 使用上述全部片段中的函数与变量；
- 单独加载任何一个片段都会因引用未定义变量抛 ReferenceError；只有 `01-core.js` 的 IIFE 头与 `07-ops.js` 的 IIFE 尾合起来才构成完整脚本。

## CUTS 常量作用

- `CUTS` 记录每个输出文件各 parts 片段的「末行号」（1-based）；
- 正向构建 `node build.js` 按 TARGETS 顺序拼接，不依赖 CUTS；
- `node build.js --gen` 按 CUTS 边界把输出文件重新切回 parts（逐字节等价），供首次生成或直接改了产物后回拆使用；
- 日常约定：只改 `js/parts/` 下的源文件，改完执行 `node build.js` 重新拼接。
