# 管理员网页 · 设置页

设置页（`#page-settings`）包含三个标签：**账号 / 机器人控制 / 危险操作**。
点击左侧导航「设置」进入（`navTo('settings')`），标签由 `02-nav.js → wireTabs('settingsTabs')` 绑定，
面板 id 为 `settingsPanelAccount / settingsPanelRobot / settingsPanelDanger`。

## 标签一：账号（`#settingsPanelAccount`）

### 当前账号

`06-refresh-token.js → renderAccountUI` 回填，登录成功后与 `/me` 校验通过后各调一次：

| 元素 | 内容 |
|---|---|
| `#accountName` | 当前管理员用户名（`currentAdmin.username`），未登录为「—」 |
| `#accountRole` | 昵称 + 角色（`nickname · role`，无昵称时只显示 `role`） |
| `#logoutBtn` | 「退出登录」→ `06-refresh-token.js → logout`：先 `POST /logout` 吊销当前 session（失败忽略），再清 `localStorage` 里的 token、置空 `state` 与 `currentAdmin`、关闭 WebSocket、`closeDrawer()`、`showLogin()` |

### 修改密码

`06-refresh-token.js → changePassword`，绑定在 `#savePass` 上。依次校验「原密码与新密码均填写」
「两次新密码一致」「新密码至少 8 位」（错误写 `#tokenMsg` 并标红），通过后调
`POST /api/admin/password { old_password, new_password }`；后端改密后吊销该账号全部 session，
前端提示「密码已修改，请重新登录」并在 800ms 后自动 `logout`。

| 元素 | 作用 |
|---|---|
| `#oldPass` | 原密码 |
| `#np1 / #np2` | 新密码 / 再次输入新密码 |
| `#savePass` | 提交按钮 |
| `#tokenMsg` | 校验与结果提示（`.token-msg.ok / .err`） |

> 登录、token 存取、401 全局处理与登录限流细节见 [01_登录与会话.md](01_登录与会话.md)。

## 标签二：机器人控制（`#settingsPanelRobot`）

两块内容：**设备控制权** 与 **平台点位**。原「控制权与点位」合成一张卡，现按语义拆成两张
（点位同步与控制权无关，放在一起容易误解）。

### 设备控制权

| 操作 | 触发 | 函数（文件） | 接口（均 `/api/admin` 前缀） |
|---|---|---|---|
| 获取控制权 | 按钮「获取控制权」 | `09-ops.js → actGrant` | `POST /control/grant { device_sn }`（600 秒） |
| 释放控制权 | 按钮「释放控制权」 | `09-ops.js → actRelease` | `POST /control/release { device_sn }` |

- **已删除手填控制权 ID 的输入框 `#ctrlId`**：后端在「获取控制权」时已把平台返回的 `ctrlId` 持久化到
  `meta` 表（键 `ctrl_id:<device_sn>`，见 `backend/domains/admin/routes.js → /admin/control/grant`），
  「释放控制权」时若请求体没带 `ctrl_id` 就自动读这份记录（释放成功后删除），前端因此不需要也不应该让管理员手工填。
- 卡片说明文案即表达这一点：「获取后系统会记住控制权 ID，『释放』无需再手工填写。」

### 平台点位

| 操作 | 触发 | 函数（文件） | 接口（均 `/api/admin` 前缀） |
|---|---|---|---|
| 同步点位 | 按钮「同步点位」 | `09-ops.js → actSyncLm` | `POST /landmarks/sync {}`（平台 landmarks 拉到本地库；召唤与配送选点依赖这份数据） |

## 标签三：危险操作（`#settingsPanelDanger`）

| 操作 | 触发 | 函数（文件） | 接口（均 `/api/admin` 前缀） |
|---|---|---|---|
| 一键初始化状态 | 按钮 `#reset` | `09-ops.js` 内 `$('reset').onclick` | `POST /reset {}`：关全部平台活跃任务 + 释放全部控制权 + 删除全部活跃订单（作废任务 + 回补库存 + 平台召回）+ 批次全部置已取消 |

点击后弹 `window.confirm`（逐条列出将执行的四步），确认后调接口；返回 `{ closed, released, cancelled, batch_cleaned, failed }`，
前端把结果拼成一句话 toast + log（有失败项时标 warn 并列出前 5 条），随后 `refresh()`，
操作日志页正开着则顺带 `loadAudit(true)`。该操作作用于真实机器人，不可撤销。

所有设置页写操作都由 `09-ops.js → run` 统一执行（成功 toast + `refresh()`，失败走 `opFail`），
危险操作额外经 `confirmRun` 二次确认。
