# 管理员网页 · 页面骨架与通用机制

管理员网页（调度台）由 `管理员网页/index.html` 定义页面骨架，`管理员网页/admin.js`（构建产物）承载全部交互逻辑，
`管理员网页/admin-map.js`（构建产物）承载总览页校园实时地图。页面采用「登录遮罩 + 左侧导航 + 报头 + 固定页面头 + 独立滚动内容区」的结构，
登录遮罩 `#loginMask` 默认可见，仅在会话有效或登录成功时才隐藏。

## 页面骨架（index.html 结构）

| 区块 | 元素 | 作用 |
|---|---|---|
| 矢量图标库 | `<svg><symbol id="i-*">` | 页面统一 24×24 线性图标（stroke 1.8），全部图标从本库引用，不用表情符号 |
| 左侧导航 | `.sidenav`，三个 `.nav-item[data-page]` | 总览 / 配送数据 / 设置，`onclick="navTo('xx')"`；底部只显示连接时间 `#conn`（「更新 <时间>」） |
| 报头 | `.masthead`，`#pageTitle / #pageSub` | 当前页标题与副标题；右侧「刷新」按钮 `#refresh` |
| 认证提示条 | `#authBanner` | 未登录 / 登录过期的全局提示（`setAuthBanner`），仅异常时显示 |
| 页面滚动容器 | `.page-scroll` | `flex:1` + `overflow:hidden`，自身不滚动，只作为三个页面的承载层 |
| 总览页 | `#page-overview`，两个标签 | 机器人（机器人卡 + 校园实时地图 + 异常与死锁告警）/ 操作日志（服务端审计 + 状态字典 + 会话回显） |
| 配送数据页 | `#page-data`，三个标签 × 三分段 | 批次 / 订单 / 任务 × 活跃 / 历史 / 全部；工具栏含搜索、分段、状态筛选、计数 |
| 设置页 | `#page-settings`，三个标签 | 账号（改密 / 退出）/ 机器人控制（控制权 / 平台点位）/ 危险操作 |
| 覆盖层 | `#ctxMenu / #toast / #detailDrawer / #pickModal` | 右键菜单、轻提示、详情抽屉、选择弹窗（召唤目标点 / 开关舱） |
| 登录遮罩 | `#loginMask` | 账号 + 密码表单，默认可见，登录成功或会话有效时隐藏 |
| 脚本引用 | `vendor/leaflet.js → admin.js → admin-map.js` | 按序加载，构建产物在 `index.html` 底部引用 |

## 布局：三层固定 + 只有内容区滚动

2026-09 重构后布局写在 `css/base.css` 顶部注释与规则里，**不再使用 sticky 负 margin hack**：

```
.layout  flex / height:100dvh / overflow:hidden      ← 整页不滚动
  .sidenav                                            ← 左侧导航（固定）
  .main  flex column / height:100dvh / overflow:hidden
    .masthead                                          固定：页标题 + 全局操作
    #authBanner                                        固定：仅异常时显示
    .page-scroll  flex:1 / min-height:0 / overflow:hidden
      .page.active  flex column / height:100%          ← 当前页
        .page-head   固定：标签 + 分段 + 搜索/筛选（flex:none）
        .page-body   overflow-y:auto                    ← 唯一滚动区
```

- `.masthead / .auth-banner / .page-head / .page-body` 共用同一宽度约束 `max-width: var(--content-w)`，
  `--content-w` 在 `:root` 里定义为 `1500px`，因此报头、页面头、内容区左边界与右侧规则线严格对齐；
- 切页时 `navTo` 会把该页 `.page-body` 的 `scrollTop` 归零（导航与报头/页面头固定不动）；
- 层级变量：`--z-nav:10 / --z-menu:60 / --z-modal:300 / --z-toast:400`。

## 导航与功能区块

- **一级导航**：`02-nav.js → navTo` 依据 `PAGE_META` 切换页面与标题；
  `02-nav.js → wireTabs` 统一绑定三组标签页，`showPanel(prefix, key, allKeys)` 按「前缀 + 首字母大写」拼面板 id
  （如 `dataPanel+batch` → `dataPanelBatch`）。

| 导航项 | data-page | 标题 / 副标题 | 内容区块（对应子文档） |
|---|---|---|---|
| 总览 | overview | 总览 · 机器人状态、异常与死锁监控 | 机器人（机器人卡 + 校园实时地图 + 异常与死锁告警）/ 操作日志（管理员操作日志 + 状态字典 + 本次会话回显） → [02_总览页.md](02_总览页.md) |
| 配送数据 | data | 配送数据 · 批次 / 订单 / 任务的搜索、状态与详情 | 批次 / 订单 / 任务 × 活跃 / 历史 / 全部，卡片式展示 → [03_配送数据页.md](03_配送数据页.md) |
| 设置 | settings | 设置 · 账号、控制权、点位与危险操作 | 账号 / 机器人控制 / 危险操作 → [05_设置页.md](05_设置页.md) |

- 导航从原四项（总览 / 配送任务 / 历史记录 / 设置）合并为三项：配送任务与历史记录本是同一批数据的不同过滤
  （配送任务·订单页展示全部订单，与历史·订单完全重叠，两页工具栏逐字重复），现合并为一页用「活跃 / 历史 / 全部」分段切换。
- 侧栏「配送数据」徽标 `#navTaskCount` 由 `04-overview-ws.js → renderNavCount` 计算：
  活跃批次（status ∈ 0,1,2）+ 活跃订单（status ∈ 2,3,6）+ 未完成任务（`void_at` 为空且 `task_status < 80`）的合计，大于 0 时标红。

- **标签页 / 分段 / 搜索 / 筛选**
  - `wireTabs('overviewTabs')` → `overviewTab`（`robot | log`），切到 `log` 时调 `loadAudit()`，切回 `robot` 时 `invalidateAdminMap()`；
  - `wireTabs('dataTabs')` → `dataTab`（`batch | order | task`），切换时清空状态筛选、按实体类型 `fillStatusOptions(tab)` 重填下拉、`showPanel` 换面板、`renderDataPage()`；
  - `#dataScope` 分段（`active | history | all`）直接写 `dataScope` 后重渲染，过滤口径见 `05-render-cards.js → inScope`；
  - `02-nav.js → wireSearch('dataSearch')`：单一搜索框，160ms 防抖后写 `searchQ`（跨批次号 / 订单号 / 任务号 / 点位 / 商品名）；
  - `#dataStatus` 状态筛选写 `statusFilter`，选项由 `fillStatusOptions` 按 `ORDER_STATUS / TASK_STATUS / BATCH_STATUS` 生成；
  - 计数 `#dataCount` 显示「共 N 张卡」，由 `renderDataPage` 回填。

- **数据接口与刷新**
  - `06-refresh-token.js → refresh` 一次性拉 `GET /api/admin/state`（`service.js → buildAdminState` 聚合设备、平台任务、
    本地批次/订单/任务、死锁与异常告警），写入闭包变量 `state`，`busy` 标志防重入，`#conn` 显示「更新于 server_time」；
  - 聚合口径：活跃记录全量 + 终态各取最近 100 条（`queries.js → active*/history*`，活跃 LIMIT 50、历史 LIMIT 100），
    所以「历史 / 全部」分段看到的是近期终态数据，不是全库历史；
  - `04-overview-ws.js → render` 分发渲染：`renderOverview / renderDataPage / renderNavCount`；
  - 列表数据全部来自 `state`，前端本地过滤，不再有表格懒加载接口。

- **WebSocket 实时层**（`04-overview-ws.js`，事件驱动、前端不轮询）
  - 连接地址 `wsURL()`：`ws(s)://host/ws?token=..&src=admin`，`connectWS` 建立连接后订阅主题 `admin/live`；
  - `live` 事件：`m.robots` 存入 `liveRobots`（供详情抽屉「实时位置」读取）并交给 `window.mapOnLive` 更新地图小车，
    抽屉正开着则原地刷新其实时位置段（`renderDrawerLive`）；`m.robot` 原地刷新机器人卡片（`renderRobotCard`，不整页重绘）；
  - `state_changed` 事件：触发一次 `refresh()`；
  - 断线 4 秒重连（`scheduleReconnect`）；`09-ops.js` 启动段另有 20 秒一次的健康探查，只重连不拉数据。

## 状态色映射

`01-core.js`：`orderTag / batchTag / taskTag` 按状态码映射颜色与中文文案；`batchHeadColor` 给批次卡整行头部取底色
（注入 `--bh`）；`statusDotClass` 给时间线节点圆点取色；`ageLabel / ageCell` 把时间转为
「刚刚 / N 分钟 / N 小时 / N 天」并加陈旧色（>20 分钟 `stale-soft`、>1 小时 `stale`）；
`lastEventText` 把 `last_event`（后端 `status_events` 最新一条）渲染成「时间 · 状态」的「最近变更」摘要。

## 通用操作约定

- **破坏性操作只从右键菜单进入**（`01-core.js` 头部注释里的铁律）：删除订单 / 清理批次 / 关闭并作废 / 仅作废
  在卡片上没有任何行内按钮；卡片整卡点击 = 打开详情抽屉。这样同一操作只有一个入口，也避免历史态（只读）出现无效按钮。
- 所有写操作统一走后端「统一落账」（作废任务 + 回补库存 + 摘批次 + 平台召回关任务），保证机器人状态、用户端、商家端同步。
- 通用执行器为 `09-ops.js → run / confirmRun`：先 log，成功即 toast + `refresh()` 重新拉全量
  （操作日志页正开着顺带 `loadAudit(true)`；抽屉正开着顺带 `drawerRefresh()`）；失败走 `09-ops.js → opFail`
  （401 转认证横幅 `setAuthBanner`，其余 toast + log）。危险操作均经 `window.confirm` 二次确认。
- 右键菜单（`03-menu.js → showCtx / hideCtx`）按实体挂接 `ctxOrder / ctxBatch / ctxTask`（卡片上以
  `oncontextmenu="window.ctxXxx(id,event)"` 触发），机器人卡「更多操作」按钮复用同一菜单（`showRobotMenu`）；
  菜单自动贴边收敛，窗口外点击 / Esc / 失焦自动关闭。
- 复制编号：`03-menu.js → copyText / fallbackCopy`，纯前端（clipboard API → execCommand 兜底），
  右键菜单与详情抽屉「复制编号」共用。
- 认证提示条文案：会话失效时为「登录已过期：请重新登录」+ 提示「请重新登录后再操作」
  （原「请在上方输入正确的管理员令牌后保存」已随静态令牌方案废弃而删除）。
- 手动刷新：报头「刷新」按钮 `#refresh` → `refresh`（`06-refresh-token.js`），重新拉 `GET /api/admin/state`。
