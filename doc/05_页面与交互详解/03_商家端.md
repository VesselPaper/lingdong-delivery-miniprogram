**本部分范围**：本章逐页详解微信原生小程序「零栋商家」（目录 `商家端/`）的全部 22 个页面与 6 个通用组件。每个页面按「职责 → 数据来源 → 页面构成 → 交互清单 → 重点链路 → 状态与边界」组织；函数名、接口路径、跳转目标均取自真实代码，定位格式为「商家端/pages/xxx/xxx.js → 函数名」。接口统一以 `/api` 为前缀（实际前缀由 `商家端/utils/config.js → baseUrl` 拼接，开发环境为局域网地址，如 `http://10.75.155.19:3000/api`）。

### 通用机制（辅助文件）

- **请求封装** `商家端/utils/request.js → request/get/post/put/del`：统一拼接 `config.baseUrl`、注入 `Authorization: Bearer <token>`、15 秒超时（注释明确：监控页每 5 秒一轮，60 秒默认超时会在弱网下堆积悬挂请求）。未登录不发请求直接 `wx.reLaunch` 登录页；`401/403` 时调用 `clearLoginState()` 清登录态并回登录页 —— 403 同等处理，否则非商家账号一旦登录就永久卡在「无权限」且没有路径回登录页。业务失败（`code !== 0`）统一 toast 展示 `msg` 3 秒，`silent` 选项可关闭提示。
- **登录态清理** `商家端/utils/request.js → clearLoginState`：删除缓存键 `token / userInfo / runtimeFlags / shopInfo`，清空 `app.globalData.token/userInfo`，并断开推送 WebSocket（`商家端/utils/push.js → destroy`）。注释明确店员手机常共用，不清干净会让换人登录后的工作台先显示上一位商家的营业状态、自动接单开关与配送费。
- **店铺状态** `商家端/utils/shopState.js`：`loadShop()` 拉取 GET /api/merchant/shop 并缓存到本地 `shopInfo`，失败回退本地缓存；`isOpen/getBusiness/getAutoAccept/getDeliveryFee` 读缓存（配送费非法值回退 1 元）；`setBusiness/setAutoAccept/setDeliveryFee` 写 PUT /api/merchant/shop（配送费限制 0~999 且保留两位小数），请求失败时乐观更新本地缓存保证 UI 不卡死。
- **实时推送** `商家端/utils/push.js`：WebSocket 地址由 `baseUrl` 推导（http→ws、去 `/api` 拼 `/ws`），token 放握手 header。首页/工作台/任务页/上货配单页在 `onLoad` 用 `subscribe` 订阅、`onUnload` 用 `unsubscribe` 退订；收到 `order_created` 事件后由页面自行重拉接口做局部刷新。断线指数退避重连（1.5s→15s 封顶），最后一个订阅者离开即断开（避免无人监听时永久重连耗电），登出时 `destroy()` 显式断开并置 `closedByUser`。
- **自定义 tabBar** `商家端/custom-tab-bar/index.js`：仅「首页 / 我的」两个 tab，`wx.switchTab` 切换；首页与「我的」页在 `onShow` 里通过 `getTabBar().setData({ selected })` 同步选中态，`pageLifetimes.show` 与 `attached` 里 `updateSelected` 兜底校正。
- **启动路由** `商家端/app.js → onLaunch`：有 token 时置 `globalData.autoEnterShop = true`（冷启动后首页自动进工作台页，只消费一次）；无 token 直接 `wx.reLaunch` 登录页。

### 状态/样式映射速览（读自真实代码常量）

- **订单状态色板** `商家端/pages/orders/list.js → ST_CLASS`（history/detail/exception/batchDetail 同构）：`0 灰 / 1 橙 / 2 蓝 / 3 绿 / 4 绿 / 5 灰 / 6 红 / 7 灰`；展示文案以 `status_text` 或 `stage_text` 为准（已取订单显示「已取」）。
- **批次状态** `商家端/pages/orders/list.js → BATCH_TEXT/BATCH_TAG`：`0 组单中（灰）/ 1 待上货（橙）/ 2 配送中（蓝）/ 3 已完成（绿）/ 4 异常（红）`；待取货分类下卡片文案强制为「待取货」。
- **角标数字语义**：`pending_orders` / `pendingBatchCount` 均为「组单中 + 待上货批次内订单总数」，不是批次个数；工作台与任务页右上角红点同源（GET /api/merchant/device/pending）。
- **运行模式标志** `runtimeFlags`：登录响应下发 `device_mock`（上货页开舱/关舱/派发走模拟还是真实分支）、`login`（登录按钮是否显示「模拟登录（演示）」）。

## pages/index/index —— 首页 tab：站点入口与营业状态

- **数据来源**：`onShow` → `商家端/pages/index/index.js → onShow` 调 `shopState.loadShop()`（GET /api/merchant/shop）后 `setData({ shopOpen })`，商铺卡片右上角渲染「营业中（绿）/歇业中（灰）」标签。
- **页面构成**：顶部搜索框（占位「请输入商铺名称」）+「锁定排序」图标按钮；中部商铺卡片 = 商铺名「四川师范大学商铺」+ 营业标签 + 「上次访问」角标 + 底部「进入站点」行（时间图标 + 蓝色文字）。
- **交互清单**：

| 按钮/交互 | 触发函数 | 行为与调用的接口 | 后续链路/跳转 |
| --- | --- | --- | --- |
| 搜索输入框 | onSearch | 仅更新本地 `keyword`，本页未参与过滤 | — |
| 锁定排序 | lockSort | toast「锁定排序功能开发中」 | — |
| 商铺卡片（进入站点） | goShop | — | `wx.navigateTo` → /pages/shop/home |
| tabBar 选中态同步 | onShow | `getTabBar().setData({ selected: 0 })` | — |

- **重点链路**：冷启动（`app.js → onLaunch` 检测到 token）或刚登录（登录页置位）都会把 `globalData.autoEnterShop` 置 true；首页 `onShow` 消费该标志（先置 false 再跳转），保证**只自动跳一次**，用户从工作台返回首页后不会再被弹进去。
- **状态与边界**：未登录冷启动由 `app.js → onLaunch` 直接 `reLaunch` 登录页，首页不会闪现；`shopOpen` 仅用于标签展示，真实开关以后端为准。

## pages/user/login —— 商家登录（微信一键登录 + 邀请码）

- **数据来源**：`onShow` 读本地缓存 `runtimeFlags.login === 'demo'`，决定按钮文案「模拟登录（演示）」或「微信一键登录」，并显示对应演示模式说明行。
- **页面构成**：顶部品牌区（圆形 logo + 「零栋商家」+「商家登录管理商品与配送」）；中部「商家邀请码」输入框（占位「首次登录必填，由店主提供」）+ 提示「商家权限只能凭邀请码授予，客户端无法自行声明身份」；底部主按钮 + 协议声明「登录即同意《商家入驻协议》与《隐私政策》」。
- **交互清单**：

| 按钮/交互 | 触发函数 | 行为与调用的接口 | 后续链路/跳转 |
| --- | --- | --- | --- |
| 邀请码输入 | onCodeInput | 更新 `merchantCode` | — |
| 微信一键登录 | wechatLogin | `wx.login` 取 code → POST /api/auth/login（body：`code、client:'merchant'、nickname:'零栋铺子'、merchant_code`，`needAuth:false`） | 校验通过后 `wx.switchTab` → /pages/index/index |

- **重点链路**：登录接口显式传 `needAuth: false`（否则被 `request` 的未登录拦截永远发不出去）；`client:'merchant'` 供后端选择商家端 appid/secret 走真实 code2session，不再传 `role` —— 服务端不接受客户端自报身份，商家权限只能凭 `merchant_code` 授予。**先校验身份再落盘**：`res.user.role !== 'merchant'` 时弹窗「当前不是商家账号」并直接 return，绝不写 token —— 否则下次冷启动跳过登录页，之后所有 `/merchant/*` 都会 403，用户只看到「无权限」却没有任何路径回登录页。通过后依次写 `token`、`userInfo`、`runtimeFlags`（运行模式标志），置 `autoEnterShop = true`，toast「登录成功」后 500ms `wx.switchTab` 回首页。
- **状态与边界**：`logging` 防重复提交（按钮置灰）；失败 toast 展示后端 `msg` 或兜底文案；演示模式提示「当前后端未配置商家端微信凭据，登录为演示模式（不产生真实微信身份）」。

## pages/shop/home —— 工作台（四态主面板 + 异常/售后次面板 + 配单上货角标按钮）

- **数据来源**：`onShow` → `shopState.loadShop()`（GET /api/merchant/shop）→ `load()`（GET /api/merchant/stats，返回 `pending/ready_load/delivering/pickup/exception/aftersale/cancel_requests`）→ `loadPendingBatches()`（GET /api/merchant/device/pending 的 `pending_orders` 字段）。`onLoad` 订阅推送，`onUnload` 退订。

- **交互清单**：

| 待取货 | goPickup | — | navigateTo /pages/orders/list?stage=pickup |
| 异常 | goException | — | navigateTo /pages/orders/exception |
| 售后 | goAftersale | — | navigateTo /pages/orders/aftersale |
| 商品管理 | goGoods | — | navigateTo /pages/goods/list |
| 活动管理 | goActivities | — | navigateTo /pages/activity/list |

| 配送监控 | goMonitor | — | navigateTo /pages/delivery/monitor |
| 商铺设置 | goSettings | — | navigateTo /pages/shop/settings |

- **重点链路（工作台四态数字 → /api/merchant/stats）**：`onShow` 每次进入都重拉 `stats`；四个格子角标数字来自 `stats.pending / ready_load / delivering / pickup`，为 0 时加 `zero` 样式置灰弱化；次面板 `stats.exception`（红）、`stats.aftersale`（橙）仅在非 0 时醒目；「取消申请」入口在 `stats.cancel_requests` 非 0 时显示红点；底部圆形按钮角标 `pendingBatchCount` > 0 才渲染。收到推送 `order_created` 时 `load()` + `loadPendingBatches()` 局部刷新，不整页重载。

## pages/orders/list —— 任务页（底部四分类 + 批次分组 + 接单/异常处理）

- **数据来源**：`onLoad` 解析 `?stage=`（直接选中四分类）或 `?tab=`（工作台异常入口的精确状态过滤，写入 `statusFilter`）；`onShow` → `shopState.loadShop()` + `load()` + `loadPendingCount()`；`onLoad` 订阅推送、`onUnload` 退订。

- **交互清单**：

| 按钮/交互 | 触发函数 | 行为与调用的接口 | 后续链路/跳转 |
| --- | --- | --- | --- |
| 底部四分类 | onStage | 切换 `active`（accept/load/deliver/pickup）并清 `statusFilter` 后 `load()` | — |
| 搜索框 | onSearch | 本地过滤（`applyFilter`，匹配订单号/短号/当日序号/点位/收餐人）；兼容原生 input 与 search-box 两种事件形态 | — |

| 关舱 | closeBin | 模拟：直接置 `phase='loaded'`；真实：POST /api/merchant/device/batch/close-bin `{batch_id}`（silent）成功后 | 弹「是否立即配送」（确认关舱后机器人才移动）→ 确认走 `dispatchAll`，否则 `startCountdown(180)` 启动 180s 建议配送倒计时 |
| 圆形「开始配送」 | dispatchAll | 前置校验 `phase === 'loaded'`（舱门开着车不能移动，未关舱 toast「请先关闭舱门后再开始配送」）；模拟：POST /api/merchant/device/batch/mock-dispatch；真实：POST /api/merchant/device/batch/dispatch（silent） | 成功清倒计时、置 `phase='dispatched'`，1.6~2.2s 后 `wx.navigateBack()` 自动返回批次列表 |
| 滑块「开始配送」 | onSliderChange / onSliderEnd | 记录 `sliderX`；松手时拖到底（`sliderAreaW - sliderThumbW - 20`）触发 `dispatchAll`，否则回弹归零 | 同上 |

- **重点链路（开舱/关舱/立即配送 → /api/merchant/device/batch/open-bin|close-bin|dispatch）**：页面按「scanned 可开舱 → open 已开舱 → loaded 已关舱 → dispatched 已派发」四阶段渲染唯一操作按钮。`inferPhase(b)` 由后端批次/任务状态**恢复**操作阶段（修复退出重进后按钮错乱问题）：status 2/3/4 → dispatched（配送中/已完成/已取消，不可再操作）；status 1 优先看后端落库 `ready_dispatch === true`（已关舱 → 直接「立即配送」），否则取各订单 `task.task_status` 最大值：≥50 已上货 → loaded、≥40 上货中 → open、其余 → scanned。模拟/真实分支由登录下发的 `runtimeFlags.device_mock` 决定，取不到默认 false —— 宁可走真实分支报错，也不可假装成功（代码注释 P0-2 修复）。真实代码分支完整保留在方法内（`DEVICE_MOCK=false` 分支），后续直接切换即可。
- **状态与边界**：已派发显示成功态「机器人已出发，将按路线依次配送」后自动返回，无页面内冗余返回按钮；`onHide/onUnload` 清理倒计时定时器（`clearTimer`），`onReady` 按窗口宽度换算滑块尺寸；倒计时归零文案切换为「已超过建议等待时长，请尽快开始配送」；批次加载中显示「加载中…」占位卡。

- **状态与边界**：歇业期间暂停接新单、已接订单正常配送；自动接单开启后扫码将直接接单；退出登录清理彻底，防止共用店员手机时下一位登录者看到上一位商家的营业状态、自动接单开关与配送费。

## 跨页链路小结

- **接单 → 组单 → 上货 → 配送**：任务页/详情页/扫码页 `confirmOrder` 走 POST /api/merchant/order/confirm 并入批次（后端自动派车，一车最多 12 单）→ 工作台/任务页/上货配单页角标红点来自 GET /api/merchant/device/pending 的 `pending_orders` → 上货配单页批次卡 `enterBatch`（组单中先 POST /api/merchant/delivery/batch/dispatch 定型）→ 批次详情开舱/关舱/立即配送（/api/merchant/device/batch/open-bin | close-bin | dispatch，模拟模式走 /api/merchant/device/batch/mock-dispatch）→ 派发完成自动返回批次列表。
- **异常处置**：异常订单在任务页与异常页均可处理 —— POST /api/merchant/order/exception/retry 重新配送（作废旧批次并入新批次）、POST /api/merchant/order/exception/refund 取消并退款（回补库存）；售后与取消申请各自独立处理接口（/api/merchant/refund/handle、/api/merchant/cancel-request/handle）。
- **监控**：配送监控 5 秒轮询 /api/merchant/map + /api/merchant/robots + /api/merchant/device/pending，地图按静态签名增量重绘，机器人概览（电量/状态/位置）与配送中批次分组卡面实时刷新；「本车二维码」→ robotQr 生成 `LD-R:<sn>` 码贴车，与配单上货扫码解析规则闭环。
- **登录态闭环**：登录（/api/auth/login）先验身份再落盘；任何请求遇 401/403 由 `request.js` 统一清登录态回登录页；退出登录显式 `clearLoginState()`（含 `shopInfo` 等缓存）并断开推送 WebSocket，换人登录不串号。
