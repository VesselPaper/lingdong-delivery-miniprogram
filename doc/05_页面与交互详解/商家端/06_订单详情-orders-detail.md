# 订单详情（接单 + 商品明细 + 批次归属）
> 页面路径：pages/orders/detail（商家端小程序）


- **数据来源**：`onLoad` 存 `id`（`?id=`）；`onShow` → `shopState.loadShop()` + `load()` → GET /api/merchant/order/detail?id=。
- **页面构成**：状态头部（浅色卡 + 状态色圆点 + 状态色标题「订单 N · status_text」+ 阶段副文案）；「订单信息」卡（订单编号 / 送达点位 / 收餐人姓名电话 / 备注[有则显] / 下单时间 / 配送批次[短号+完整 batch_no+单数+状态]）；「商品明细」卡（图片 + 名称 + x数量 + ¥价格，底部合计）；「收款信息」卡（应付金额 / 支付方式「微信支付」/ 收款状态[已收款绿·待支付灰] / 未支付时提示由用户端支付后自动更新）；底部操作区。
- **交互清单**：

| 按钮/交互 | 触发函数 | 行为与调用的接口 | 后续链路/跳转 |
| --- | --- | --- | --- |
| 接单并装车 | confirmOrder | 歇业拦截 → 弹窗确认 → POST /api/merchant/order/confirm `{id}` | 成功 toast「已接单，并入批次 N」→ `load()` 刷新 |
| 删除订单 | deleteOrder | 弹窗二次确认（说明会取消订单 / 作废机器人任务 / 回补库存 / 通知用户且不可撤销）→ POST /api/merchant/order/delete `{order_id}` | 成功 toast「订单已删除」→ 700ms 后 `navigateBack()` 回列表（`onShow` 自动重拉） |

- **删除订单（2026-10-07 从管理员网页迁入，店主专属）**：`canDelete = role.isOwner() && [0,1,2,3,6].includes(status)` —— 前端先拦一道，因为后端对店员返 403 而 `request.js` 遇 403 会清登录态并把人踢回登录页，比"看不到按钮"难看得多。可删状态与后端 `ORDER_DELETABLE` 口径一致；**已完成 / 已取消 / 已退款是终态不可删**（重复删会再走一遍库存回补，越补越多）。按钮放在底部操作区、用分隔线与上方操作隔开（`.del-order`），避免挨着「接单并装车」误点；按钮下方给出后果提示 `.del-order-hint`。

- **重点链路**：状态副文案按 `status` 分支 —— 1「请尽快接单，机器人将在门店等待装货」、2「机器人已接单，正在配送」、3「机器人已到达取餐点」、6「配送异常，请在任务页处理」。**取餐超时运营提示**：status=3 且未取时，按 `picking_up_at`（用户正在取餐，舱门已打开）/ `pickup_timeout_stage===1`（取餐超时：先送其他单，稍后返回，再等 15 分钟）/ `pickup_timeout_stage===2`（已返回再等，即将取消退款，请留意）给出不同文案。
- **状态与边界**：**配送中（status≥2）无任何操作按钮** —— 注释明确测试阶段开始配送后模拟约 10 秒送达进入待取货，真实阶段由平台回调推进；接单按钮仅在 `status === 1 && shopOpen` 时显示，歇业时显示「歇业中，暂不可接单」禁用态。
