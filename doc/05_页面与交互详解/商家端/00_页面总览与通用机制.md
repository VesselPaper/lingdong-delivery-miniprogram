### 通用机制（辅助文件）

- **请求封装** `商家端/utils/request.js → request/get/post/put/del`：统一拼接 `config.baseUrl`、注入 `Authorization: Bearer <token>`、15 秒超时（注释明确：监控页每 5 秒一轮，60 秒默认超时会在弱网下堆积悬挂请求）。未登录不发请求直接 `wx.reLaunch` 登录页；`401/403` 时调用 `clearLoginState()` 清登录态并回登录页 —— 403 同等处理，否则非商家账号一旦登录就永久卡在「无权限」且没有路径回登录页。业务失败（`code !== 0`）统一 toast 展示 `msg` 3 秒，`silent` 选项可关闭提示。
- **登录态清理** `商家端/utils/request.js → clearLoginState`：删除缓存键 `token / userInfo / runtimeFlags / shopInfo`，清空 `app.globalData.token/userInfo`，并断开推送 WebSocket（`商家端/utils/push.js → destroy`）。注释明确店员手机常共用，不清干净会让换人登录后的工作台先显示上一位商家的营业状态、自动接单开关与配送费。
- **店铺状态** `商家端/utils/shopState.js`：`loadShop()` 拉取 GET /api/merchant/shop 并缓存到本地 `shopInfo`，失败回退本地缓存；`isOpen/getBusiness/getAutoAccept/getDeliveryFee` 读缓存（配送费非法值回退 1 元）；`setBusiness/setAutoAccept/setDeliveryFee` 写 PUT /api/merchant/shop（配送费限制 0~999 且保留两位小数），请求失败时乐观更新本地缓存保证 UI 不卡死。
- **实时推送** `商家端/utils/push.js`：WebSocket 地址由 `baseUrl` 推导（http→ws、去 `/api` 拼 `/ws`），token 放握手 header。首页/工作台/任务页/上货配单页在 `onLoad` 用 `subscribe` 订阅、`onUnload` 用 `unsubscribe` 退订；收到 `order_created`（新订单）或 `batch_dispatched`（批次自动定型）事件后由页面自行重拉接口做局部刷新。断线指数退避重连（1.5s→15s 封顶），最后一个订阅者离开即断开（避免无人监听时永久重连耗电），登出时 `destroy()` 显式断开并置 `closedByUser`。
- **自定义 tabBar** `商家端/custom-tab-bar/index.js`：仅「首页 / 我的」两个 tab，`wx.switchTab` 切换；首页与「我的」页在 `onShow` 里通过 `getTabBar().setData({ selected })` 同步选中态，`pageLifetimes.show` 与 `attached` 里 `updateSelected` 兜底校正。
- **启动路由** `商家端/app.js → onLaunch`：有 token 时置 `globalData.autoEnterShop = true`（冷启动后首页自动进工作台页，只消费一次）；无 token 直接 `wx.reLaunch` 登录页。

### 状态/样式映射速览（读自真实代码常量）

- **订单状态色板** `商家端/pages/orders/list.js → ST_CLASS`（history/detail/exception/batchDetail 同构）：`0 灰 / 1 橙 / 2 蓝 / 3 绿 / 4 绿 / 5 灰 / 6 红 / 7 灰`；展示文案以 `status_text` 或 `stage_text` 为准（已取订单显示「已取」）。
- **批次状态** `商家端/pages/orders/list.js → BATCH_TEXT/BATCH_TAG`：`0 组单中（灰）/ 1 待上货（橙）/ 2 配送中（蓝）/ 3 已完成（绿）/ 4 异常（红）`；待取货分类下卡片文案强制为「待取货」。
- **角标数字语义**：`pending_orders` / `pendingBatchCount` 均为「组单中 + 待上货批次内订单总数」，不是批次个数；工作台与任务页右上角红点同源（GET /api/merchant/device/pending）。
- **运行模式标志** `runtimeFlags`：登录响应下发 `device_mock`（上货页开舱/关舱/派发走模拟还是真实分支）、`login`（用户端登录按钮是否显示「模拟登录（演示）」；**商家端为账号密码登录，不依赖该标志**）。

## 跨页链路小结

- **接单 → 组单 → 上货 → 配送**：任务页/详情页/扫码页 `confirmOrder` 走 POST /api/merchant/order/confirm 并入批次（组单中，一车最多 12 件；**满容或成立超 90s 后端自动定型**）→ 工作台/任务页/上货配单页角标红点来自 GET /api/merchant/device/pending 的 `pending_orders` → 上货配单页批次卡点击 `goBatchDetail` 纯查看、点「上货」按钮 `enterBatch`（组单中先 POST /api/merchant/delivery/batch/dispatch 即时定型）→ 批次详情开舱/关舱/立即配送（/api/merchant/device/batch/open-bin | close-bin | dispatch，模拟模式走 /api/merchant/device/batch/mock-dispatch）→ 派发完成自动返回批次列表。
- **异常处置**：异常订单在任务页与异常页均可处理 —— POST /api/merchant/order/exception/retry 重新配送（作废旧批次并入新批次）、POST /api/merchant/order/exception/refund 取消并退款（回补库存）；售后与取消申请各自独立处理接口（/api/merchant/refund/handle、/api/merchant/cancel-request/handle）。
- **监控**：配送监控 5 秒轮询 /api/merchant/map + /api/merchant/robots + /api/merchant/device/pending，地图按静态签名增量重绘，机器人概览（电量/状态/位置）与配送中批次分组卡面实时刷新；「本车二维码」→ robotQr 生成 `LD-R:<sn>` 码贴车，与配单上货扫码解析规则闭环。
- **登录态闭环**：登录（/api/auth/login）先验身份再落盘；任何请求遇 401/403 由 `request.js` 统一清登录态回登录页；退出登录显式 `clearLoginState()`（含 `shopInfo` 等缓存）并断开推送 WebSocket，换人登录不串号。
