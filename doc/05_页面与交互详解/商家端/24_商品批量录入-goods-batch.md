# 商品批量录入（Excel 粘贴 / 连续扫码 → 逐条回显结果）
> 页面路径：pages/goods/batch（商家端小程序）　新增于 2026-10-06

**入口**：商品管理（pages/goods/list）统计卡右上角「批量录入」，仅店主可见。

- **数据来源**：`onLoad` 不拉数据；`loadCategories` 不调用（本页分类为自由输入 + 「统一分类」批量填入）。扫码时逐条 GET /api/merchant/goods/by-barcode。
- **页面构成**：顶部两格切换（「从表格粘贴」/「扫码录入」）+ 对应输入面板 + 待录入列表（一行一张卡）+ 底部固定提交区（条码已存在时的处理开关、统一分类、提交按钮）。
- **商品行字段**：商品名称（必填）、条码、售价（必填）、分类、单位、库存（默认 99 填充）。

- **交互清单**：

| 按钮/交互 | 触发函数 | 行为与调用的接口 | 后续链路/跳转 |
| --- | --- | --- | --- |
| 切换输入方式 | onTab | 切 `tab`（paste / scan），列表不随之清空（可贴几次、扫几个攒成一批） | — |
| 粘贴框输入 | onPasteInput | 记 `pasteText` | — |
| 解析成商品列表 | doParse | 本地 `parsePaste` 按行列切分 → `appendRows` → 清空粘贴框 + toast「解析出 N 行（已识别表头）」 | 行进入待录入列表 |
| 扫商品条码 | scanOne | `wx.scanCode` → 拿到条码 → GET /api/merchant/goods/by-barcode `{code}`（silent） | 命中：整行带出名称/分类/单位/售价 + 蓝字「已识别」；未命中：只带条码 + 黄字「请补名称和售价」。已在列表中的条码不重复添加 |
| 行内输入 | onRowField | 按 `data-i` / `data-field` 只更新该格，并清掉该格自己的红字与结果标记（逐字输入不整表重算，避免没输完就飘红） | — |
| 行内失焦 | onRowBlur | `refresh` 整表重算行号与校验 | — |
| 删除某行 | delRow | 从数组移除并重算 | — |
| 清空 | clearAll | `wx.showModal` 二次确认后清空 | — |
| 统一分类 | onBulkCategory / applyBulkCategory | 把输入的分类**只填给还没填分类的行**（不覆盖已填的） | — |
| 条码已存在时 | onIfExists | switch 切换 `if_exists`：跳过（默认）/ 更新 | 决定后端对已存在条码的处理 |
| 提交录入 | submit | 本地校验 → POST /api/merchant/goods/batch `{items, if_exists}` | 见下 |

- **粘贴解析规则（`parsePaste`）**：
  - 分隔符：Excel 复制出来是 Tab；手打常见逗号。**两种都认**（行内含 Tab 就按 Tab 切，否则按逗号切）。
  - 列识别：**优先认表头行**——第一行命中 2 格以上列名，或「每一格都是认识的列名」（照顾单列粘贴，表头只有「名称」一格），且能认得出名称列，就按表头把列对上，**列的先后顺序随便**。认不出表头则按默认列序：名称 → 条码 → 分类 → 单位 → 售价 → 库存。
  - 列名词表：名称/商品名/品名、条码/条形码/编码、分类/类别、单位/主单位、售价/价格/单价/零售价、库存/库存量/数量/存货。
  - 空行丢弃；缺列留空不报错；只有表头没有数据 → 0 行。
  - 为什么按列名认而不是写死位置：每个人复制的列顺序不一定一样，位置写死的话列一换就整批录错，而且错得没有任何提示。

- **本地预校验（`markRows`）与后端同口径**：名称必填、价格 0~9999、同一批里条码不重复（只认第一条，其余提示「条码与第 N 行重复」）。**对不上口径会出现「这里说没问题、提交后又失败」的割裂感**。有条码但无名称的行不登记条码（与后端一致，不误报重复）。

- **提交后**：
  - 逐条结果贴回对应行：新增成功（绿）/ 已更新（蓝）/ 已跳过（黄）/ 失败（红 + 原因）。
  - **只保留失败的行**继续修改——成功的已入库，留着再提交一次会被当「已存在」跳过，反而看不清；全部成功则清空列表并弹「录入完成」汇总。
  - 顶部保留一行「上次提交：新增 X、更新 Y、跳过 Z、失败 N」。
  - 失败行随响应带回原因（如「条码与第 5 行重复」「价格不合法（0~9999）」），商家只改那几行再提交，不必整批重来。

- **权限**：新增商品含定价 → 店主专属。`onLoad` 先 `role.isOwner()` 校验并退回。**必须前置拦**：否则请求拿到 403，而 `request.js` 对 403 会清登录态 + `reLaunch` 到登录页，店员会被直接踢出去，体验更差。

- **状态与边界**：请求封装已统一弹提示，`catch` 内不重复弹；提交中按钮置灰显示「提交中…」；`request.post` 抛错时列表内容不丢，可改完重试。
