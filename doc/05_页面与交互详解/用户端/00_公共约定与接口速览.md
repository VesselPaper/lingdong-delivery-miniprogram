## 公共约定：请求封装要点（承接前文）

页面全部经由 `用户端/utils/request.js` 发请求，与订单/配送相关的行为如下（完整约定见前文文档）：

- **请求入口**：`request.get / post(url, data, options)` → 内部 `request()`。默认 `needAuth = true`：本地无 `token` 时不发请求，直接 `toLogin()` 跳登录页并 reject「请先登录」；有 token 则带 `Authorization: Bearer <token>`。`wx.request` 超时 10 秒。
- **响应判定**：`statusCode === 200 && code === 0` 才 resolve `data`；否则按 `msg` 弹 toast（`options.silent` 传 true 时不弹，专供轮询类请求——配送追踪每 3 秒一次，断网时不能刷屏）；网络层失败非 silent 弹「网络异常」。
- **401/403 清登录态**：收到 401/403 统一执行 `clearLoginState()`（移除 `SESSION_KEYS` 全部 11 个 storage 键：`token`、`userInfo`、`runtimeFlags`、`last_confirm`、`checkout_items`、`user_point`、`search_history`、`order_tab`、`goods_category`、`goods_keyword`、`goods_focus`，并置空 `app.globalData.token / userInfo`）后 `toLogin()` 跳登录页；403 且非 silent 额外弹「无权限」。`toLogin()` 内置 800ms 重入锁，避免并发失败叠出多层登录页。
- **已读机制（清红点）**：我的页红点取自 GET `/api/user/order/badge`；本文订单列表与订单详情页 `onShow` 均会静默调用 POST `/api/user/order/mark-read`，进入即视为已读，清除我的页红点。
- **支付封装**：`用户端/utils/pay.js → payOrder(orderId)`，POST `/api/order/pay`（`{ id }`）；后端返回 `mock: true` 时视为支付成功（演示档不拉起收银台）；否则取 `payParams` 调 `wx.requestPayment`，收银台成功后内部 `pollPaid` 轮询 GET `/api/order/detail?id=` 直到 `status > 0` 确认已收款；用户取消支付时 reject `'cancel'`（各调用方对此静默）。

## 存疑点（以真实代码为准，供后续核对）

1. **`delivery/track` 空态「去下单」按钮失效**：`track.wxml` 空态按钮绑定 `bindtap="goOrder"`，但 `track.js` 未定义 `goOrder` 函数，点击无任何行为（微信小程序对未定义事件处理器仅告警不报错）。推测原意是跳商城/首页下单，需补实现或改绑。
2. **`order/detail` 的 `confirmReceive` 为未绑定保留函数**：`detail.js` 定义了 `confirmReceive`（POST `/api/delivery/confirm`，模拟扫码确认取餐），但 `detail.wxml` 未绑定任何控件；当前已送达态的实际取餐入口是「扫码取餐」按钮跳转 `delivery/scanPickup` 页。
3. **`delivery/track` 与 `delivery/pickup` 已注册但无导航入口**：两页均已在 `app.json` 注册，但全量检索 `用户端/` 的 js/wxml 未发现任何页面跳转进入（仅 track 页内跳转 scanPickup）；`scanPickup.js` 注释写明 pickup 原设计为「订单号直连（列表/详情进入）」，说明入口尚未接通或已改由扫码取餐替代，需确认是否补入口（如订单详情/列表的追踪入口）。
4. **任务描述中的「订单详情同批次一车多单信息」不在详情页**：详情页 wxml 无批次信息卡；同批次信息实际位于 `delivery/track`（`batch` 卡：本车共 N 单 / 已取 X 单）与 `delivery/pickup`、`delivery/scanPickup`（`batch_order_count` 卡），详情页仅展示取餐码与扫码取餐入口。
5. **防重复提交无显式节流**：取消申请/退款提交仅依赖 `wx.showLoading` 提示与后端幂等/状态校验（如取消申请处理中置灰），页面按钮本身未做 disabled 锁定；开舱/关舱同样依赖 loading 提示，快速连点可能并发请求，靠后端校验兜底。
