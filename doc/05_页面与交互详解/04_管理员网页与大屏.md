本部分范围：说明「管理员网页」（调度台）与「可视化大屏」两个展示端的页面结构、交互与数据链路。
管理员网页是登录后可操作的调度后台（导航、表格、机器人操作、构建机制）；可视化大屏是免登录的只读展示页（三栏布局、聚合接口、3D 地图渲染管线）。
文中函数名与接口均以源码实际定义为准，代码定位格式为「文件路径 → 函数名」。

## 管理员网页

管理员网页（调度台）由 `管理员网页/index.html` 定义页面骨架，`管理员网页/admin.js`（构建产物）承载全部交互逻辑，
`管理员网页/admin-map.js`（构建产物）承载总览页校园实时地图。页面采用「登录遮罩 + 左侧导航 + 报头 + 可滚动内容区」的结构，
登录遮罩 `#loginMask` 默认可见，仅在会话有效或登录成功时才隐藏。

### 登录机制（方案 A：账号密码 → session token）

登录采用「管理员账号 + 密码」换取随机 session token 的方案，取代了早期版本的「手工粘贴令牌」。
相关逻辑集中在 `管理员网页/js/parts/admin/06-refresh-token.js`，token 存取与请求封装在 `01-core.js`。

- **登录**：`06-refresh-token.js → adminLogin`
  - 校验账号密码非空（空则提示「请输入账号和密码」），按钮置灰防重复提交；
  - 调用 `api('/login', 'POST', { username, password })`，实际请求 `POST /api/admin/login`
    （后端 `backend/domains/admin/routes.js`，密码以 scrypt 校验，成功后签发随机 session token 并写审计日志）；
  - 返回体 `{ token, admin }`，`admin` 含 `username / nickname / role`；
  - 成功后 `localStorage.setItem(TOKEN_KEY, d.token)` → `hideLogin()` → `renderAccountUI()` → `refresh()` → `connectWS()`。

- **token 存放与携带**
  - `01-core.js` 定义 `TOKEN_KEY = 'lingdong_admin_token'`，登录后写入 `localStorage`；
  - `01-core.js → token()` 读取，`01-core.js → api()` 在每次请求头携带 `x-admin-token`；
  - 后端以 `adminGuard` 中间件统一鉴权，返回 401 即会话失效。

- **401 全局处理**（`01-core.js → api`）
  - 返回 401 且路径不是 `/login` 时：先调用 `onUnauthorized`，再抛出异常；
  - `onUnauthorized` 由 `06-refresh-token.js` 末尾赋值：清空当前管理员并 `showLogin()` 弹登录页；
  - `/login` 自身的 401（密码错误）**不触发**全局会话失效，错误文案直接显示在 `#loginErr`，避免清空用户刚输入的账号密码；
  - 业务码非 0（`j.code !== 0`）同样视为异常抛出，异常对象带 `err.status / err.code / err.message`。

- **hideLogin 时机**（两处）
  - `adminLogin` 成功后调用 `hideLogin()`；
  - 启动时（`07-ops.js` 启动段）：`localStorage` 存在 token → `api('/me')`（`GET /api/admin/me`）校验会话 →
    通过则 `renderAccountUI()` 并显式 `hideLogin()`（否则每次刷新都被登录遮罩挡住）；失败走 `onUnauthorized`；无 token 直接 `showLogin()`。

- **登出**：`06-refresh-token.js → logout`
  - 先 `api('/logout', 'POST')` 让后端吊销当前 session（`POST /api/admin/logout`）；
  - 再清 `localStorage`、置空 `state`、关闭 WebSocket、`showLogin()`，日志记「已退出登录」。

- **修改密码**：`06-refresh-token.js → changePassword`
  - 依次校验「原密码与新密码均填写」「两次新密码一致」「新密码至少 8 位」；
  - 调 `api('/password', 'POST', { old_password, new_password })`（`POST /api/admin/password`）；
  - 后端改密后吊销该账号全部 session，前端提示「密码已修改，请重新登录」并在 800ms 后自动 `logout`。

- **登录限流**：后端按「账号 + IP」计数，连续失败超过 `ADMIN_LOGIN_MAX`（默认 5）次锁定 `ADMIN_LOGIN_WINDOW_MS`（默认 10 分钟），
  锁定期间返回 429「尝试次数过多，请 10 分钟后再试」。

  - `02-nav.js → wireSearch`：`#tasksSearch / #historySearch` 160ms 防抖，写入 `searchQ`；
  - `maybeAutoExpandByOrderNo`：按订单号搜到批次时自动展开对应批次；
  - `fillStatusOptions`：按实体类型（exec / batch / order / task）填充状态下拉，`tasksKind / historyKind` 做标签 → 类型映射。

- **多选与批量**（`03-select.js`）
  - 多选集合 `sel = { order, batch, task, plat }`；`updateSelUI` 同步行高亮、已选计数与批量按钮显隐；
  - `toggleSel / toggleSelAll / clearSel` 为行内 / 全选 / 清空入口；

- **数据接口与刷新**
  - `06-refresh-token.js → refresh` 一次性拉 `GET /api/admin/state`（`service.js → buildAdminState` 聚合设备、平台任务、
    本地批次/订单/任务、死锁与异常告警），写入闭包变量 `state`，`busy` 标志防重入，`#conn` 显示 `server_time`；
  - `04-overview-ws.js → render` 分发渲染：`renderOverview / renderTasksPage / renderHistoryPage / renderNavCount`；
  - 批次展开懒加载 `GET /api/admin/batch/orders?batch_id=`（`03-select.js → toggleExpand`，缓存于 `batchOrdersCache`）。

- **WebSocket 实时层**（`04-overview-ws.js`，事件驱动、前端不轮询）
  - 连接地址 `wsURL()`：`ws(s)://host/ws?token=..&src=admin`，`connectWS` 建立连接后订阅主题 `admin/live`；
  - `live` 事件：`m.robot` 原地刷新机器人卡片（`renderRobotCard`，不整页重绘），`m.robots` 交给 `window.mapOnLive` 更新地图小车；
  - `state_changed` 事件：触发一次 `refresh()`；
  - 断线 4 秒重连（`scheduleReconnect`）；`07-ops.js` 启动段另有 20 秒一次的健康探查，只重连不拉数据。

### 总览页校园实时地图（admin-map.js）

总览「机器人」标签右侧是 Leaflet 实时地图，由 `管理员网页/js/parts/map/*.js` 五片实现（与 admin.js 同构的 IIFE 分片）：

- **坐标系**（`01-init.js`）：Leaflet `CRS.Simple` 像素坐标，平台雷达地图 PNG 为唯一底图；按平台 map 元数据
  `{ width, height, resolution, origin }` 做像素级对齐，`toPixel` 把世界坐标（米）线性映射为图像像素（y 翻转），
  点位 / 路网 / 无人车 / 配送站位与雷达图严格对齐，不再用 bbox 外包框或经纬度近似；
- **底图**：`/api/dashboard/map-image`（与可视化大屏同一后端代理地址）；首次 `fitBounds` 显示全图并把最小缩放锁为全图大小（`applyRadar`）；
- **静态层**（`02-static.js`）：`updateLandmarks` 按类型分色渲染平台点位——取货点蓝 `#1d5bd6`、上货点橙 `#e8890c`、
  充电点绿 `#2f9e44`、巡逻点紫（circleMarker + 悬停泡泡），名字文字常驻可见；`usableLandmarks` 剔除名为「固定路径」的噪音点位；
  `updateRoutes` 把配送站位按停靠顺序画成编号钉（`stopSvg`）；
- **车辆层**（`03-cars.js`）：`updateCars` 按 `device_sn` 复用标记，SVG 铲形俯视车图标 + 车名（尾 6 位），车头随航向
  `deg = HEADING_OFFSET - θ` 旋转；`applyRouteFocus` 与 `highlightBatchDetail / clearBatchFocus` 实现批次聚焦
  （目标批次站位高亮、其余降透明，并 fitBounds 定位）；
- **渲染与拉取**（`04-render.js`）：`poll` 拉 `GET /api/admin/map`（adminGuard 鉴权，服务端 3 秒缓存）→ `renderMap`
  （写 `META`、铺雷达图、更新静态层与车辆、刷新底栏 `#mapFoot` 统计）；`setMask` 控制加载/失败遮罩；
- **实时层**（`05-live.js`）：`window.mapOnLive` 由 admin.js 的 WS live 事件调用，原地只更新小车与实时心跳底栏
  （`#mapFoot` 显示各车坐标与时间戳），不整体重拉；`trackCar` 记录每台车最近 80 个位置画绿色虚线轨迹；
  `ensureFollowBtn` 提供「跟随小车」按钮（约 12m×12m 视野 + 边沿跟随，小车驶出中部 33% 安全区才平移追过去）；
  `invalidateAdminMap` 在标签切回时刷新尺寸；`reloadAdminMap`（= poll）在 WS 重连/初次加载时拉一次完整地图；
  `adminMapDebug` 为排障钩子；「回到校园」按钮 `#mapResetBtn` 复位到全图。

### 交互清单（按钮 → 函数 → 接口 → 刷新）

所有写操作统一走后端「统一落账」（作废任务 + 回补库存 + 摘批次 + 平台召回关任务），保证机器人状态、用户端、商家端同步。
通用执行器为 `07-ops.js → run / confirmRun`：先 log，成功即 toast + `refresh()` 重新拉全量；失败走 `03-select.js → opFail`
（401 转认证横幅 `setAuthBanner`，其余 toast + log）。危险操作均经 `window.confirm` 二次确认。

| 操作 | 触发 | 函数（文件） | 接口（均 `/api/admin` 前缀） |
|---|---|---|---|
| 召唤机器人 | 总览·机器人卡 | `07-ops.js → actSummon` | `GET /robot/summon-targets` 取上货/充电/取货点 → `openPickModal` 弹窗选择 → `POST /robot/summon { device_sn, landmark_id }`（会中断正在执行的配送任务） |
| 开关舱门 | 总览·机器人卡 | `actDrawerPick` | 弹窗选开/关舱 → `POST /drawer { device_sn, cmd }`（drawerCtrl 独立控制，不影响任务状态） |
| 停止（驻停） | 总览·机器人卡 | `actStop` | `POST /robot/stop { device_sn, stop_time: 30 }`，原地驻停 30 秒后自动恢复 |
| 继续工作 | 总览·机器人卡 | `actRecover` | `POST /robot/recover { device_sn }`，恢复其任务执行 |
| 停止并取消任务 | 总览·机器人卡 | `actStopCancel` | `POST /robot/stop-cancel { device_sn }`（先关活跃任务再驻停，舱内有货自动开舱，不可撤销） |
| 删除订单 | 行内 / 右键 / 批量 | `actCancelOrder` / `runBulkOrder` | `POST /order/cancel { order_id }`；批量 `POST /orders/bulk-cancel { order_ids }`（逐单容错，返回 cancelled/failed） |
| 清理批次 | 行内 / 右键 / 批量 | `actCancelBatch` / `runBulkBatch` | `POST /batch/cancel { batch_id }`；批量 `POST /batches/bulk-cancel { batch_ids }`（删批内活跃订单 + 释放控制权 + 批次置 4） |
| 关闭并作废任务 | 行内 / 右键 / 批量 | `actCloseVoid` / `runBulkTask` | `POST /task/close-void { task_id }`；批量 `POST /tasks/bulk-close-void { task_ids }` |
| 仅作废本地任务 | 右键菜单 | `actVoid` | `POST /task/void { task_id }`（本地任务置 110 + void_at） |
| 取消/关闭平台任务 | 平台任务表 | `actCancel` / `actClose` | `POST /task/cancel { platform_task_id }`；`POST /task/close { device_sn, platform_task_id }`（缺设备编号时取 `state.robot.device_sn`） |
| 批次内订单展开 | 展开箭头 / 搜索自动 | `toggleExpand` / `maybeAutoExpandByOrderNo` | `GET /batch/orders?batch_id=`（懒加载并缓存） |
| 复制编号 | 右键菜单 | `copyText` / `fallbackCopy` | 纯前端（clipboard API → execCommand 兜底） |
| 获取/释放控制权 | 设置·控制权与点位 | `actGrant` / `actRelease` | `POST /control/grant { device_sn }`（600 秒）；`POST /control/release { device_sn, ctrl_id }` |
| 同步点位 | 设置·控制权与点位 | `actSyncLm` | `POST /landmarks/sync`（平台 landmarks 拉到本地库） |
| 一键初始化状态 | 设置·危险操作 | `#reset` onclick（07-ops.js） | `POST /reset`：关全部平台活跃任务 + 释放全部控制权 + 删除全部活跃订单 + 批次全部置 4 |
| 手动刷新 | 报头「刷新」按钮 | `refresh`（06-refresh-token.js） | 重新拉 `GET /state` |

补充说明：

- 右键菜单（`showCtx / hideCtx`）统一由 `03-select.js` 实现，按实体挂接 `ctxOrder / ctxBatch / ctxTask / ctxPlat`，
  菜单项含「复制编号」及条件出现的危险操作；窗口外点击 / Esc / 失焦自动关闭；
- 批次展开行由 `expandRow` 生成内嵌迷你表（短号 / 订单号 / 状态 / 商品 / 点位 / 金额 / 取餐码 / 创建时间）；
- `07-ops.js → actDelPre` 定义了「删除预创建任务」（`POST /precreate/del`），但当前 index.html 未绑定对应按钮（见存疑点）；
- 所有单行 / 批量操作完成后均通过 `run()` 内部统一 `refresh()` 刷新，实时数据另由 WS `state_changed` 事件驱动。

### 构建机制（build.js 分片拼接）

`管理员网页/build.js` 是「拆分式构建」脚本，把按数据域拆散的小文件拼成两个浏览器直接引用的产物。

- **TARGETS 清单**（顺序即拼接顺序）

| 输出文件 | parts 清单 | 内容划分 |
|---|---|---|
| `admin.js` | `01-core → 07-ops` 共 7 片 | 头部 IIFE/常量/工具（`esc / log / toast / api / 状态字典`）→ 导航 → 选择与批量 → 总览与 WS → 表格渲染 → 刷新与认证 → 操作与启动 |
| `admin-map.js` | `map/01-init → 05-live` 共 5 片 | 地图初始化（元数据/坐标映射/雷达底图）→ 静态点位与配送站位 → 无人车图层 → 渲染与拉取 → 实时层 |

- **为什么 parts 不能单独运行**
  - 每个 parts 文件只是同一个 IIFE 闭包里的「一段」：`01-core.js` 开头是 `(function () { 'use strict' …` 与闭包共享变量
    （`state / sel / expandedSet / batchOrdersCache / statusFilter / searchQ / busy / onUnauthorized / TOKEN_KEY`），
    `07-ops.js` 末尾才是启动逻辑与 `})()` 收尾；
  - 中间片段无导出、无独立入口，且互相交叉引用：`02-nav.js` 用 `api / state / expandedSet`；
    `03-select.js` 调 `refresh / renderTasksPage`（分别定义于 06、05 片）；`04-overview-ws.js` 调 `renderTasksPage / renderHistoryPage`；
    `06-refresh-token.js` 给 `01-core.js` 声明的 `onUnauthorized` 赋值；`07-ops.js` 使用上述全部片段中的函数与变量；
  - 单独加载任何一个片段都会因引用未定义变量抛 ReferenceError；只有 `01-core.js` 的 IIFE 头与 `07-ops.js` 的 IIFE 尾合起来才构成完整脚本。

- **CUTS 常量作用**
  - `CUTS` 记录每个输出文件各 parts 片段的「末行号」（1-based）；
  - 正向构建 `node build.js` 按 TARGETS 顺序拼接，不依赖 CUTS；
  - `node build.js --gen` 按 CUTS 边界把输出文件重新切回 parts（逐字节等价），供首次生成或直接改了产物后回拆使用；
  - 日常约定：只改 `js/parts/` 下的源文件，改完执行 `node build.js` 重新拼接。

## 可视化大屏

可视化大屏（`可视化大屏/index.html` + `可视化大屏/js/*`）是一块 7×24 常挂的只读调度看板，由后端同端口托管（见「刷新与部署」），
无登录、无写操作。页面无任何第三方图表库，所有图形均为原生 HTML/CSS/SVG 与 Canvas/WebGL。

### 布局（左中右三栏，固定 1920×1080 画布）

保证 1080p / 2K / 4K 版式一致。结构自上而下：顶栏、主体栅格、底栏（「每 5 秒刷新 · 每日 04:00 自动重载」）。

- **顶栏**：品牌 logo + 店名与校区 `#subTitle`、运行档位 `#kvMode` 与平台 `#kvPlatform`、大屏标题、演示标识 `#demoBadge`、
  连接状态 `#conn`（`setConn` 切换 ok/bad）、时钟 `#clock`（`tickClock` 每秒刷新）。

- **左栏 `#colLeft`**
  - 运行状态面板：店铺 `#kvShop`、营业状态 `#kvBusiness`（营业中/休息中）、自动接单 `#kvAuto`（已开启/已关闭），

  - 车辆状态面板：车辆清单 `#robotList`（名称、电量条与百分比、机器状态，`renderRobots`，最多 `MAX_ROBOTS=6` 台，
    `statusClass` 映射空闲/忙/充电/异常配色）+ 任务状态标签组（静态展示：空闲待命 / 配送执行中 / 返回门店 / 充电中）；
  - 无人机器车展示区：robot.png 正/背/侧三帧旋转展示，纯装饰。

- **中栏 `#mapCard`**
  - 地图主体 `#mapBox`（Canvas/WebGL 渲染）+ 加载遮罩 `#mapMask` + 状态提示 `#mapTip`；

  - 订单配送看板：统计卡 `#mToday / #mDelivering / #mPickup / #mPending`（`renderStats`，`paintMetric` 让 0 值弱色化）；
    副行 `#mAmount / #mLoad / #mException / #mAftersale / #mCancelReq`；状态分布堆叠条 `renderStatusBar`（纯 CSS 百分比条）；

### 数据源（只读聚合接口）

大屏只调后端只读聚合接口，全部免登录（不经 `adminGuard`），路由与字段在 `backend/domains/admin/routes.js` 与
`service.js → buildDashboard` 中确认。

| 接口 | 说明 |
|---|---|
| `GET /api/dashboard/overview` | 主聚合（`DASHBOARD_CACHE_MS` 默认 5 秒缓存）。返回 `server_time / run_mode / real_platform / shop / stats / map / map_error / robots / robots_error / batches / pickup_alerts` |
| `GET /api/dashboard/map-image` | 雷达底图代理（`DASHBOARD_MAP_CACHE_MS` 默认 10 分钟缓存）。平台底图是 OSS 签名直链、几十秒过期，直接给浏览器会间歇性 403 白图，故由后端取字节缓存 |
| `GET /api/config/tianditu` | 天地图浏览器端密钥注入（`backend/.env` 的 `TIANDITU_TK`，不入仓库）；仅 Leaflet 回退底图路径使用 |
| `GET /api/dashboard/robot-positions` | `dashboard.js` 以 1 秒间隔高频轮询的车辆位置轻量接口。**后端当前未注册该路由**，轮询静默失败，车辆实时移动实际依赖 overview 每 5 秒下发的 `map.robots`（见存疑点） |

`overview` 关键字段：

| 字段 | 内容 | 后端来源 |
|---|---|---|
| `map` | `{ map_url, barrier_url, bbox, landmarks, graph, robots, routes }` | 平台 `getMapOverview()` |

| `robots / robots_error` | 车辆列表（在线/电量/机器状态） | 平台 `getDeviceList()`，失败降级为空数组 + 错误文案 |
| `batches` | 进行中批次概览（含 `daily_seq / active_orders / waiting_pickup`） | `delivery_batches` 表 |
| `pickup_alerts` | 取餐超时告警（含 `pickup_timeout_stage`） | `orders` 表 |
| `shop / run_mode / real_platform` | 店铺状态、运行档位、是否真实平台 | `shops` 表 + `services/runtime` |

`stats` 字段口径（order 域 `computeStats`）：

| 字段 | 含义 | 对应大屏元素 |
|---|---|---|
| `today_orders` | 今日订单数 | `#mToday` |
| `today_amount` | 今日营业额 | `#mAmount` |
| `pending` | 待接单 | `#mPending`（0 值弱色） |
| `ready_load` | 待上货 | `#mLoad` |
| `delivering` | 配送中 | `#mDelivering` |
| `pickup` | 待取货 | `#mPickup` |

| `cancel_requests` | 取消申请 | `#mCancelReq` |

取数逻辑（`dashboard.js`）：

- `loop()` 每 `POLL_MS`（5000ms）调 `fetchOverview`（带 `FETCH_TIMEOUT=8000ms` AbortController 超时），成功后 `apply`
  分发到各渲染函数（`renderRunState / renderStats / renderStatusBar / renderRobots / renderBatches / renderAlerts / renderMap / diffEvents`）；
  失败保留上一屏内容、仅在右上角标「连接中断」——大屏最忌讳黑屏；
- `pollRobots()` 按 `ROBOT_POLL_MS`（1000ms）单独高频轮询车辆位置，只喂 3D 地图（`Map3D.setRobots`）；只把「有有效坐标」的车交给地图；
- 演示模式：地址栏加 `?demo=1`，`demoPatch` 用真实地图与点位叠加模拟车辆往返（`LD-DEMO-01/02`）、生成演示路线与统计，
  顶部亮「演示数据」标识避免与真实数据混淆；
- 标定模式：`?calib=1` 走 `calibPanel / renderCalib`，把红色点位逐一拖到真实位置（至少 3 个、建议 4~6 个），
  `solveSimilarity`（高斯消元解相似变换最小二乘）输出新标定参数写回代码。

### Leaflet 回退路径与底图源（dashboard.js）

`renderMap` 的渲染优先级为：`window.Map3D`（立体地图）→ `window.RadarMap`（雷达图层回退）→ `initMap`（Leaflet 在线地图）。
Leaflet 路径保留在 `dashboard.js` 中（`initMap / updateLandmarks / updateGraph / updateRoutes / updateCars / platformToLngLat`），
当前仅在 Map3D 组件缺失时启用：

- **底图源**：`TILE_PROVIDER` 常量默认 `'tianditu'`（天地图 WMTS，矢量底图 `vec` + 中文注记 `cva` 双层，`maxNativeZoom=18`、
  `maxZoom=20`，tk 由 `getTiandituTk` 从 `/api/config/tianditu` 注入）；备选 `carto / osm / osm-de / amap-vector / amap-sat`，
  改一处即可切换；非天地图源走「OSM 德国镜像 → 高德矢量」的防抖降级链（只有从未成功且连续失败 ≥3 次才换源，`tileload` 成功即锁定）；
- **坐标变换**：`CALIB_T = { a, b, tx, ty }` 相似变换把平台局部坐标（米）→ WebMercator 米 → WGS84 经纬度
  （`platformToLngLat`，`?calib=1` 标定模式可重新拟合出该参数）；车辆朝向 `HEADING_OFFSET = 90`（箭头默认朝上 → 东为 90°）；
- **图层**：点位 `updateLandmarks`（上货点橙、其余荧光绿 circleMarker）、路网 `updateGraph`（青色发光 polyline）、
  路线 `updateRoutes`（青色虚线 + 停靠序号 divIcon）、车辆 `updateCars`（蓝色箭头 + 尾号，按 `device_sn` 复用）。

### 3D 地图（map3d 系列模块职责）

中栏地图由 `map3d-entry.js` 统一入口 `window.Map3D` 分发到「真 3D / 2.5D 回退」两套渲染器，
`dashboard.js → renderMap` 只依赖 `Map3D.ensure / update / setRobots` 等门面方法。

| 模块 | 职责 | 关键函数 |
|---|---|---|
| `可视化大屏/js/map3d-entry.js` | 渲染器门面：`pick()` 探测 WebGL（`Map3DGL.probe()`）决定模式 `gl / flat`；WebGL 初始化失败时 `degradeIfNeeded()` 现场降级 2.5D，不黑屏，`#mapTip` 写明当前模式 | `ensure / update / resetView / setOpts / getOpts / setRobots / mode` |
| `可视化大屏/js/map3d-gl.js` | 真三维 WebGL 渲染器 `window.Map3DGL`（默认主力）：场景网格与相机数学复用 `scene3d.js`，地面贴 `assets/radar-ground-dark.png`；鼠标拖拽平移、滚轮缩放、双击复位、触屏手势 | `probe / hasFailed / ensure / update / resetView / setRobots / setOpts / getOpts` |
| `可视化大屏/js/map3d.js` | 2.5D 斜轴测 Canvas 回退 `window.Map3DFlat`：静态层画到离屏画布（`buildStatic`，仅参数变化时重绘），每帧 `frame` 只画动态层（车辆逐帧插值、路线流动虚线、配送点呼吸圈）；无实时数据时 `initDemo / demoCarsPos` 让演示车沿骨架路线跑 | `ensure / update / setRobots / resetView / bindControls / bindInteractions` |
| `可视化大屏/js/map3d-core.js` | 几何/投影/场景核心 `window.Map3DCore`（浏览器与 Node 预览共用同一套代码）：斜轴测投影（旋转摆正 → 俯仰压扁 → 高度偏移），`buildScene` 生成按深度排序的绘制项，`deconflict` 标签贪心避让 | `makeView / project / unproject / groundAffine / makePlatformToRadar / buildScene / carGeometry` |
| `可视化大屏/js/scene3d.js` | 真三维场景构建 `window.Scene3D`（供 GL 渲染器）：自带 mat4 矩阵、耳切三角化、网格累加器、车辆/光环/光柱网格、校园道路拓扑网与贴路寻路（`buildRoadGraph / routeOnRoads / simplifyPath`）、建筑「让路」逻辑、相机与取景（`makeCamera / fitCamera`）、光照（`shade`） | `buildStatic / buildCar / buildRouteMesh / demoRoutePaths / principalAzimuth` |

数据分层与交互：

- **静态数据**：来自 `assets/map-calibration.js`（以 `<script>` 引入 `window.MAP_CALIBRATION`，file:// 双击也能读；
  `map3d.js` 另有 XHR 读 `map-calibration.json` 的兜底）——含楼栋轮廓 `ring` 与米高 `height_m`（× `scale_px_per_m` 换算像素）、
  校园道路 `roads`（main/walk 分级）、雷达可通行骨架 `paths`；地面贴图 `assets/radar-ground.png`（2.5D）与 `radar-ground-dark.png`（GL）；
- **动态数据**：来自 overview 的 `map.bbox / map.landmarks / map.robots / map.routes`，平台坐标经 `makePlatformToRadar`
  （bbox 归一化 + y 翻转）换算到雷达底图像素系（x 右、y 下），再进入投影管线；
- **视角交互**：`#m3Tilt`（俯仰 3~88°，越大越接近垂直俯视）、`#m3Height`（楼高夸张 20~200，压低可减少遮挡）；
  `#m3Spin` 自动环绕、`#m3Follow` 镜头跟随第一台车、`#m3Fade` 楼体半透明（俯视时看清被楼压住的道路）、
  `#m3Path` 显示测绘骨架线（青色荧光，默认关）、`#m3Route` 显示橙色规划/实时路线（默认关）、
  `#m3Road` 校园道路（默认开）、`#m3Label` 楼栋标注（默认开）；
  画布内滚轮缩放、拖拽平移/旋转、双击复位，面板头 `#mapReset` 回到校园；
- **测绘线语义**：`paths` 是「测绘出的可通行骨架线」（机器人实际行驶路径，源自雷达走廊），2.5D 版用「柔光 → 白壳 → 蓝芯」三层描画，
  GL 版用外发光扁带 + 亮芯线，与平台下发的橙色规划路线（`routes`）区分。

### 刷新与部署

- **轮询间隔**：主聚合 `POLL_MS = 5000`ms（overview，后端另有 5 秒缓存）；车辆位置 `ROBOT_POLL_MS = 1000`ms；
  时钟 1 秒；`memoryGuard` 与 `dailyReload` 各 60 秒检查。
- **免登录只读**：所有 `/api/dashboard/*` 接口不经 `adminGuard`，页面不含任何写操作按钮，适合挂在走廊/门店大屏上常显。
- **长跑稳定性**（`dashboard.js` 头部注释与实现）

| 措施 | 说明 |
|---|---|
| 固定 DOM | 所有列表「复用节点 + 改文本」（`renderRobots / renderBatches / renderAlerts / diffEvents` 先补齐节点再改内容），绝不无限 append |
| 无图表库 | 状态分布是纯 CSS 堆叠条（`renderStatusBar`），不初始化/常驻任何图表实例 |
| 静态层不重绘 | 只在底图或数据签名变化时重画；车辆节点按 `device_sn` 复用、位移走 `transform`（只走合成层） |
| 每日重载 | `RELOAD_HOUR = 4` 点整页 `location.reload()` 释放累积渲染状态 |
| 内存兜底 | 堆内存超 `MEM_LIMIT = 800MB` 主动重载（Chrome 专有 `performance.memory`，取不到则跳过） |
| 断连不黑屏 | 取数失败保留上一屏内容，只在右上角标「连接中断」 |

- **部署方式**：后端同端口三服务——`backend/server.js` 用 `express.static` 托管 `/admin`（管理员网页）与 `/dashboard`（大屏），
  根路径 `/` 301 到 `/admin/`；`/dashboard` 无斜杠访问会 301 到 `/dashboard/`（index.html 用相对路径，必须带斜杠；
  后端不自建 `/dashboard` 路由，避免与斜杠版互相重定向成死循环）。
  大屏主机浏览器打开 `http://<后端IP>:3000/dashboard/` 即可全屏展示，另有 `deploy/看门狗.ps1`（每 60 秒检查后端与大屏进程，
  异常自动拉起）与 `deploy/安装开机自启.ps1`（注册登录自启计划任务）。双击 `index.html`（file://）时
