# 04 · 数据库设计

最后更新：2026-09-04
数据库：SQLite（backend/data/lingdong.db，node:sqlite）。建表与种子见 backend/db.js。

## 表关系总览

```
users 1 ──── n addresses
users 1 ──── n cart ──── n→1 goods
users 1 ──── n orders 1 ──── n order_items
orders n ──── 1 delivery_batches 1 ──── n orders   （一车多单：一个配送批次含最多 12 单）
orders 1 ──── 1 delivery_tasks（每单一个平台任务，同批次任务共用同一机器人/货仓）
landmarks 1 ──── n addresses / n orders（landmark_id 关联点位）
shops（单门店，id=1）
activities（独立）
```

## 关键索引与约束

- users.openid 唯一
- orders.order_no 唯一

## 迁移说明（backend/db.js migrate）

- landmarks 表自动补 platform_building_id / platform_map_id / platform_landmark_id / pos_x / pos_y 列。
- orders 表自动补 batch_id / picked_up_at 列；delivery_tasks 补 batch_id 列；users 补 order_read_at 列。
- 历史 addresses 的 landmark_id 若存成 "2.0" 会自动规范化为 "2"。
- 2026-09：landmarks 种子改为正式环境真实点位（川师成龙校区：商铺上货 + 东苑1~13栋，含平台映射）；新增 delivery_batches 表（一车多单）。

## 环境变量（backend/.env / .env.example）

- `LINGDONG_DB`：数据库路径覆盖（多实例/测试隔离）。
- `BATCH_MAX_ORDERS`：一车最多单数（默认 12）。
- `BATCH_WAIT_MS`：自动接单模式下批次等待派车时长（默认 90s）。
- `BATCH_SCAN_MS`：自动派车扫描间隔（默认 15s）。
