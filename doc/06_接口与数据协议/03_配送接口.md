# 06 · 接口与数据协议 · 03 配送接口

### 2.4 delivery 域（`domains/delivery/routes.js`）：点位 / 配送追踪 / 用户取餐 / 批次设备 / 平台回调

| 方法 | 路径 | 鉴权 | 说明 | 关键出入参 |
| --- | --- | --- | --- | --- |
| GET | `/landmarks` | 无 | 点位列表（匿名裁剪 `platform_*` 字段；登录态返回全字段） | 出：landmark 数组 |
| GET | `/delivery/track` | 用户 | 配送追踪（详见 3.10） | Query `order_id`；出 `{order_status, order_status_text, pickup_code, landmark_name, task, task_text, position, percent, map, batch}` |
| POST | `/delivery/confirm` | 用户 | 确认收货（订单→4 + 结算销量；scan_code 与取餐码比对） | 入 `{order_id, scan_code?}` |
| POST | `/delivery/pickup-scan` | 用户 | 扫码进入取餐页（返回取餐上下文），`service.pickupContext` | 入 `{order_id}`；出 取餐上下文 |
| POST | `/delivery/pickup-by-code` | 用户 | 扫码+输取餐码校验（归属/待取/码匹配/车一致） | 入 `{device_sn, pickup_code}`；出 取餐上下文 |
| POST | `/delivery/pickup-by-scan` | 用户 | 扫码自动匹配本人在该车的待取订单（免输码） | 入 `{device_sn}`；出 `{auto_matched:true,…}` 或 `{auto_matched:false}` |
| POST | `/delivery/pickup-open` | 用户 | 取餐开舱（详见 3.7） | 入 `{order_id}`；出 `{order_id, status, opened_at, test?/summon?}` |
| POST | `/delivery/pickup-close` | 用户 | 取餐关舱（详见 3.8） | 入 `{order_id}`；出 `{order_id, status:4, test?/summon?}` |
| POST | `/delivery/pickup-close-all` | 用户 | 同点多单一起取：一次关舱确认本批次本点位全部待取订单 | 入 `{batch_id, landmark_id?}`；出 `{batch_id, landmark_id, count}` |
| GET | `/merchant/delivery/batch/list` | 商家 | 批次列表（近 20 个，含 orders/route），`queries.recentBatches + batch.getBatchDetail` | 出：批次数组 |
| GET | `/merchant/delivery/batch/detail` | 商家 | 批次详情（详见 3.9），`batch.getBatchDetail` | Query `batch_id`；404 批次不存在 |
| POST | `/merchant/delivery/batch/dispatch` | 商家 | 批次派车（详见 3.4），`service.doDispatchBatch` | 入 `{batch_id, device_sn?}`；出 批次详情 |
| POST | `/merchant/device/batch/open-bin` | 商家 | 批次开舱上货（详见 3.5） | 入 `{batch_id}`；出 `{batch_id, opened}` 或 `{waiting:true}`（召唤模式车未到） |
| POST | `/merchant/device/batch/close-bin` | 商家 | 批次关舱等待（不派发；落 `loaded_at`） | 入 `{batch_id}` |
| POST | `/merchant/device/batch/dispatch` | 商家 | 批次开始配送（详见 3.6） | 入 `{batch_id}`；出 `{batch_id, dispatched}` 或 `{summoned:true, detail}` |
| POST | `/merchant/device/batch/mock-dispatch` | 商家 | 模拟开始配送（仅测试档；`MOCK_ARRIVE_MS` 后自动送达） | 入 `{batch_id}`；出 `{batch_id, status:2, msg}` |
| GET | `/merchant/robots` | 商家 | 机器人设备列表（平台 runtimeStatusList） | 出：robots 数组；502 平台失败 |
| GET | `/merchant/delivery/monitor` | 商家 | 配送监控（未完成任务 + 实时位置） | 出：任务数组（含 position） |
| GET | `/merchant/map` | 商家 | 配送监控真实地图（底图/路网/点位/机器人/路线），`platform.getMapOverview` | 出 `{map_url, barrier_url, bbox, landmarks, graph, robots, routes}` |
| POST | `/merchant/landmarks/sync` | 商家 | 平台点位同步（幂等 upsert），`platform.syncLandmarks` | 出 `{ok, buildingId, buildingName, count, inserted, updated, removed}` |
| POST | `/merchant/delivery/test-complete` | 商家 | 测试完成配送（仅测试档；按 order_id 或 batch_id 置 3/4） | 入 `{order_id?/batch_id?, status=3}` |
| GET | `/merchant/device/pending` | 商家 | 待上货/组单批次列表（配单页主入口；含 `robot_available` 占用标注） | 出 `{open_batches, ready_batches, active_batches, pending_orders}` |
| POST | `/merchant/device/scan` | 商家 | 扫码识别机器人→定位待上货批次（详见 3.4A） | 入 `{deviceSn}`；出 批次+全部订单+`control_ok`+`at_loading_point` |
| POST | `/merchant/device/open-bin` | 商家 | 单任务开舱（验证通过自动开舱） | 入 任务定位参数；出 ok/502 |
| POST | `/merchant/device/close-bin` | 商家 | 单任务关舱（等待不派发） | 入 任务定位参数 |
| POST | `/merchant/device/dispatch` | 商家 | 单任务开始配送（确认上货） | 入 任务定位参数 |
| POST | `/platform/callback/delivery` | 无 | 配送任务状态回调（`service.handleDeliveryCallback`；token 防伪） | 出 `{code:"SUCCESS"}` |
| POST | `/platform/cb/:token/delivery` | 无 | 同上（令牌走路径段形态） | 出同上 |
| GET/POST | `/platform/check-order` | 无 | 业务订单状态校验（`service.handleCheckOrder`） | Query/body `orderNo`；出 `{code:"COMM_200", data:null}` 或强制关任务事件 |
| GET/POST | `/platform/cb/:token/check-order` | 无 | 同上（令牌走路径段形态） | 出同上 |
| POST | `/platform/callback/exception` | 无 | 设备异常上报（T/R/I/N 类，仅记日志） | 出 `{code:"SUCCESS"}` |
| POST | `/platform/cb/:token/exception` | 无 | 同上（令牌走路径段形态） | 出同上 |

> 配送异常订单的**处理**接口（retry/refund/列表）定义于 order 域（`/merchant/order/exception/*`，见 2.3）；
> 异常**产生**由 delivery 域定时器扫描（`delivery/timers.js`，超时未接单→状态 6）。
