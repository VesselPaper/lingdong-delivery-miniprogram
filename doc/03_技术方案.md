## 1. 项目架构

```
用户端小程序 ──┐                    ┌── 开放物流平台（robox，正式环境）
商家端小程序 ──┤   HTTP / JSON       │   排队任务/状态/位置/点位
              ├── 自建后端 ──────────┤
              │  (Node/Express/     └   微信服务器（code2session、支付回调）
              │   SQLite, 端口3000)
              └──
```

- 小程序端：微信原生，UI 自绘（仅用 tdesign-miniprogram 的 icon 图标组件）。
- 后端：Node.js + Express + node:sqlite（零外部数据库服务），位于 backend/。
- 数据源：商品/订单/用户/地址/活动/店铺在本地 SQLite；机器人设备、点位、配送任务对接到开放物流平台。
- 安全边界：小程序端不存放开放物流平台凭据与微信支付商户凭据，全部只在后端 .env。

## 1.1 一车多单（配送批次）架构

现实模型：无人车单仓可放多份商品（一车最多 12 件）。设计为「配送批次」模型，**批次容量以商品件数计**：

```
订单支付 → (自动接单[营业+auto_accept]) → 并入「组单中」批次(≤12件商品)
    → 批次派车：路径规划(按点位分组+贪心最近邻) → 为每单创建独立平台任务(同一设备/货仓)
    → 商家上货：扫码识别机器人 → 整批开舱 → 放货 → 关舱 → 整批确认出发
    → 机器人按路线逐点位配送 → 每点位用户凭「本单独立取餐码」开舱取走自己那份
    → 全部订单取走(picked_up_at 全非空) 或 平台任务全部完成 → 批次完成
```

要点：

1. **容量以商品件数为单位**（`BATCH_MAX_ITEMS`，默认 12 件/车）：`delivery_batches.total_items` 记录已装件数，自动派车满员按 `total_items ≥ 12` 判断；不再以订单数为容量。
2. **最优分批（best-fit 贪心）**：新订单按商品总件数（`order_items.quantity` 求和）放入「能容纳且当前最满」的组单中批次（`total_items + 本单件数 ≤ 12`，按 `total_items DESC` 取最满）；无合适批次才新建。**单件数 < 12 → 整单留在同一批**；**单件数 > 12 → 自动独占新建批次**（当前试点订单件数均远小于 12；跨车拆单需改造取餐码/任务与批次关联，属后续升级项）。
3. **每单独立取餐码**（防止同一仓多人拿错；平台 unloading/verify 按任务匹配取餐码开舱）。
4. **一个仓多个人拿**：orders.picked_up_at 记录每单是否已取走；批次完成 = 仓内全部取完。
5. **多地点配送顺序**：batch.route 按停靠顺序（贪心最近邻，近似最小化顾客总等待），平台任务按停靠顺序创建并以 priority 递减提示排程；同点位多单合并为一站。**路线在商家端批次卡下方展示**：先送楼栋在左、后送在右，以 `→` 分隔。
6. **批次 UI 区分**：商家端批次卡头部整行品牌蓝底白字（状态/件数标签白底蓝字），便于一眼区分不同批次。
7. **平台对接**：每单一个 queue/create 任务（outOrderNo 独立），同批次指定同一 deviceSn（未指定时自动挑空闲机器人或由平台队列分配）；平台单任务仅一个下货点，多地点 = 一车多任务，机器人按任务顺序逐点配送（verify/match 返回机器内全部任务）。

## 2. 技术选型

| 项         | 选择                                  | 说明                         |
| ---------- | ------------------------------------- | ---------------------------- |
| 小程序框架 | 微信原生                              | 保持速度与稳定性，不做跨端   |
| UI 组件    | 全自绘 + tdesign-miniprogram icon     | 设计变量集中在 app.wxss      |
| 后端       | Node.js + Express                     | 本地可跑，便于课程演示       |
| 数据库     | SQLite（node:sqlite 内置驱动）        | 零依赖；后续可平滑迁移 MySQL |
| 登录       | 微信 code2session（测试阶段演示登录） | 正式启用见 server.js 注释    |
| 支付       | 微信支付 V3 JSAPI                     | services/wxpay.js            |
| 物流平台   | robox 开放物流平台                    | services/platform.js         |
| 配置       | 轻量 .env 加载（零依赖）              | backend/.env                 |

## 6. 存储方案

### 小程序本地缓存（wx.setStorageSync）

| key                          | 内容                          | 端     |
| ---------------------------- | ----------------------------- | ------ |
| token                        | 登录凭证（openid）            | 双端   |
| userInfo                     | 用户对象                      | 双端   |
| checkout_items               | 结算商品项                    | 用户端 |
| last_confirm                 | 上次下单的点位/姓名/电话/备注 | 用户端 |
| order_tab                    | 订单列表当前 tab              | 用户端 |
| goods_category / goods_focus | 商城分类/搜索焦点             | 用户端 |
| shopInfo                     | 店铺状态缓存（营业/自动接单） | 商家端 |

### 后端存储（SQLite）

所有业务数据落库：users/addresses/landmarks/goods/cart/orders/order_items/delivery_tasks/shops/activities。状态统一在服务端，多端共享（如店铺营业状态）。

#### 商品库存/销量模型（goodsStats 服务）

- **下单**（/api/order/create）：库存即时 `-数量`（`MAX(0,…)` 防负），售罄商品拒绝下单；**销量不计**。
- **收货完成**（订单到 3 已送达 / 4 已完成：平台任务 80、用户取餐开舱、商家测试完成、确认取餐/关舱）：`goods.sales += 数量`，`orders.goods_settled=1`（幂等）。
- **取消/退款**（订单 5/7）且 `goods_settled=0`：`goods.stock += 数量` 回补（未真正售出不记销量）。
- 实现：`backend/services/goodsStats.js`（settleSales / restoreStock），由 server.js、services/batch.js（markOrderPicked）、services/platform.js（applyStatus）调用。

## 7. 安全点

| 风险         | 措施                                                                            |
| ------------ | ------------------------------------------------------------------------------- |
| 接口越权     | 除公开接口外均校验登录（auth）；商家接口校验 role=merchant（merchantGuard 403） |
| 凭证泄露     | 开放物流平台 appid/secret、微信支付商户私钥只存后端 .env，小程序端不存放        |
| 支付回调伪造 | wxpay.decryptNotify 用 APIv3 密钥解密 AES-GCM，校验 out_trade_no 与订单状态     |
| 取餐验证     | pickup_code 校验（扫码/输码），不匹配拒绝                                       |
| 登录态       | token=openid（真实 openid 不可预测）；演示模式为本地哈希                        |
| XSS          | 小程序原生渲染不执行 HTML；商品/活动文案仅文本展示                              |
| 地址数据     | landmark_id 后端统一转字符串，避免类型不一致导致匹配错误                        |
| 输入校验     | 手机号正则、金额按商品表计价（不信任前端传价）                                  |

## 8. 风险点

| 风险             | 说明 / 应对                                                                                                            |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 包体积           | 当前单包、组件精简（仅 icon）；若超 2MB 需做分包（把订单/配送等低频页拆到 subPackages）                                |
| 低版本兼容       | 使用的基础 API 均为常用能力；真机低版本微信需关注 wx.requestPayment / wx.chooseMedia                                   |
| 平台外送上楼限制 | 平台错误码 DLV_CTRL_0023 禁止外卖上楼任务，配送点按楼栋门口设计                                                        |
| 回调公网可达     | feedbackDeliveryTaskUrl / checkBizOrderStatusUrl / 支付回调需公网 https（云服务器域名）；无公网时用 basicList 轮询兜底 |
| Mock/真实切换    | PLATFORM_MOCK=true 本地演示；真实模式需配置平台凭据与点位同步，否则任务不下发（有明确提示）                            |
| 支付未配置       | 支付接口返回 501；正式上线必须配置微信支付商户                                                                         |
| 登录未配置       | 测试阶段演示登录；正式必须 WX_APPID/WX_SECRET                                                                          |
| 数据量增长       | 列表接口暂未分页；订单量大后需加分页与索引                                                                             |
