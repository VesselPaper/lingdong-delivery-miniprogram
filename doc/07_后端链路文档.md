# 07 · 前后端链路文档

最后更新：2026-09-03
说明：记录小程序用户端与商家端每个关键操作的前后端完整链路（点击按钮 → API 请求 → 后端处理 → 数据库变化 → 前端渲染）。接口细节见 doc/02_接口文档.md。

## 基础说明

后端地址：http://127.0.0.1:3000
配置：backend/.env（复制 .env.example 填写），微信登录/支付/开放物流平台凭据均从环境变量读取。
前端请求封装：utils/request.js，统一携带 Authorization 头（Bearer token），返回结构 code=0 为成功。
鉴权：后端根据 token（openid）识别用户，商家接口校验 role=merchant。
订单状态：0 待支付、1 待接单、2 配送中、3 已送达、4 已完成、5 已取消、6 配送异常。
数据库：backend/data/lingdong.db（SQLite，node:sqlite 内置驱动）。

## 链路 1：微信登录（用户端/商家端）

点击位置：用户端登录页「微信一键登录」或商家端登录页「微信一键登录」。
前端动作：调用 POST /api/auth/login，传 code、role（student/merchant）、nickname。
后端处理：测试阶段为演示登录——未配置 WX_APPID/WX_SECRET 时，以 code 的稳定哈希作为 openid，点击登录直接成功（便于预览）；正式环境启用真实 code2session（代码在 server.js 注释保留，配置 .env 后取消注释）。
数据库变化：users 表新增或更新一行（openid、nickname、role）。
前端渲染：返回 token 与 user 存入本地 storage；商家端登录后跳转工作台首页。

## 链路 2：首页加载商品

页面加载：首页 onShow。
前端动作：GET /api/goods/list。
后端处理：查询 goods 表 status=1 的商品，按销量排序。
数据库变化：无（只读）。
前端渲染：商品卡片流展示，月售、价格、加购按钮。

## 链路 3：加入购物车

点击位置：首页或商品列表的加号按钮。
前端动作：POST /api/cart/add，传 goods_id、quantity=1。
后端处理：查询 cart 表是否已有该用户该商品，有则加数量，无则插入。
数据库变化：cart 表新增或更新一行。
前端渲染：toast「已加入购物车」。

## 链路 4：购物车结算

点击位置：购物车页「结算」按钮。
前端动作：读取选中项，写入本地 storage checkout_items，跳转确认订单页。
后端处理：无。
数据库变化：无。
前端渲染：确认订单页展示商品清单与送达点位。

## 链路 4.1：收货地址（结算页关联）

页面：确认订单页收货地址卡（关联「我的-收货地址」）。
前端动作：加载 GET /api/address/list（同时加载 /api/landmarks 点位）；自动选中默认地址（无默认则取第一条，无地址则回填上次下单选项）；弹层选择地址或「新增收货地址」。
前端处理：选中地址后按 landmark_id 匹配点位自动回填送达点，并回填 contact_name / contact_phone（数值比较兜底，兼容历史 "2.0" 文本数据）。
后端处理：/api/address/save 将 landmark_id 显式转字符串存储（node:sqlite 会把整数绑定到 TEXT 列存成 "2.0"，导致与点位 id 无法匹配）；启动迁移自动修正历史 "2.0" 数据。
数据库变化：addresses 表增删改。
前端渲染：地址卡展示收餐人/电话/点位/详细地址；新增地址从地址管理页返回后自动刷新。

## 链路 5：提交订单（下单）

点击位置：确认订单页「提交订单」按钮。
前端校验：点位、姓名、手机号格式。
前端动作：POST /api/order/create，传 landmark_id、landmark_name、remark、items 数组。
后端处理：按 goods 表单价计算总额，生成 order_no 与 pickup_code，插入 orders 表（status=0 待支付），写入 order_items 明细，同步扣减库存、累加销量，清空购物车。
数据库变化：orders 新增一行、order_items 新增多行、goods 库存与销量更新、cart 清空。
前端渲染：跳转订单详情页并拉起支付。

## 链路 6：支付订单（微信支付 V3）

点击位置：订单详情页「立即支付」或订单列表「去支付」。
前端动作：POST /api/order/pay，传 id。
后端处理：校验订单为待支付状态，调用微信支付 V3 统一下单（jsapiPay），返回小程序端拉起收银台所需参数。
前端渲染：wx.requestPayment 拉起微信收银台。
支付结果：微信服务器回调 POST /api/pay/notify，后端解密 resource 后将订单 status 0 → 1（待接单）；前端支付成功后轮询订单详情确认已收款（status>0）。

## 链路 7：商家接单（创建配送任务）

点击位置：商家端订单列表「接单」或订单详情「接单并装车」或扫码配单。
前端动作：POST /api/merchant/order/confirm，传 id。
后端处理：校验商家身份、店铺营业状态（歇业则拒绝）、订单状态（须为 1 待接单），调用平台层创建配送任务。
数据库变化：orders.status 1 → 2，delivery_tasks 新增一行（task_status 0 排队中，绑定 delivery_task_id）。
平台层：
真实模式（默认）：调用开放物流平台 queue/create 创建排队任务（上货点=零栋铺子取餐点，送货点=学生所选点位，下货策略=收件人手机号/取餐码），注册 feedbackDeliveryTaskUrl 与 checkBizOrderStatusUrl 回调，记录 platform_task_id。
本地演示（PLATFORM_MOCK=true）：本地状态机每 4 秒推进任务状态，到达取餐点自动置订单为已送达。
前端渲染：toast「已接单，机器人出发」，订单列表刷新为配送中。

## 链路 8：配送追踪

页面：用户端「配送」tab 或订单详情「查看配送位置」。
前端动作：GET /api/delivery/track?order_id=x，每 3 秒轮询。
后端处理：查询 orders 与 delivery_tasks，返回订单状态、任务状态、机器人位置（真实模式走 eviz 代理接口，Mock 模式返回模拟坐标）。
数据库变化：无（只读）。
前端渲染：进度条（已接单/取餐/配送/送达四段）、机器人位置在地图移动、取餐码展示。

## 链路 9：平台状态回调（真实模式）

触发：开放物流平台任务状态变更时回调 POST /api/platform/callback/delivery（feedbackDeliveryTaskUrl）。
后端处理：按 platform_task_id 找到 delivery_tasks，调用 platform.applyStatus 更新任务状态并联动订单状态：
任务 70 到达取餐点 → 订单 3 已送达（待取餐）
任务 80 完成 → 订单 4 已完成
任务 110/150 取消/关闭 → 订单 5 已取消
任务 90/100 系列失败 → 订单 6 配送异常
数据库变化：delivery_tasks.task_status、orders.status 更新。
兜底：后端每 PLATFORM_POLL_MS（默认 8s）轮询 deliveryTask/basicList 同步活动任务状态。

## 链路 10：确认取餐（完成订单）

点击位置：配送追踪页「扫码取餐/输入取餐码」或订单详情同按钮。
前端动作：POST /api/delivery/confirm，传 order_id、scan_code（扫码或输入）。
后端处理：校验订单状态为 3 已送达；若传 scan_code 则与订单 pickup_code 比对，不匹配拒绝。
数据库变化：orders.status 3 → 4。
前端渲染：订单状态变为「已完成」。

## 链路 11：取消订单

点击位置：订单列表「取消」。
前端动作：确认弹窗后 POST /api/order/cancel，传 id。
后端处理：仅待支付（0）与待接单（1）可取消，置为已取消（5）。
数据库变化：orders.status → 5。
前端渲染：订单显示「已取消」。

## 链路 12：商家工作台统计

页面：商家端工作台（进入站点）。
前端动作：GET /api/merchant/stats。
后端处理：按天统计今日订单数、营业额（排除待支付与已取消）、待接单数、配送中数、完成数。
数据库变化：无（只读）。
前端渲染：统计卡。

## 链路 13：店铺营业/自动接单（真实后端状态）

页面：商家端店铺设置。
前端动作：GET /api/merchant/shop 拉取状态；PUT /api/merchant/shop 切换营业/自动接单。
后端处理：读写 shops 表（id=1 单门店）；接单接口校验店铺营业状态，歇业时拒绝接单。
数据库变化：shops.business_status / auto_accept 更新。
前端渲染：首页/订单页展示营业标记，设置页切换后即时生效（多端共享同一后端状态）。

## 链路 14：商家商品管理

新增：POST /api/merchant/goods，插入 goods 表。
编辑：PUT /api/merchant/goods，更新 goods 表。
上下架：PUT /api/merchant/goods/status，更新 status 字段（1 在售 / 0 下架），用户端仅展示在售商品。
图片：POST /api/merchant/upload 上传 base64 图片至 backend/uploads，返回 /uploads/xxx 路径。
前端渲染：商品列表刷新，下架商品用户端不再可见。

## 链路 15：配送监控（商家端）

页面：商家端「配送监控」。
前端动作：GET /api/merchant/delivery/monitor，每 5 秒轮询；GET /api/merchant/robots 获取机器人真实状态。
后端处理：monitor 查询所有未完成配送任务（含失败任务），关联订单编号与送达点位，附加机器人位置；robots 调用开放物流平台 runtimeStatusList 返回真实设备（编号/名称/在线/电量/运行状态/位置，状态码映射为中文）。
数据库变化：无（只读）。
前端渲染：顶部展示真实机器人卡（可多台）；任务列表展示状态文本与位置。平台未配置或调用失败时，机器人区显示错误卡（"未配置开放物流平台凭据 / 本地演示模式"）+ 重试按钮。

## 链路 16：平台点位同步（真实模式）

入口：商家端调用 POST /api/merchant/landmarks/sync（需商家身份）。
后端处理：调用开放物流平台 buildingList 获取 buildingId，landmarkInfo 获取点位列表，将 platform_building_id / platform_map_id / platform_landmark_id 写入本地 landmarks 表。
数据库变化：landmarks 表平台映射字段更新。
前端渲染：用户端下单选址展示真实点位；接单时据此创建真实排队任务。

## 链路 17：商家端活动管理（发布/编辑/上下线/删除）

页面：商家端工作台「活动管理」→ 活动列表/编辑。
前端动作：
新建：POST /api/merchant/activities，传 title、subtitle、link、sort（保存后默认发布 status=1）。
编辑：PUT /api/merchant/activities，传 id 与字段。
上下线：PUT /api/merchant/activities/status，传 id、status（1 发布 / 0 下线）。
删除：DELETE /api/merchant/activities，传 id。
列表：GET /api/merchant/activities（含未发布活动）。
后端处理：读写 activities 表；用户端 GET /api/activity/list 仅返回 status=1（已发布）活动。
数据库变化：activities 表增删改，status 控制发布状态。
前端渲染：商家端活动列表展示状态标签（已发布/已下线），可编辑/发布/下线/删除；用户端活动页展示已发布活动，点击跳转 link。

## 与开放物流平台的关系

默认真实模式：凭据来自 .env（PLATFORM_APPID/PLATFORM_SECRET/PLATFORM_PRINCIPALID），创建任务调用 robox 测试环境排队任务接口 queue/create，状态通过 feedbackDeliveryTaskUrl 回调 + basicList 轮询双通道同步，位置通过 eviz/iotGatewayProxy 获取，点位通过 buildingList/landmarkInfo 同步。
本地演示：PLATFORM_MOCK=true 时使用本地模拟状态机自动推进，完整演示下单→接单→配送→取餐链路。
平台对接细节（字段取值、点位映射）待 Apifox 接口文档获取后精化，见 文档\8月26日说明会问题清单.md。
