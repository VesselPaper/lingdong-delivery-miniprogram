最后更新：2026-09-03
说明：自建后端（Node/Express/SQLite）全部接口。开放物流平台（robox）开放接口以正式环境 Apifox 导出文档为准：`校内快递配送机器人/接口/默认模块.openapi.json`（open-logis_1.0，本地保留，不入 git）；配套说明见 项目进度/03_技术记录.md 与 文档/飞书文档/飞书文档.md。
后端地址：http://127.0.0.1:3000（生产替换为正式域名）；前端请求统一走 utils/request.js。

## 通用约定

### Base URL
开发：`http://localhost:3000/api` 或 `http://127.0.0.1:3000/api`
生产：由小程序 config.js 的 baseUrl 配置，需为小程序后台白名单域名（https）。

### 请求格式
Content-Type: application/json；请求体为 JSON。

### 返回结构（统一）
```json
{ "code": 0, "msg": "success", "data": { ... } }
```
- code = 0 表示成功；非 0 为业务失败或 HTTP 状态码。
- HTTP 状态码与业务 code 通常一致：400 参数/状态错误、401 未登录、403 无权限、404 不存在、500 服务端、501 未配置、502 上游失败。

### 鉴权
除登录、商品、点位、活动、平台回调外，均需在请求头携带：
```
Authorization: Bearer <token>
```
token 即登录返回的 openid（演示模式下为 demo_ 前缀的稳定哈希）。登录失效返回 401。

### 登录
POST /api/auth/login 返回 token 与 user，前端存 storage（key: token / userInfo）。

### 文件上传
POST /api/merchant/upload，body 传 base64 图片数据，返回 /uploads/xxx 相对路径；前端 request.js 会自动转成完整地址。

### 分页
当前接口均为全量返回（无分页）；如后续数据量大，订单/商品列表可加 page/size。

### 错误码速查
- 0 成功
- 400 参数错误 / 业务状态不允许
- 401 未登录 / 登录失效
- 403 无权限（非商家访问商家接口）
- 404 数据不存在
- 500 服务端异常
- 501 功能未开通（支付通道未配置）
- 502 上游调用失败（微信下单失败、获取机器人失败）

## 一、用户与鉴权

### 1.1 登录
- 地址：POST /api/auth/login
- 鉴权：无
- 入参：
```json
{ "code": "wx.login 返回的 code", "role": "student | merchant", "nickname": "昵称(可选)" }
```
- 出参：
```json
{ "token": "openid", "user": { "id":1, "openid":"...", "nickname":"...", "phone":"...", "role":"student" } }
```
- 说明：测试阶段为演示登录（以 code 稳定哈希为 openid，点击微信登录直接成功）；正式环境启用 code2session（server.js 中注释保留，配置 WX_APPID/WX_SECRET 后启用）。
- 错误：400 缺少登录凭证。

### 1.2 获取用户信息
- 地址：GET /api/user/profile
- 鉴权：需登录
- 出参：user 对象（id/openid/nickname/phone/role）

### 1.3 更新用户信息
- 地址：PUT /api/user/profile
- 鉴权：需登录
- 入参：`{ "nickname": "新昵称", "phone": "13800000000" }`（均可选）
- 出参：更新后的 user

## 六、订单

订单状态：0 待支付 / 1 待接单 / 2 配送中 / 3 已送达 / 4 已完成 / 5 已取消 / 6 配送异常 / 7 已退款

### 6.1 创建订单
- 地址：POST /api/order/create
- 鉴权：需登录
- 入参：
```json
{ "landmark_id":"8", "landmark_name":"东苑1栋", "remark":"不要辣", "items":[{"goods_id":1,"quantity":2}] }
```
- 出参：`{ "order_id":7, "order_no":"LD12345678XXXX", "total_amount":21.8, "pickup_code":"1234" }`
- 说明：后端按商品表单价计价；生成 order_no 与 4 位取餐码；**下单即扣库存**（实时可用量，防超卖）、清空购物车；**销量在收货完成时结算**（见 6.4 说明 / goodsStats）。**店铺歇业时拒绝下单**（用户端结算按钮同步置灰）。
- 错误：400 订单不能为空 / 商品不存在 / **「xx」已售罄，请更换商品** / **店铺歇业中，暂无法下单**。

> **库存/销量口径（goodsStats）**：下单时库存即时 -1（防止超卖）；订单到达「收货完成」（status 3 已送达 / 4 已完成，含平台任务 80、用户取餐开舱、商家测试完成）时已售 +1（幂等，orders.goods_settled 标记）；订单取消(5)/退款(7)且未结算时**回补库存**（不记已售）。

### 6.2 支付下单（微信支付 V3 JSAPI）
- 地址：POST /api/order/pay
- 鉴权：需登录
- 入参：`{ "id":7 }`
- 出参：`{ "order_id":7, "payParams": { "timeStamp":"", "nonceStr":"", "package":"prepay_id=...", "signType":"RSA", "paySign":"..." } }`
- 说明：前端拿到 payParams 调 wx.requestPayment；支付结果以微信回调为准。
- 试点说明：`backend/.env` 设 `PAY_MOCK=true` 时跳过真实微信支付，直接置订单为已支付（status=1），用于先跑通真实配送；商户号就绪后删除该开关即走真实支付。
- 错误：400 状态不允许支付 / 404 订单不存在 / 501 支付通道未配置 / 502 微信下单失败。

### 6.3 微信支付结果回调（微信服务器调用）
- 地址：POST /api/pay/notify
- 鉴权：无（微信服务器直调，需公网可达 https）
- 入参：微信支付 V3 回调报文（resource 加密）
- 出参：`{ "code":"SUCCESS", "message":"成功" }`
- 说明：解密 resource，trade_state=SUCCESS 且订单待支付时置 status=1。

### 6.4 订单列表
- 地址：GET /api/order/list?status=1
- 鉴权：需登录
- Query：status 可选（空=全部）
- 出参：orders 数组（含 status_text）

### 6.5 订单详情
- 地址：GET /api/order/detail?id=7
- 鉴权：需登录
- 出参：
```json
{ "...订单字段...", "status_text":"配送中", "items":[{ "goods_id":1,"goods_name":"...","quantity":2,"price":10.9 }],
  "task": { "task_status":50, "status_text":"已上货，出发配送" } }
```

### 6.6 取消订单
- 地址：POST /api/order/cancel
- 鉴权：需登录
- 入参：`{ "id":7 }`
- 说明：免费取消窗口内（下单后 `FREE_CANCEL_WINDOW_MS` 内，默认 10 分钟，可用环境变量覆盖）可直接取消，**不论商家是否接单**，只要未真正开始配送（配送任务状态 < 50 已上货）；待支付(0)订单随时可取消。取消后状态 5 已取消；若有配送任务且未完成，同步标记任务取消（task_status=110）。
- 错误：400 已超过可自由取消时间，请提交取消申请 / 配送中不支持取消，送达后可申请退款 / 该订单已送达/完成，请通过「退款/投诉」申请处理。

### 6.7 提交取消申请（用户）
- 地址：POST /api/order/cancel-request
- 鉴权：需登录
- 入参：`{ "order_id":7, "reason":"临时有事" }`
- 出参：`{ "id":1, "status":0 }`
- 说明：超过免费取消窗口且未配送（待支付0/待接单1）时提交，由商家判断是否同意；同一订单存在待处理申请时不可重复提交。
- 错误：400 当前状态不可提交取消申请 / 仍可直接取消，无需提交申请 / 已有待处理的取消申请。

### 6.8 我的取消申请记录（用户）
- 地址：GET /api/order/cancel-request/list
- 鉴权：需登录
- 出参：取消申请数组（含 order_no、reason、status、status_text、merchant_reply）

### 6.9 我的页订单红点（进行中订单常驻计数）
- 地址：GET /api/user/order/badge
- 鉴权：需登录
- 出参：`{ "unread": true, "count": 2 }`
- 说明：**进行中的订单数**（待接单1/配送中2/已送达待取餐3），**常驻显示不随已读清除**；订单全部处理完（完成/取消/退款）后才消失。用于「我的」页全部订单/配送中图标红点+数字。

### 6.10 标记订单动态已读（兼容保留）
- 地址：POST /api/user/order/mark-read
- 鉴权：需登录
- 入参：空
- 说明：保留兼容（红点已改为进行中常驻计数，本接口不再清除红点）。

## 七、配送

### 7.1 配送追踪
- 地址：GET /api/delivery/track?order_id=7
- 鉴权：需登录
- 出参：
```json
{ "order_status":3, "order_status_text":"已送达", "pickup_code":"1234", "landmark_name":"东苑1栋",
  "task": { "task_status":70, "status_text":"已到达取餐点" },
  "task_text": "已到达取餐点",
  "position": { "x":996,"y":880,"theta":-3.117,"timestamp":..., "locQuality":"100.0" },
  "batch": { "batch_id":1, "batch_no":"BD...", "status":2, "status_text":"配送中",
             "total_orders":4, "picked_orders":1, "multi_order":true, "device_sn":"..." } }
```
- 说明：position 真实模式来自平台 eviz（可能为 null），Mock 模式返回模拟坐标。`batch` 为同批次信息（一车多单：本车共几单/已取几单）；`task_text` 在无任务时给出更准确文案（组单中/待上货阶段）。

### 7.2 确认取餐
- 地址：POST /api/delivery/confirm
- 鉴权：需登录
- 入参：`{ "order_id":7, "scan_code":"1234" }`
- 说明：须订单已送达(3)；传 scan_code 时与 pickup_code 比对。
- 错误：400 机器人还未送达 / 取餐码不匹配。

### 7.3 扫码取餐（取餐页进入）
- 地址：POST /api/delivery/pickup-scan
- 鉴权：需登录
- 入参：`{ "order_id":7 }`
- 出参：`{ "order_id":7, "order_no":"...", "pickup_code":"1234", "landmark_name":"东苑1栋", "task":{ "task_id":12, "platform_task_id":"...", "device_sn":"...", "task_status":70, "status_text":"已到达取餐点" } }`
- 说明：校验订单归属 + 已送达(3)，返回取餐上下文供取餐页展示与操作。机器人屏二维码为「模拟扫码」动作后进入本页。
- 错误：404 订单不存在 / 400 机器人还未送达。

### 7.4 打开舱门取餐
- 地址：POST /api/delivery/pickup-open
- 鉴权：需登录
- 入参：`{ "order_id":7 }`
- 出参：`{ "order_id":7, "status":4, "test":true|false }`
- 说明：须已送达(3)。有真实任务（deviceSn+平台任务）时调平台 unloading/verify 开舱（开舱即完成，订单→4）；无真实任务时本地直接完成并标记 `test:true`（测试兜底）。**一车多单：开舱取餐即标记本单已取走（orders.picked_up_at），批次已取计数 +1，全部取完批次完成**。
- 错误：404 / 400 机器人还未送达 / 502 开舱失败。

### 7.5 关闭舱门
- 地址：POST /api/delivery/pickup-close
- 鉴权：需登录
- 入参：`{ "order_id":7 }`
- 出参：`{ "order_id":7, "status":4, "test":true|false }`
- 说明：调平台 unloading/confirm 关舱返回（40s 未调用平台自动关舱）；订单若仍为已送达则置为已完成。测试兜底同上。
- 错误：404 / 400 订单状态不允许 / 502 关舱失败。

## 九、商家端（全部需商家身份，403 无权限）

### 9.1 店铺状态
- 地址：GET /api/merchant/shop
- 出参：`{ "id":1, "name":"零栋铺子", "business_status":"open", "auto_accept":0 }`

### 9.2 更新店铺状态
- 地址：PUT /api/merchant/shop
- 入参：`{ "business_status":"open|closed", "auto_accept":1 }`
- 出参：更新后 shop

### 9.3 工作台统计
- 地址：GET /api/merchant/stats
- 出参：
```json
{
  "today_orders":10, "today_amount":120.5,
  "pending":2,          // 待接单：订单 status=1
  "ready_load":1,       // 待上货：批次 status=1（机器人前往上货点，可上货）
  "delivering":2,       // 配送中：批次 status=2
  "pickup":3,           // 待取货：订单 status=3（已送达未取）
  "exception":0,        // 异常：订单 status=6
  "aftersale":1,        // 售后：待处理退款/投诉数
  "cancel_requests":0,  // 待处理取消申请
  "finished":5          // 已完成订单数
}
```
- 说明：商铺首页主面板依次展示「待接单/待上货/配送中/待取货」四态，异常/售后放次面板。

### 9.4 商家订单列表
- 地址：GET /api/merchant/orders
- 鉴权：需商家
- Query 三选一：`?stage=accept|load|deliver|pickup`（任务页四分类：待接单 / 待上货=已接单且批次未派车或待上货 / **配送中=批次已开始配送** / 待取货=已送达）或 `?scope=active|history` 或 `?status=状态号`
- 出参：订单数组，每单含：
```json
{
  "id":7, "order_no":"LD...", "daily_seq":12, "status":2, "status_text":"配送中",
  "stage_text":"待上货",
  "landmark_name":"东苑1栋", "total_amount":21.8, "created_at":"...",
  "items":[{"goods_id":1,"goods_name":"...","goods_image":"/uploads/..","price":10.9,"quantity":2}],
  "first_name":"...", "first_image":"/uploads/..", "first_qty":2, "item_count":3,
  "batch":{"batch_no":"BD...","daily_seq":3,"status":1}
}
```
- 说明：`daily_seq` 为当日序号（每天从 1 重置，商家端卡面展示「订单 N / 批次 N」，完整编号只在详情页显示）；items/first_* 供任务页与历史订单页展示商品图片、价格、数量；**stage 过滤时返回 `stage_text`**（待接单/待上货/配送中/待取货，任务页按分类着色，避免「待上货分类里全是配送中字样」）；`landmark_name` 已清洗脏点位名（`?？` 占位符回退 landmarks 表）。

### 9.4A 配送异常订单处理（重新配送 / 取消并退款）
- 地址：POST /api/merchant/order/exception/retry
- 鉴权：需商家
- 入参：`{ "order_id":44 }`
- 说明：仅订单状态=6（配送异常）可操作。重新配送：作废旧批次未完成任务、从旧批次摘除、并入新的「组单中」批次（商家随后派车重新上货配送）。出参 `{ order_id, status:2, batch_id, batch_no, msg }`。

## 十一、状态同步机制（真实模式）

- 主通道：平台 feedbackDeliveryTaskUrl 回调推送任务状态。
- 兜底：后端每 PLATFORM_POLL_MS（默认 8s）轮询 deliveryTask/basicList 同步活动任务（查询参数 `idList=平台任务ID`，返回 data 数组即任务本体，字段 taskStatus/deviceSn）。
- 位置：配送追踪/监控调 `iotGatewayProxy/{deviceSn}/buildingManager/om-api/EvizServer` 获取机器人坐标，3 秒缓存。
- **超时未接单检测**：机器人长时间未接单（任务卡在「排队中0/任务已接收10/去上货点20/到达上货点30/上货中40」超过 `DELIVERY_TIMEOUT_MS`，默认 15 分钟，可用环境变量覆盖）→ 订单自动标记**配送异常(6)**，商家端「异常」可见并可处理（重试/取消/退款）。扫描间隔 `DELIVERY_SCAN_MS`（默认 60s）。

### 12.5 商家处理售后
- 地址：POST /api/merchant/refund/handle
- 鉴权：需商家
- 入参：`{ "id":1, "action":"approve|reject|reply", "amount":5(可选,退款同意时可改), "reply":"理由/回复" }`
- 说明：退款 approve → 状态3 已退款、订单→7 已退款（金额默认全额，传 amount 可部分退款）；reject → 状态2（需理由）；投诉 reply → 状态4 已处理。
- 错误：404 售后单不存在 / 400 已处理或缺少理由。
