# 02 · 接口文档（API）

最后更新：2026-09-03
说明：自建后端（Node/Express/SQLite）全部接口。开放物流平台（robox）开放接口以正式环境 Apifox 导出文档为准：`送餐无人车微信小程序/接口/默认模块.openapi.json`（open-logis_1.0，本地保留，不入 git）；配套说明见 项目进度/03_技术记录.md 与 文档/飞书文档/飞书文档.md。
后端地址：http://127.0.0.1:3000（生产替换为正式域名）；前端请求统一走 utils/request.js。

## 通用约定

### Base URL
开发：`http://localhost:3000/api` 或 `http://127.0.0.1:3000/api`
生产：由小程序 config.js 的 baseUrl 配置，需为小程序后台白名单域名（https）。

### 请求格式
Content-Type: application/json；请求体为 JSON。

### 返回结构（统一）
```json
{ "code": 0, "msg": "success", "data": { ... } }
```
- code = 0 表示成功；非 0 为业务失败或 HTTP 状态码。
- HTTP 状态码与业务 code 通常一致：400 参数/状态错误、401 未登录、403 无权限、404 不存在、500 服务端、501 未配置、502 上游失败。

### 鉴权
除登录、商品、点位、活动、平台回调外，均需在请求头携带：
```
Authorization: Bearer <token>
```
token 即登录返回的 openid（演示模式下为 demo_ 前缀的稳定哈希）。登录失效返回 401。

### 登录
POST /api/auth/login 返回 token 与 user，前端存 storage（key: token / userInfo）。

### 文件上传
POST /api/merchant/upload，body 传 base64 图片数据，返回 /uploads/xxx 相对路径；前端 request.js 会自动转成完整地址。

### 分页
当前接口均为全量返回（无分页）；如后续数据量大，订单/商品列表可加 page/size。

### 错误码速查
- 0 成功
- 400 参数错误 / 业务状态不允许
- 401 未登录 / 登录失效
- 403 无权限（非商家访问商家接口）
- 404 数据不存在
- 500 服务端异常
- 501 功能未开通（支付通道未配置）
- 502 上游调用失败（微信下单失败、获取机器人失败）

## 一、用户与鉴权

### 1.1 登录
- 地址：POST /api/auth/login
- 鉴权：无
- 入参：
```json
{ "code": "wx.login 返回的 code", "role": "student | merchant", "nickname": "昵称(可选)" }
```
- 出参：
```json
{ "token": "openid", "user": { "id":1, "openid":"...", "nickname":"...", "phone":"...", "role":"student" } }
```
- 说明：测试阶段为演示登录（以 code 稳定哈希为 openid，点击微信登录直接成功）；正式环境启用 code2session（server.js 中注释保留，配置 WX_APPID/WX_SECRET 后启用）。
- 错误：400 缺少登录凭证。

### 1.2 获取用户信息
- 地址：GET /api/user/profile
- 鉴权：需登录
- 出参：user 对象（id/openid/nickname/phone/role）

### 1.3 更新用户信息
- 地址：PUT /api/user/profile
- 鉴权：需登录
- 入参：`{ "nickname": "新昵称", "phone": "13800000000" }`（均可选）
- 出参：更新后的 user

## 二、商品

### 2.1 商品分类
- 地址：GET /api/goods/categories
- 出参：`["热卤","卤味","饮品","套餐"]`

### 2.2 商品列表
- 地址：GET /api/goods/list
- Query：`category=热卤`（可选）、`keyword=xxx`（可选，名称模糊）
- 出参：goods 数组（仅 status=1 在售，按销量排序）
```json
[{ "id":1, "name":"...", "price":10.9, "original_price":12.9, "image":"", "category":"热卤", "stock":100, "status":1, "description":"...", "sales":326 }]
```

### 2.3 商品详情
- 地址：GET /api/goods/detail?id=1
- 出参：单个 goods；404 商品不存在

## 六、订单

订单状态：0 待支付 / 1 待接单 / 2 配送中 / 3 已送达 / 4 已完成 / 5 已取消 / 6 配送异常

### 6.1 创建订单
- 地址：POST /api/order/create
- 鉴权：需登录
- 入参：
```json
{ "landmark_id":"8", "landmark_name":"东苑1栋", "remark":"不要辣", "items":[{"goods_id":1,"quantity":2}] }
```
- 出参：`{ "order_id":7, "order_no":"LD12345678XXXX", "total_amount":21.8, "pickup_code":"1234" }`
- 说明：后端按商品表单价计价；生成 order_no 与 4 位取餐码；扣库存、加销量、清空购物车。
- 错误：400 订单不能为空 / 商品不存在。

### 6.2 支付下单（微信支付 V3 JSAPI）
- 地址：POST /api/order/pay
- 鉴权：需登录
- 入参：`{ "id":7 }`
- 出参：`{ "order_id":7, "payParams": { "timeStamp":"", "nonceStr":"", "package":"prepay_id=...", "signType":"RSA", "paySign":"..." } }`
- 说明：前端拿到 payParams 调 wx.requestPayment；支付结果以微信回调为准。
- 试点说明：`backend/.env` 设 `PAY_MOCK=true` 时跳过真实微信支付，直接置订单为已支付（status=1），用于先跑通真实配送；商户号就绪后删除该开关即走真实支付。
- 错误：400 状态不允许支付 / 404 订单不存在 / 501 支付通道未配置 / 502 微信下单失败。

### 6.3 微信支付结果回调（微信服务器调用）
- 地址：POST /api/pay/notify
- 鉴权：无（微信服务器直调，需公网可达 https）
- 入参：微信支付 V3 回调报文（resource 加密）
- 出参：`{ "code":"SUCCESS", "message":"成功" }`
- 说明：解密 resource，trade_state=SUCCESS 且订单待支付时置 status=1。

### 6.4 订单列表
- 地址：GET /api/order/list?status=1
- 鉴权：需登录
- Query：status 可选（空=全部）
- 出参：orders 数组（含 status_text）

### 6.5 订单详情
- 地址：GET /api/order/detail?id=7
- 鉴权：需登录
- 出参：
```json
{ "...订单字段...", "status_text":"配送中", "items":[{ "goods_id":1,"goods_name":"...","quantity":2,"price":10.9 }],
  "task": { "task_status":50, "status_text":"已上货，出发配送" } }
```

### 6.6 取消订单
- 地址：POST /api/order/cancel
- 鉴权：需登录
- 入参：`{ "id":7 }`
- 说明：仅待支付(0)/待接单(1)可取消，取消后状态 5。
- 错误：400 配送中的订单无法取消。

## 七、配送

### 7.1 配送追踪
- 地址：GET /api/delivery/track?order_id=7
- 鉴权：需登录
- 出参：
```json
{ "order_status":3, "order_status_text":"已送达", "pickup_code":"1234", "landmark_name":"东苑1栋",
  "task": { "task_status":70, "status_text":"已到达取餐点" },
  "position": { "x":996,"y":880,"theta":-3.117,"timestamp":..., "locQuality":"100.0" } }
```
- 说明：position 真实模式来自平台 eviz（可能为 null），Mock 模式返回模拟坐标。

### 7.2 确认取餐
- 地址：POST /api/delivery/confirm
- 鉴权：需登录
- 入参：`{ "order_id":7, "scan_code":"1234" }`
- 说明：须订单已送达(3)；传 scan_code 时与 pickup_code 比对。
- 错误：400 机器人还未送达 / 取餐码不匹配。

### 7.3 扫码取餐（取餐页进入）
- 地址：POST /api/delivery/pickup-scan
- 鉴权：需登录
- 入参：`{ "order_id":7 }`
- 出参：`{ "order_id":7, "order_no":"...", "pickup_code":"1234", "landmark_name":"东苑1栋", "task":{ "task_id":12, "platform_task_id":"...", "device_sn":"...", "task_status":70, "status_text":"已到达取餐点" } }`
- 说明：校验订单归属 + 已送达(3)，返回取餐上下文供取餐页展示与操作。机器人屏二维码为「模拟扫码」动作后进入本页。
- 错误：404 订单不存在 / 400 机器人还未送达。

### 7.4 打开舱门取餐
- 地址：POST /api/delivery/pickup-open
- 鉴权：需登录
- 入参：`{ "order_id":7 }`
- 出参：`{ "order_id":7, "status":4, "test":true|false }`
- 说明：须已送达(3)。有真实任务（deviceSn+平台任务）时调平台 unloading/verify 开舱（开舱即完成，订单→4）；无真实任务时本地直接完成并标记 `test:true`（测试兜底）。
- 错误：404 / 400 机器人还未送达 / 502 开舱失败。

### 7.5 关闭舱门
- 地址：POST /api/delivery/pickup-close
- 鉴权：需登录
- 入参：`{ "order_id":7 }`
- 出参：`{ "order_id":7, "status":4, "test":true|false }`
- 说明：调平台 unloading/confirm 关舱返回（40s 未调用平台自动关舱）；订单若仍为已送达则置为已完成。测试兜底同上。
- 错误：404 / 400 订单状态不允许 / 502 关舱失败。

### 9.19 平台点位同步
- 地址：POST /api/merchant/landmarks/sync
- 出参：`{ "ok":true, "buildingId":"1257237128126592_zcsdb3dd6396c824", "buildingName":"四川师范大学成龙校区", "count":10, "inserted":n, "updated":n, "removed":n }`
- 说明：调平台 buildingList + landmarkInfo（type=deliverPoint），按平台 landmarkId 幂等 upsert；名称含「上货/商铺/店铺/铺子」的点位识别为上货点（loadingPoint）；并清理无平台映射的历史演示点位。
- 错误：500 未配置平台凭据 / 同步失败。

### 9.20 扫码识别机器人（面对面上货）
- 地址：POST /api/merchant/device/scan
- 入参：`{ "deviceSn":"R105A2601A76GK00K00" }`（商家扫机器人屏幕二维码，内容为设备编号）
- 出参：`{ "task_id":12, "platform_task_id":"...", "device_sn":"...", "order_no":"...", "pickup_code":"1234", "delivery_landmark":"东苑1栋", "contact_name":"...", "contact_phone":"...", "task_status":30, "status_text":"到达上货点", "control_ok":true, "control_msg":"" }`
- 说明：按 deviceSn 定位该机器人上「待上货」订单（task_status<50）；回写 device_sn；调平台 authority/grant 获取控制权（header duration 180s）。Mock 模式返回最新未上货任务模拟。
- 错误：400 缺少设备编号 / 404 该机器人暂无待上货订单。

### 9.21 打开舱门（上货验证开舱）
- 地址：POST /api/merchant/device/open-bin
- 入参：`{ "task_id":12 }`
- 说明：调平台 loading/verify（strategies=anyCode 取餐码，autoOpen=true），验证通过自动开舱，任务状态→40 上货中。
- 错误：404 任务不存在 / 400 任务未下发到平台 / 502 上货验证失败。

### 9.22 关闭舱门（关舱等待，不派发）
- 地址：POST /api/merchant/device/close-bin
- 入参：`{ "task_id":12 }`
- 说明：调平台 drawerCtrl 关舱（stockPos=pos_1），机器人原地等待不派发（任务仍为 40）；商家点「立即配送」才派发。
- 错误：404 任务不存在 / 400 缺少设备编号（请先扫码）/ 502 舱门控制失败。

### 9.23 开始配送（确认上货）
- 地址：POST /api/merchant/device/dispatch
- 入参：`{ "task_id":12 }`
- 说明：调平台 loading/confirm，任务状态→50 已上货，机器人开始配送。
- 错误：404 任务不存在 / 400 任务未下发或缺少设备编号 / 502 确认上货失败。

### 9.24 待上货任务列表（上货页主入口）
- 地址：GET /api/merchant/device/pending
- 鉴权：需商家
- 出参：待上货任务数组（task_status IN 0/10/20/30/40，按"已到上货点/上货中"优先排序）
```json
[{ "task_id":12, "platform_task_id":"...", "device_sn":"R105A2601A76GK00K00", "task_status":30, "status_text":"到达上货点", "order_no":"LD...", "pickup_code":"1234", "delivery_landmark":"东苑1栋", "contact_name":"...", "contact_phone":"..." }]
```
- 说明：商家上货以列表选择为主（机器人到上货点即可见），扫码为可选项；选中后走 9.21~9.23 开舱/关舱/派发。

### 9.25 测试完成配送（测试辅助）
- 地址：POST /api/merchant/delivery/test-complete
- 鉴权：需商家
- 入参：`{ "order_id":13, "status":3 }`（status：3 已送达 / 4 已完成，默认 3）
- 说明：**仅测试用**。真实模式无真机器人时，把卡在「配送中」的订单标记为已送达/已完成（任务置 80），便于走通"用户取餐→完成"流程；不会真实下发任务。
- 错误：404 订单不存在。

## 十、开放物流平台回调（平台方调用）

### 10.1 配送任务状态回调（feedbackDeliveryTaskUrl）
- 地址：POST /api/platform/callback/delivery
- 鉴权：无（平台调用，需公网可达 https）
- 入参（平台回调结构，兼容多种字段）：
```json
{ "taskId":"...", "taskStatus":70, "taskStatusText":"已到达取餐点", "deviceSn":"..." }
```
- 出参：`{ "code":"SUCCESS", "msg":"ok" }`
- 说明：按 platform_task_id 找到本地任务，applyStatus 联动订单状态。

### 10.2 业务订单状态校验（checkBizOrderStatusUrl）
- 地址：POST /api/platform/check-order（兼容 GET）
- 入参：Query `orderNo`（或 body 的 orderNo/outOrderNo）
- 出参（订单正常）：`{ "code":"COMM_200", "data":null, "msg":"ok" }`
- 出参（订单已取消/退款，设备端强制关任务）：`{ "code":"COMM_200", "data":{ "keyEvent":{ "eventName":"forceCloseTask", "taskSubStatus":201, "eventDesc":"订单已取消/退款" } }, "msg":"ok" }`
- 说明：对接文档要求 HttpMethod 为 POST 且公开访问；taskSubStatus 201 已退款 / 202 人工送达。

### 10.3 设备异常上报回调
- 地址：POST /api/platform/callback/exception
- 出参：`{ "code":"SUCCESS", "msg":"ok" }`
- 说明：T 任务类 / R 机器类 / I IOT 类 / N 导航类异常，当前仅记录日志。

## 十一、状态同步机制（真实模式）

- 主通道：平台 feedbackDeliveryTaskUrl 回调推送任务状态。
- 兜底：后端每 PLATFORM_POLL_MS（默认 8s）轮询 deliveryTask/basicList 同步活动任务（查询参数 `idList=平台任务ID`，返回 data 数组即任务本体，字段 taskStatus/deviceSn）。
- 位置：配送追踪/监控调 `iotGatewayProxy/{deviceSn}/buildingManager/om-api/EvizServer` 获取机器人坐标，3 秒缓存。

## 十二、售后（退款/投诉）

售后状态：0 待处理 / 2 已拒绝 / 3 已退款 / 4 已处理(投诉)；类型 refund 退款 / complaint 投诉。

### 12.1 申请退款/投诉（用户）
- 地址：POST /api/refund/apply
- 鉴权：需登录
- 入参：`{ "order_id":7, "type":"refund|complaint", "reason":"..." }`
- 出参：`{ "id":1, "type":"refund", "status":0 }`
- 说明：仅已送达(3)/已完成(4)/配送异常(6)可申请；退款金额默认订单全额。
- 错误：404 订单不存在 / 400 当前状态不可申请。

### 12.2 我的售后记录（用户）
- 地址：GET /api/refund/list
- 鉴权：需登录
- 出参：售后记录数组（含 order_no、type、reason、amount、status、status_text、merchant_reply）

### 12.3 商家售后列表
- 地址：GET /api/merchant/refunds?status=0
- 鉴权：需商家
- Query：status 可选（0 待处理等），默认全部，待处理优先
- 出参：售后数组（含 order_no、landmark_name、type、reason、amount、status_text、merchant_reply）

### 12.4 商家售后详情
- 地址：GET /api/merchant/refund/detail?id=1
- 鉴权：需商家
- 出参：售后单 + 订单信息（order_no、total_amount）

### 12.5 商家处理售后
- 地址：POST /api/merchant/refund/handle
- 鉴权：需商家
- 入参：`{ "id":1, "action":"approve|reject|reply", "amount":5(可选,退款同意时可改), "reply":"理由/回复" }`
- 说明：退款 approve → 状态3 已退款、订单→7 已退款（金额默认全额，传 amount 可部分退款）；reject → 状态2（需理由）；投诉 reply → 状态4 已处理。
- 错误：404 售后单不存在 / 400 已处理或缺少理由。
