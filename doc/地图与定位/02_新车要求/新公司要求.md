# 新公司要求

2026-10-27 · 项目组

## 一、地图

### 1. 分区与加载

| #   | 指标     | 要求                                     | 验证方法                                       |
| --- | -------- | ---------------------------------------- | ---------------------------------------------- |
| 1   | 分区方式 | 一张逻辑图 + 物理分块，一个校区切 3–4 块 | 建两块相邻区域，测量拼缝处同名点坐标差         |
| 2   | 跨块任务 | 从一块派单到另一块不中断，不需人工切图   | 跨区块下发任务，记录中断次数与是否需人工切换   |
| 3   | 按需加载 | 只加载当前块和相邻块，不整图进内存       | 监测运行内存，应与车辆当前位置相关、与总图面积无关 |
| 4   | 单块加载 | 打开一块 ≤10 秒，切块不卡                | 现场计测单块图加载耗时                         |
| 5   | 增补一块 | 补扫不动其他块，老点位不漂               | 新增一块后复测相邻区域老点位坐标               |

### 2. 扫图参数

| #   | 指标     | 要求                             | 验证方法                                 |
| --- | -------- | -------------------------------- | ---------------------------------------- |
| 1   | 单图容量 | ≥25 万㎡，分辨率 ≤0.05 米/格     | 现场建 25 万㎡ 图一幅，记录保存结果与耗时 |
| 2   | 全场容量 | ≥70 万㎡                         | 全场分块加载，检查相邻块拼接一致性       |
| 3   | 建图工时 | 单块 ≤5 小时，全场 ≤1.5 个工作日 | 计测自开扫至出图的工时，不含返工与封路   |
| 4   | 增量更新 | 改路后补扫 ≤30 分钟，不整图重扫  | 指定 5000 ㎡ 区域改道，计测补扫耗时      |

工时按幅宽 15 米、速度 1 米每秒估：25 万㎡ 走 16.7 公里约 4.6 小时，67 万㎡ 走 44.7 公里约 12.4 小时。对方报的工期明显更长，就让他们给明细。

### 3. 扩建与回滚

| #   | 指标     | 要求                                     | 验证方法                         |
| --- | -------- | ---------------------------------------- | -------------------------------- |
| 1   | 失败回滚 | 扩建失败可回滚，上一版必须还在，能一键恢复 | 人为触发扩建失败，验证能否退回上一版 |

## 二、精度

### 4. 定点停靠精度

| #   | 指标             | 要求                                                                                       |
| --- | ---------------- | ------------------------------------------------------------------------------------------ |
| 1   | 定点停靠精度     | 按车相对地面量：停到指定点位，每次偏差 ≤5 厘米；同一目标点反复停 20 次，离散度 ≤5 厘米（1σ）；车身姿态与标定方向差 ≤5° |
| 2   | 地图与实地一致性 | 图上标注点位与实地量测点相差 ≤5 厘米（抽查 20 点）                                          |
| 3   | 跨区与扩建一致性 | 重叠区同名点 ≤5 厘米；500 米环线闭环 ≤10 厘米；重扫不得静默改动老点位，改动超 5 厘米须给迁移清单 |

停靠这一档不看场景，一律 5 厘米。

5 厘米按车相对地面量：在地上定一个点，车反复停 20 次，每一次都要落在 5 厘米内。这一档要靠第 5 节那套绝对基准（卫星或控制点、全图一套坐标系）才拿得住，只靠激光跑久了会漂，报价前请确认能做到。

### 5. 绝对定位

| #   | 指标       | 要求                                                         | 验证方法                         |
| --- | ---------- | ------------------------------------------------------------ | -------------------------------- |
| 1   | 基准来源   | 卫星（GPS/北斗/RTK）或控制点提供绝对约束，全图共用一套坐标系 | 索取定位方案说明及标称精度       |
| 2   | 冷启动     | 断电再开机，≤5 分钟重新定位可用                              | 断电重启，计测至可接受任务的时间 |
| 3   | 重启一致性 | 同一点坐标，重启前后差 ≤5 厘米                               | 重启前后各测同一点坐标，比对差值 |
| 4   | 丢星兜底   | 卫星被挡时靠激光和惯导继续走，不停车                         | 在树荫、楼间等遮挡路段各测试一次 |

## 三、运营

### 6. 多单配送

| #   | 指标     | 要求                                         | 验证方法                             |
| --- | -------- | -------------------------------------------- | ------------------------------------ |
| 1   | 单趟点数 | ≥6 个不同点位，一次下发，途中不回仓          | 一次下发 6 单 6 点任务，记录全程是否回仓 |
| 2   | 排序权重 | 订单数量与路线距离两个权重同时参与，比例可配 | 调整权重配置，比对生成的配送顺序         |
| 3   | 货仓装载 | 6 单同时装下，货格独立可开                   | 以 6 单实物装载，验证各货格独立开启      |
| 4   | 无人取货 | 超时后跳过该点继续送，不整趟作废             | 点位无人取货，验证超时后是否跳过         |

### 7. 异常停靠

| #   | 指标     | 要求                                                       | 验证方法                                 |
| --- | -------- | ---------------------------------------------------------- | ---------------------------------------- |
| 1   | 到点被占 | 点位被车、货、人占住时先等，不强行贴点，等待位置不阻主通道 | 在点位放置障碍物，观察停车位置与等待行为 |
| 2   | 等待提示 | 等待期间灯光或语音提示                                     | 修改等待时长配置，验证按新时长执行       |
| 3   | 超时处理 | 超时自动换备用点（同点 5 米内）并上报后台，不需人工重派    | 持续占用点位，验证是否切换备用点并上报事件 |
| 4   | 占位解除 | 障碍移开后自动回原点位继续任务                             | 移除障碍物，验证是否返回原点位继续任务   |
| 5   | 事件记录 | 占位事件带时间、位置上报，后台可查                         | 核对后台事件记录的时间与位置             |

## 四、接口

### 8. 状态推送

| #   | 指标     | 要求                                                             | 验证方法                     |
| --- | -------- | ---------------------------------------------------------------- | ---------------------------- |
| 1   | 事件覆盖 | 到达点位、停靠完成、开仓、取件完成、离点、异常（被占、故障、低电）均主动上报 | 逐一触发，核对是否全部收到   |
| 2   | 推送内容 | 任务号、车辆号、点位号、事件类型、时间戳、位姿，字段齐全           | 抽查各事件的字段是否完整     |
| 3   | 推送时延 | 事件发生到接收 ≤2 秒                                             | 打点计测                     |
| 4   | 重试补偿 | 推送失败自动重试；断线重连后补推未送达事件，不丢事件               | 断网一分钟后恢复，核对事件是否补齐 |
| 5   | 推送日志 | 每次推送有时间、事件、结果记录，可查                               | 核对日志与实测事件是否一致   |

以主动推送为主，轮询接口只作核对，不作为任务状态的唯一来源。

### 9. 开放程度

| 层面     | 要求                                                         |
| -------- | ------------------------------------------------------------ |
| 任务调度 | 用户自己选车、选点、定顺序，厂商调度算法可以旁路             |
| 路径     | 用户自己给途经点或完整路径，不被强制走厂商算出的路线         |
| 定位     | 实时位姿可读，能拿自己的定位结果覆盖                         |
| 动作     | 用户可以逐条下发前进、转向、停车、开仓                       |
| 回传     | 位姿、电量、货仓状态、故障码实时可读                         |
| 交付     | 接口文档、调试账号、能跑通的最小示例（发一条动作、读回位姿） |

### 10. 地图元数据

| #   | 指标       | 要求                                                         | 验证方法             |
| --- | ---------- | ------------------------------------------------------------ | -------------------- |
| 1   | 元数据接口 | 分辨率、原点、地图 ID、版本号、创建与更新时间、校验和，六项齐全 | 调接口逐项核对字段   |
