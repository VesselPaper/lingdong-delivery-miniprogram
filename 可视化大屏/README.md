# 零栋无人送餐 · 数据可视化大屏

无人车实时调度大屏：一块屏幕上同时看**校园 3D 立体地图 + 每台无人车的位置动向 + 订单/批次状态**。
用浏览器（Chromium 内核）渲染，主机只负责「开机全屏打开这个页面」，7×24 挂着即可。

---

## 一、怎么打开

大屏由后端直接托管，**不需要单独起服务**：

| 场景 | 地址 |
|---|---|
| 本机/局域网看（推荐） | `http://<后端IP>:3000/dashboard` |
| 本机 | `http://127.0.0.1:3000/dashboard` |
| 演示模式（模拟车辆，机器人没开工也能演示） | `http://<后端IP>:3000/dashboard/?demo=1` |

> `/dashboard` 会 301 跳到 `/dashboard/`（index.html 用的是相对路径，必须带斜杠）。
> 也可以直接双击 `index.html`（file:// 打开），此时页面会自己去连 `http://127.0.0.1:3000` 取数。
> kiosk 全屏启动：`deploy/启动大屏.bat`（Edge/Chrome 全屏 + 独立配置目录，供看门狗识别拉起）。

## 二、设计说明（为什么长这样）

方向：**数字孪生全息风 / 科技调度屏**（深空蓝底 + 青色霓虹 + 发光网格 + 玻璃楼体）。
与两套小程序（明亮零售白底风）刻意区分——大屏是 7×24 挂墙的调度工具，暗底高对比更适合远距离盯看：

| 设计要素 | 取值 |
|---|---|
| 页面底 | 深空蓝 `#040a16` → `#071022` 渐变 + 青色网格纹理 |
| 主色（青） | `#37e0ff`（发光描边 / 进行中信息） |
| 强调蓝 | `#1677ff`（配送中 / 车辆） |
| 提醒橙/绿/红 | 只承担状态语义（待上货 / 充电 / 异常 / 超时） |
| 地图 | WebGL 真 3D：玻璃楼体 + 青色描边 + 发光雷达走廊 + 白色小车（带定位光环/光柱/数据牌） |
| 字体 | 中文微软雅黑；数字 Consolas 等宽 + 发光 |
| 动画 | 位移走 `transform` / WebGL 矩阵；无第三方图表库 |

**渲染器自动选择**（`js/map3d-entry.js`）：

1. **Map3DGL（WebGL 真三维，默认）**：自由旋转/俯仰/缩放，楼栋按真实轮廓挤出，车辆实时移动；
2. **Map3DFlat（Canvas 2.5D 斜轴测）**：WebGL 不可用或着色器失败时自动回退，不黑屏；
3. **Leaflet（在线矢量地图）**：`?calib=1` 标定工具专用 + 最终兜底。

顶栏地图区的 `mapTip` 会写明当前用的是哪一种渲染。

## 四、数据从哪来

大屏只调后端**只读聚合接口**（免登录，5 秒缓存）：

```
GET /api/dashboard/overview
```

它把下面这些聚合成一份，并**剔除了手机号/地址等敏感字段**：

| 内容 | 后端来源 |
|---|---|
| 店铺状态、运行档位、是否真实平台 | `shops` 表 + `services/runtime` |
| 订单统计（今日订单/待接单/待上货/配送中/待取货/异常…） | `computeStats()`（与商家首页同一份口径） |
| 路网 / 点位 / 车辆实时坐标 / 进行中路线 | `platform.getMapOverview()` |
| 无人车列表（在线/电量/机器状态） | `platform.getDeviceList()` |
| 进行中批次、取餐超时告警 | `delivery_batches` / `orders` |

**车辆高频位置**（地图上的车"实时走"靠它，1 秒一次）：

```
GET /api/dashboard/robot-positions
```

只返回在线车的坐标 + 朝向（与 overview 的 `map.robots` 同一坐标空间），后端有 1s 缓存
（`DASHBOARD_ROBOTS_CACHE_MS` 可调），不会每请求都打平台。

> ⚠️ 车辆移动依赖**两个接口配合**：overview 提供地图/路线等静态上下文（5s），
> robot-positions 提供车辆实时坐标（1s）。只连得上 overview 时车不会动——这正是
> 之前"车在地图上不动"的根因（前端有轮询代码，后端接口没实现，2026-10-05 已补上）。

### 地图底图（3D 场景用静态几何，不依赖平台底图）

3D 地图的楼栋/道路来自 `assets/map-calibration.js`（本地静态数据），因此
**平台底图接口不可用时也能出图**；实时车辆/路线由上面两个接口叠加。

**雷达底图（激光可通行区）默认关闭** —— 按负责人要求，大屏只保留校园道路 + 小车图标。
需要对齐调试时，点工具栏「**雷达图**」按钮临时打开（能对照"机器人激光测绘出的可通行区，有真实路宽"）。
`/api/dashboard/map-image` 后端代理（OSS 签名直链时效极短）仍保留，供回退渲染使用。

### 坐标映射（关键：不要再用 bbox 拉伸）

平台 `building/mapInfo` 下发 **ROS 栅格地图元数据** `metadata`
（`origin`、`resolution`、`width=5786`、`height=5406`，与 `map-calibration.js` 的 `radar_full_size` 一致），
它就是「平台世界坐标（米）→ 地图像素」的**权威映射**：

```
px = (x - origin_x) / resolution
py = height - (y - origin_y) / resolution      # 图像 y 向下，origin = 左下角
```

- 大屏经由 `map.meta` 使用它；**拿不到 meta 时才退回 bbox 拉伸**（旧方案）。
- 实测差异：bbox 拉伸的坐标误差 **13~23 米**（这就是"车对不准路"的根因）；
  换成 metadata 后，平台 12 个点位 + 38 个固定路径节点投到激光底图走廊上 **50/50 零距离命中**。
- **`robotpose` 本身就是地图像素坐标**（x 右、y 下）：接口直接给 `px/py`，前端**不需要任何标定**投放。
- `POS_CAL`（robotpose→米的相似变换）**已废弃**：它由 2 个点拟合 4 参数（必然精确，不算验证），
  且平台重标定地图后失效。

### 车辆贴路（路网吸附）

雷达图的路面**有宽度**，3D 图的路是**中心线**（像导航 App）。因此显示时把车辆位置
**投影到机器人真实路网**（平台「固定路径」graph，经 metadata 精确投到场景像素）上：

- 该路网**不显示**，只作吸附网；车永远落在它真正走的那条路上（等价于 GPS 贴路）。
- 偏离路网超过 `SNAP_MAX_M`（默认 12m，定位异常）时不硬拉，照真实位置显示，避免"飞出路面又被拽回"。
- 贴路成功时，车辆数据牌的状态后缀会显示「· 已贴路」。

## 五、部署到主机（三步）

1. 主机装好 **Chrome 或 Edge**，能打开 `http://<后端IP>:3000/dashboard`；
2. 大屏由后端直接托管（无独立启动脚本）：先启动后端（根目录 `启动服务器.bat`，API/管理员/大屏同端口 3000），
   再双击 `deploy/启动大屏.bat` 以 kiosk 全屏打开；
3. 管理员身份运行 `deploy\安装开机自启.ps1` —— 注册登录自启任务，之后开机自动进大屏。

> 大屏主机与后端需在同一网络；后端在别的机器上时，在 `启动大屏.bat` 同目录放 `服务器地址.txt`，
> 第一行写 `服务器IP:端口`（如 `192.168.1.10:3000`）即可自动改连。

## 六、长跑稳定性（对应「浏览器久跑会不会出问题」）

| 措施 | 说明 |
|---|---|
| 固定 DOM | 所有列表都是「复用节点 + 改文本」，绝不做无限追加 |
| 无图表库 | 不初始化/常驻任何图表实例，状态分布是纯数字卡 |
| 静态层不重绘 | 楼栋/道路/点位只在标定数据变化时重建；车辆节点按 `device_sn` 复用 + 每帧插值 |
| 位移走合成层 | WebGL 相机矩阵 + transform，不触发布局重排 |
| 每日重载 | 每天 04:00 整页 `location.reload()` 释放累积渲染状态 |
| 内存兜底 | 堆内存超 800MB 主动重载（Chrome 专有 API，取不到就跳过） |
| 断连不黑屏 | 取数失败保留上一屏内容，只在右上角标「连接中断」 |
| 看门狗 | 后端挂了自动拉起；kiosk 浏览器退了自动重开 |

### 可调参数

| 参数 | 位置 | 默认 | 作用 |
|---|---|---|---|
| `POLL_MS` | `js/dashboard.js` | 5000 | overview 取数间隔 |
| `ROBOT_POLL_MS` | `js/dashboard.js` | 1000 | 车辆位置轮询间隔 |
| `RELOAD_HOUR` | `js/dashboard.js` | 4 | 每日整页重载时刻 |
| `MEM_LIMIT` | `js/dashboard.js` | 800MB | 内存兜底阈值 |
| `MAX_ROBOTS / MAX_BATCHES / MAX_ALERTS / MAX_EVENTS` | `js/dashboard.js` | 6/4/3/8 | 各列表最大行数（固定 DOM 规模） |
| 地图初始视角/高度 | `js/map3d-gl.js` 的 `opts` | el=65, heightScale=0.58 | 俯仰角 / 楼高夸张倍数（界面滑块可调） |
| 车辆平滑插值 | `js/map3d-gl.js` 的 `kSmooth` | `1-exp(-dt·2.6)` | 时间常数 ≈0.38s；越小越"飘"，越大越"紧跟" |
| 轨迹拖尾长度 | `js/map3d-gl.js` 的 `trail` 上限 | 30 点（≈5s） | 采样间隔 0.18s / 最小位移 0.35m |
| 贴路吸附上限 | `js/map3d-gl.js` 的 `SNAP_MAX_M` | 12 | 偏离路网超过该米数就不硬拉（照真实位置显示） |
| 雷达底图默认开关 | `js/map3d-gl.js` 的 `opts.ground` | false | 大屏默认不显示雷达图；工具栏「雷达图」可临时打开 |
| 渲染器回退 | `js/map3d-entry.js` | 自动 | WebGL 失败自动降级 2.5D |
| `DASHBOARD_CACHE_MS` | 后端 env | 5000 | overview 接口缓存 |
| `DASHBOARD_ROBOTS_CACHE_MS` | 后端 env | 1000 | 车辆位置接口缓存 |
| `DASHBOARD_PUBLIC` | 后端 env | 1 | 0 时大屏接口需管理员登录（上线建议设 0） |

## 七、排查

| 现象 | 原因 / 处理 |
|---|---|
| 页面是裸 HTML、没有样式 | 用了 `/dashboard`（无斜杠）导致相对路径失效 —— 用 `/dashboard/` |
| 地图区域提示「WebGL 不可用」或空白 | 浏览器不支持 WebGL / 显卡驱动问题 → 自动回退 2.5D；kiosk 用 Edge 一般没问题 |
| 地图上只有静态楼栋、车不动 | 车辆高频接口连不上：看后端日志确认 `/api/dashboard/robot-positions` 返回正常；机器人离线/无配送任务时平台不返回坐标，属正常，可用 `?demo=1` 看效果 |
| 地图有车但位置偏了 | 3D 场景用的是本地标定几何（map-calibration.js），点位整体偏移说明标定数据与平台 bbox 不对齐——检查 `assets/map-calibration.js` 的 transform / 与平台 `bbox` 是否一致 |
| 车辆/路线都没有 | 该场地暂无进行中批次，属正常 |
| 底图（radar-ground）不显示 | `assets/radar-ground*.png` 缺失或未随仓库同步 |
| 屏幕上字看着小 | 按 1920×1080 调的；4K 屏给 kiosk 加 `--force-device-scale-factor=1.5` |
| 拖拽/缩放不跟手 | 页面固定 1920×1080 等比缩放，非 1:1 窗口下手感会偏差（已知取舍） |

## 九、屏幕自适应与 3D 地图说明

### 固定画布 + 等比缩放

页面按 **1920×1080** 固定设计，JS（`fitScreen()`）按窗口算 `scale = min(w/1920, h/1080)` 后居中缩放。
主机是 1080p / 2K / 4K 都得到完全一致的版式比例。要改画布尺寸，需同时改 CSS 的 `.screen`
与 JS `fitScreen()` 里的 1920/1080。

### 3D 地图怎么构建（map3d 系列）

- **坐标系**：世界坐标 = 雷达底图像素（x 右、y 下），高度 z 向上；楼高 = 米 × `scale_px_per_m`。
- **楼栋**：OSM 真实轮廓（`map-calibration.js` 的 `buildings[].ring`）挤出成玻璃体块，
  配送楼（名字含"栋"）青色描边更亮 + 楼顶橙色钉标；被路线压住的楼可配置 `visual_offset_m`
  做**视图偏移**（虚线 + 圆圈标出真实位置，不显示文字）。
- **道路**：OSM 参照（灰，亮灰而非暗蓝——暗蓝会被雷达走廊同色吃掉），宽度按米换算。
- **雷达走廊**：机器人可通行区骨架（青绿发光），`paths` 开关控制。
- **车辆**：白色小车 + 车底定位光环 + 垂直光柱 + 数据牌（状态/电量），位置按时间归一化插值
  （`1-exp(-dt·2.6)`，两次定位之间匀速滑行、不"追一下停一下"），车后带**行驶轨迹拖尾**
  （青蓝渐变、越新越亮，最多 30 个采样点 ≈5s）；离线即清空拖尾，避免重新上线时拉直线。
- **实时路线**：平台下发的批次途经点 → 贴路折线（道路拓扑 Dijkstra + 吸附 + 抽稀），橙色扁带，
  默认关闭（`route` 开关），`routeFlow` 可开流光。

### 交互

- 左键拖动 = 环绕旋转；滚轮 = 缩放；右键 / Shift+拖动 = 平移；双击 = 复位。
- 地图头部**两行**：第一行「标题 + 图例 + 状态提示」，第二行控制工具栏
  （俯仰 / 高度滑块 | 环绕 / 跟随 / 楼体透明 / 测绘线 / 规划路线 / 校园道路 / 标注 / 回到校园）。
  图例项与按钮一律 `white-space:nowrap` + `flex:none` —— 面板变窄时**不会**把文字挤成竖向单字。

### 平台下发的一处数据噪音

`building/mapInfo` 除了真点位，还会把路网本身作为一个名叫**「固定路径」**的点位下发 ——
前端在入库前统一剔除（`usableLandmarks()`），`mapTip` 的点位数也据此统计。

### 标定工具（?calib=1，Leaflet 模式）

地址栏 `/dashboard/?calib=1`：把平台点位拖到在线地图上的真实位置，点「计算新变换」输出
相似变换参数（写入 dashboard.js 的 `CALIB_T` / 或标定文件 transform）。3D 模式不需要它——
3D 场景几何已由 `mapfit` 流程预生成到 `map-calibration.js`。
