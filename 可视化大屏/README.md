# 零栋无人送餐 · 数据可视化大屏

无人车实时调度大屏：一块屏幕上同时看**校园地图 + 每台无人车的位置动向 + 订单/批次状态**。
用浏览器（Chromium 内核）渲染，主机只负责「开机全屏打开这个页面」，7×24 挂着即可。

---

## 一、怎么打开

大屏由后端直接托管，**不需要单独起服务**：

| 场景 | 地址 |
|---|---|
| 本机/局域网看（推荐） | `http://<后端IP>:3000/dashboard` |
| 本机 | `http://127.0.0.1:3000/dashboard` |
| 演示模式（模拟车辆，机器人没开工也能演示） | `http://<后端IP>:3000/dashboard/?demo=1` |

> `/dashboard` 会 301 跳到 `/dashboard/`（index.html 用的是相对路径，必须带斜杠）。
> 也可以直接双击 `index.html`（file:// 打开），此时页面会自己去连 `http://127.0.0.1:3000` 取数。

## 二、设计说明（为什么长这样）

方向：**仪器面板 / 技术编辑风（Instrument Panel）**。目标是"像一套真的调度工具"，
而不是"像 AI 生成的大屏"。为此刻意避开了这些默认套路：

| 常见 AI 大屏写法 | 本项目的做法 |
|---|---|
| 蓝紫渐变背景、径向辉光 | 冷调浅灰蓝底 `#f4f6fa` + 纯白卡片 |
| 霓虹发光的暗色科技屏 | 明亮零售：白底 + 蓝主色，橙只作提醒色 |
| 暖炭黑 + 橙色（AI 助手的品牌配色） | 不用：那不是校园便利店该有的气质 |
| 渐变裁切的大标题 | 实色大字 + "蓝牌白字"店招 + 微型小字 |
| 到处圆角玻璃卡片、统一 12~16px 圆角 | 白卡 + 10px 圆角；只有地图卡带一点投影（它是主体） |
| 满屏胶囊 pill 徽章 | 小方角标 / 纯文字 + 前置色块 |
| 环形图（饼图） | 堆叠状态条 + 数值清单（小数量下更可读） |
| 装饰性多强调色（青/绿/紫/橙…） | 蓝为主色；橙/绿/红只承担状态语义 |
| 居中对称、三栏等宽卡片 | 22% / 1fr / 28% 非对称栅格，地图是主体 |
| 数字用系统比例字 | 等宽字 + tabular-nums，字号拉大、字距收紧 |
| 动画用 `left/top` | 位移走 `transform: translate3d`（只走合成层） |

字体：`Bahnschrift`（Windows 自带 DIN 系，技术感）承载西文与数字，中文回落到微软雅黑 / 苹方。
**无任何第三方前端依赖**（ECharts 已移除），页面上所有图形都是原生 HTML/CSS/SVG。

大屏向**零栋铺子门店**的视觉靠拢，依据是天府股交中心公示的两家门店实拍：

| 门店元素 | 取色 | 大屏里的用法 |
|---|---|---|

## 四、数据从哪来

大屏只调后端一个只读聚合接口（免登录，5 秒缓存）：

```
GET /api/dashboard/overview
```

它把下面这些聚合成一份，并**剔除了手机号/地址等敏感字段**：

| 内容 | 后端来源 |
|---|---|
| 店铺状态、运行档位、是否真实平台 | `shops` 表 + `services/runtime` |
| 订单统计（今日订单/待接单/待上货/配送中/待取货/异常…） | `computeStats()`（与商家首页同一份口径） |
| 校园地图底图 | `GET /api/dashboard/map-image`（后端代理，见下） |
| 路网 / 点位 / 车辆实时坐标 / 进行中路线 | `platform.getMapOverview()` |
| 无人车列表（在线/电量/机器状态） | `platform.getDeviceList()` |
| 进行中批次、取餐超时告警 | `delivery_batches` / `orders` |

### 为什么地图要后端代理

平台 `building/mapInfo` 返回的底图是 **OSS 签名直链，有效期极短**（实测取到手时已过期 14 秒，
直接下载 403）。把这条 URL 丢给浏览器，大屏会间歇性白图。因此：

- 后端 `/api/dashboard/map-image` 下载底图字节并缓存（默认 10 分钟），前端只认这个同源稳定地址；
- 缓存未命中或签名过期时，`platform.getMapImageBytes()` 会强制刷新 mapInfo 取新签名再试一次。

## 五、部署到主机（三步）

1. 主机装好 **Chrome 或 Edge**，能打开 `http://<后端IP>:3000/dashboard`；
2. 双击 `deploy\启动大屏.bat` —— 全屏 kiosk 打开大屏，用独立浏览器配置目录，不干扰日常浏览器；
3. 管理员身份运行 `deploy\安装开机自启.ps1` —— 注册登录自启任务，之后开机自动进大屏。

> 大屏主机与后端需在同一网络；若后端在别的机器上，请把 `启动大屏.bat` 里的 `URL` 改成后端实际 IP。

## 六、长跑稳定性（对应「浏览器久跑会不会出问题」）

| 措施 | 说明 |
|---|---|
| 固定 DOM | 所有列表都是「复用节点 + 改文本」，绝不做无限追加，绝不会像聊天页那样越用越卡 |
| 无图表库 | 不初始化/常驻任何图表实例，状态分布是纯 CSS 条 |
| 静态层不重绘 | 路网/点位只在底图或数据签名变化时重画；车辆节点按 `device_sn` 复用 |
| 位移走合成层 | 车辆用 `transform: translate3d` 移动，不触发布局重排 |
| 每日重载 | 每天 04:00 整页 `location.reload()` 释放累积渲染状态（数字标牌行业标配） |
| 内存兜底 | 堆内存超 800MB 主动重载（Chrome 专有 API，取不到就跳过） |
| 断连不黑屏 | 取数失败保留上一屏内容，只在右上角标「连接中断」 |
| 看门狗 | 后端挂了自动拉起；kiosk 浏览器退了自动重开 |

### 可调参数

| 参数 | 位置 | 默认 | 作用 |
|---|---|---|---|
| `POLL_MS` | `js/dashboard.js` | 5000 | 取数间隔 |
| `RELOAD_HOUR` | `js/dashboard.js` | 4 | 每日整页重载时刻 |
| `MEM_LIMIT` | `js/dashboard.js` | 800MB | 内存兜底阈值 |
| `MAP_PAD` | `js/dashboard.js` | 0 | 坐标→图片百分比内边距（底图与点位若整体偏移，微调它） |
| `HEADING_OFFSET` | `js/dashboard.js` | 90 | 车头朝向基准角（车头方向反了就改这个） |
| `MAX_ROBOTS / MAX_BATCHES / MAX_ALERTS / MAX_EVENTS` | `js/dashboard.js` | 6/4/3/8 | 各列表最大行数（固定 DOM 规模） |
| 底图亮度/压暗 | `css/dashboard.css` 的 `.mapWrap > img` 与 `.mapWrap::after` | — | 底图太亮抢主体、太暗看不清点位名时调这两个值 |
| `DASHBOARD_CACHE_MS` | 后端 env | 5000 | 聚合接口缓存 |
| `DASHBOARD_MAP_CACHE_MS` | 后端 env | 600000 | 底图字节缓存 |

## 七、排查

| 现象 | 原因 / 处理 |
|---|---|
| 页面是裸 HTML、没有样式 | 多半是用了 `/dashboard`（无斜杠）导致相对路径失效 —— 用 `/dashboard/`，或确认后端是 `express.static` 托管（不要自建 `/dashboard` 路由，会和斜杠版互相重定向成死循环） |
| 地图区域提示「底图加载失败，正在重试…」 | 后端底图代理没取到：看后端日志；确认平台凭据与网络，必要时重启后端刷新底图缓存 |
| 地图有点位但车辆不动 | 没有「配送中(50~79)」的任务时平台不会返回车辆坐标，属正常；可用 `?demo=1` 看效果 |
| 车辆/路线都没有 | 该场地暂无进行中批次，属正常 |
| 点位与底图整体错位 | 调 `MAP_PAD` |
| 屏幕上字看着小 | 这是按 1920×1080 调的；换 4K 屏时把 CSS 里的根字号/各 `font-size` 等比放大，或给 kiosk 加 `--force-device-scale-factor=1.5` |

## 九、屏幕自适应与地图说明

### 固定画布 + 等比缩放

页面按 **1920×1080** 固定设计，JS（`fitScreen()`）按窗口算 `scale = min(w/1920, h/1080)` 后居中缩放。
好处：主机是 1080p / 2K / 4K 都得到完全一致的版式比例，**不会再出现"窗口窄一点、某个值被挤出卡片"**。
要改画布尺寸，需同时改 CSS 的 `.screen` 与 JS `fitScreen()` 里的 1920/1080。

（另外 `.kv b`、`.robotName` 等两端对齐的行都加了 `min-width:0` + 省略号兜底，
即使将来改画布尺寸也不会撑破卡片。）

### 地图为什么长这样

中间那张图是**平台（越凡）下发的机器人建图**：浅蓝区域 = 机器人可通行区域，所以边缘呈锯齿状，
观感偏"扫描图"。**它不能随便换掉** —— 车辆坐标（`eviz robotpose`）、点位与路网 pose 都在**同一套坐标系**里，
前端是按 `bbox` 把坐标映射成图像百分比的；换一张无关的地图，车就会跑偏。

**当前已换成「真实实时可拖拽地图」方案（Leaflet + 高德瓦片）：**

- 渲染：`vendor/leaflet.js`（本地内置，离线可用）+ 高德 z=18 免费瓦片（中文标注、POI），
  **可拖拽、可缩放**（+/- 按钮缩放；滚动缩放已关闭，避免大屏误触），地图头部有「回到校园」复位按钮
- 图层：12 个平台点位（圆点：店铺=橙 / 其余=招牌蓝，悬停显示名称）、路网（浅蓝细线）、
  配送路线（蓝色虚线 + 停靠序号）、无人车（蓝色箭头 + 编号，随轮询每 5 秒实时更新）
- 坐标：平台坐标系 → GCJ-02 的变换常量在 `js/dashboard.js` 的 **`MAP_CALIB`**；
  推导脚本见 `deploy\抓取校园底图.ps1`（瓦片抓取）与 `deploy\校准并生成底图.ps1`（参数推导）

**校准依据与精度（重要）**：平台没有公开机器人地图的地理参考，坐标只有相对值，所以对齐是**推出来的**：

| 结论 | 依据 |
|---|---|
| 比例 1 平台单位 = 1 米（`S=0.09`，即 1.945 px/m） | 走廊主轴长度 ≈ 269 单位，与图上对应路网长度吻合 |
| 旋转 `Rot=0`（正北朝上） | 平台走廊主轴是竖直的，且与图上一条南北向步行道平行；试过 −17° 反而斜穿路网 |
| 平移 `(Tx,Ty)` | 以**零栋铺子 = 东苑三栋一楼**为锚点：平台"商铺上货"点应与图上"东苑学子超市"重合 |

**精度约 ±20~30m**（相当于 1~2 栋楼）。想要更准，只需一个现场确认：
让零栋的人看一眼 "图上「东苑学子超市」是不是零栋铺子" —— 若不是，改 `MAP_CALIB` 里的 `tx/ty` 平移即可。

> ⚠️ 版权：高德瓦片仅适合校内演示。正式对外发布请改用高德 JS API（带 key）或自有授权地图。
> ⚠️ 已知限制：页面整体做了「固定 1920×1080 等比缩放」，在缩放 ≠ 1 的窗口里**拖拽手感会偏差**
> （1920×1080 原生窗口下是准确的）。Leaflet 不支持放在 CSS transform 缩放的容器里，属已知取舍。

### 平台下发的一处数据噪音

`building/mapInfo` 除了真点位，还会把路网本身作为一个名叫**「固定路径」**的点位下发 ——
它会在角落露出一截被裁掉的标签。前端在入库前统一剔除（`usableLandmarks()`），
`mapTip` 的点位数也据此统计。
