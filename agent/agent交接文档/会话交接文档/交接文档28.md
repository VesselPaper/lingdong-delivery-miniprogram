## 三、关键已核实结论

1. **平台目前有两张图**：
   - 小图 `1257237128126592_zcsdb3dd6396c824_1d-99`：5786×5406，resolution 0.05，origin `[-37.331894,-137.285003]`，12 个点位。
   - 大图 `1257237128126592_zcsdb3dd6396c824_1d-98`：16042×16677，resolution 0.05，origin `[-550.15678,-142.087765]`，17 个点位。
   - **现在业务与大屏都用小图**（`backend/.env` 的 `PLATFORM_ACTIVE_MAP_ID` 已锁小图）。西苑 2/3/4、5/6 栋**只在大图上**，目前是有意过滤掉的。
2. **换大图的两个动作**（扩建完成后）：把 `PLATFORM_ACTIVE_MAP_ID` 改成大图 mapId（或留空恢复"跟随在线车所在图"），并重新标定大图底图。**不重做标定会再次整体偏移。**
3. **东苑点位在两张图上各存一份**（坐标差几厘米），按 `name|x|y` 去重认不出来 —— 必须在源头按 `mapId` 过滤。
4. **`status_events` 的 id 顺序不等于时间顺序**（实测 id 31 是 10-08、id 30 是 09-28），排序必须 `created_at DESC, id DESC`。
5. **`el=22` 时主要遮挡物是墙不是楼顶**：墙本来就是 26% alpha。楼顶透明调过、能看见，但"通透感"主要来自墙。若还要更透，下一步动墙体 alpha。
6. **日志写入逻辑一行没动**：仍是 `services/statusEvents.js` 每 `STATUS_EVENTS_MS`（默认 2500ms）轮询 + `audit()` 留痕。本轮只做"读"。
