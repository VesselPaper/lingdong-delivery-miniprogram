## 1. 项目是什么

**校内快递配送机器人**（四川师范大学校内无人送餐/快递车）：
- **用户端**微信小程序（18 页）：浏览/加购/下单、微信支付（当前模拟）、订单管理、机器人配送追踪、取餐码取餐、地址/活动。
- **商家端**微信小程序（19 页）：登录、工作台、接单（模拟扫码配单）、一车多单配单/上货、订单与售后、商品管理、配送监控（真实机器人状态）、店铺设置。
- **后端**：Node.js + Express + SQLite，单进程同端口 3000 托管三个服务：
  - 小程序 API：`/api`
  - 管理员网页：`/admin`（首次打开输管理员令牌，默认 `123456`，可 env 覆盖）
  - 数据可视化大屏：`/dashboard`（科技风 + 3D 地图 Map3D）
- **对接**：真实 robox 开放物流平台（生产 `robox.eventec.cn`）；`PLATFORM_MOCK=false` 走真实，可切本地 Mock 演示。

远端仓库：`github.com/VesselPaper/lingdong-delivery-miniprogram`

## 5. DSH（开发机 AI 助手）模型适配备忘：V4 与 V4.1（视觉/纯文本）并存

> 这是**开发机 DSH harness 配置**（`C:\Users\TIME\.dsh\settings.yaml`），不是本项目代码，但直接影响下一个对话用什么模型干活，记在这里防止再踩 400 坑。

- **原理**：DSH 按每个模型的 `input` 能力声明决定发不发图/能不能读图。纯文本模型声明 `input: ["text"]` 时，DSH 自动把图片投影/剥掉再发给模型（不会报 400）；视觉模型声明 `input: ["text","image"]` 时正常发图、可用 `read_image` 读图。
- **已落地**（settings.yaml 的 `xhy-agent-plan` provider 内）：
  - `ark-code-latest`（平台自动路由别名，落哪个模型不确定）→ `input: ["text"]` 纯文本声明，**图片自动降级为占位符**，杜绝 400。
  - `deepseek-v4-1-flash` / `deepseek-v4-flash` / `deepseek-v4-pro` → `input: ["text","image"]` 视觉声明（V4.1 / V4 均实测可读图）。
  - 默认模型 = `deepseek-v4-flash`（xhy-agent-plan，视觉）。
- **切换注意**：若切到纯文本模型（如 ark-code-latest），`read_image` 工具不可用（会提示"模型未声明 image 输入，请切换视觉模型"），但对话不报 400、图片自动转占位符。
