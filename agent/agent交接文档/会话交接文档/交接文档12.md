## 1. 项目是什么

**校内快递配送机器人**（四川师范大学校内无人送餐/快递车）：
- **用户端**微信小程序（**20 页**）：浏览/加购/下单、微信支付（当前模拟）、订单管理、机器人配送追踪、取餐码取餐、地址/活动/售后。
- **商家端**微信小程序（**22 页**）：登录、工作台、接单（模拟扫码配单）、一车多单配单/上货、订单与售后、商品/活动管理、配送监控（真实机器人状态）、店铺设置。
- **后端**：Node.js + Express + SQLite，单进程同端口 3000 托管三个服务：
  - 小程序 API：`/api`
  - 管理员网页：`/admin`（**账号密码登录**，详见 §5）
  - 数据可视化大屏：`/dashboard`（科技风 + 3D 地图 Map3D）
- **对接**：真实 robox 开放物流平台（生产 `robox.eventec.cn`）；`PLATFORM_MOCK=false` 走真实，可切本地 Mock 演示。

远端仓库：`github.com/VesselPaper/lingdong-delivery-miniprogram`

### 4.2 管理员账号体系（方案A：账号密码 + session token）— 1e3ad96 / f32902e / 4031884
管理员网页鉴权从「共享静态 ADMIN_TOKEN」改为**用户名+密码登录 → 随机 session token**：
- 密码用 Node 内置 `crypto.scrypt` 加盐哈希（salt$hash）；session token = 32 字节随机 hex，存 `admin_sessions` 表，**默认 7 天过期**（`ADMIN_SESSION_DAYS` 可调），吊销即删行，禁用账号后全部 session 一并失效。
- 登录限流（内存）：同一「账号+IP」连续失败 `ADMIN_LOGIN_MAX=5` 次后锁定 `ADMIN_LOGIN_WINDOW_MS=10` 分钟 → 429。
- **启动守卫**（server.js）：非 demo 档必须存在 ≥1 个启用的管理员账号，否则进程启动被拒绝（exit 1）。
- 账号管理工具 `backend/tools/admin_user.js`（在 backend 目录下执行）：`add / list / disable / enable / reset`，支持 `--gen` 自动生成 16 位强密码。
- **本地库现状**（`backend/data/lingdong.db`，gitignored）：已有 2 个启用账号 —— `admin`（昵称 沈明俊）、`LDPZadmin`（昵称 零栋铺子）。**密码由创建者设定，不在文档记录**；忘了可用 `node backend/tools/admin_user.js reset --username <账号> --password xxx` 或 `--gen` 重设。

## 8. 铁律（老规矩，仍生效）

1. **两处 baseUrl**：`用户端/utils/config.js` 与 `商家端/utils/config.js` 均已改为 ENV 机制（`CURRENT='dev'`），商家端为 `LAN_BASE`。**IP 是成员本机配置，不提交**（每个人的网络环境不同，提交会互相覆盖）——改 IP 只在本地改 ENV.dev（或 LAN_BASE），提交代码时用 `git add` 指定文件、不要把这两个文件 `git add .` 带进去；pull 冲突时用 `git stash` 保留本机值（见根 README §8）。上线前必须换正式域名（当前是局域网地址，且未被 gitignore）。
2. **`.env` 不入库**（已 gitignore）：真实凭据只在本地；clone 后从 `.env.example` 复制。
3. **推送策略**：push 前先 pull，绝不 force 覆盖远端；开发建议在 `feature/summon-delivery` 上继续或开新分支，勿直接动 main。
4. **管理员密码不写文档**：账号/密码变动一律用 `backend/tools/admin_user.js` 管理，密码只当面告知。
5. **后端改动后先回归**：改配送/订单相关代码后先跑 `test_batch_flow.js` / `test_summon_flow.js` 全绿再 commit；临时脚本 `_*.js` 用完即删。
6. **提交必须先确认**：任何 git 提交（commit / push）**必须先经用户（项目负责人）明确同意**，禁止独自提交；每次提交前把待提交文件清单、提交说明展示给用户确认。
