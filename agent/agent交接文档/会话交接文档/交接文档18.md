## 二、已核实的结论（都验证过，不是推测）

### 2.1 为什么成员登不进去 —— 三个原因叠加

| # | 原因 | 证据 |
| --- | --- | --- |
| 1 | **成员的库里根本没有账号**。管理员账号在 `admin_users`、商家/用户账号在 `users`，都存在 `backend/data/lingdong.db`，而该目录**不进仓库** → clone 后是空库；且非 demo 档缺管理员会 `process.exit(1)`；商家账号又只能从管理员网页创建 → **死锁** | `backend/db.js` 建表 + `.gitignore`；`server.js:190-205` 启动守卫 |
| 2 | **双端小程序写死了负责人本机局域网 IP**（`192.168.70.50:3000`），换网络就全量请求失败，表现成"登录失败" | `用户端/utils/config.js`、`商家端/utils/config.js` 的 `BASES.develop` |
| 3 | **用户端原来完全没有账号密码入口**（只有 `wx.login` 换 openid） | `用户端/pages/user/login.js` 旧版无密码框 |

### 2.2 为什么"雷达图点了不能显示" —— 渲染器只在接口成功后才创建

- 3D 渲染器（连带**工具栏所有按钮**的事件绑定）只在第一次 `renderMap()` 里创建，而 `renderMap()` 原先**只被接口成功后的 `apply()` 调用**。
- 所以后端没起 / 接口失败时：地图区永久停在「地图数据加载中…」、工具栏每个按钮点了都没反应、**console 一条报错都没有**（完全无线索）。而楼栋/道路/雷达底图本来就来自本地标定文件，不依赖后端。
- 另外 `map3d-gl.js` 雷达底图 png 加载失败是**静默**的（只置 `groundReady=false`），表现为"按钮亮了但画面没变化"。
- 旧结论（记错）需要纠正：`可视化大屏/assets/map-calibration.js` **一直在仓库里**（2026-09-18 起随代码提交），不需要向负责人索取。`AGENTS.md` 已改正。

## 七、下次动手前的坑（本次踩到的）

- 改仓库里 CRLF 文件时，一次性脚本必须**按原文件行尾**匹配（先把 `\n` 归一化成文件实际行尾），并断言"恰好命中 1 次"，否则会静默写坏。本次所有替换脚本都带这个断言。
- **不要用 shell 读写中文文件**（`Get-Content` / `Out-File`）：会乱码并**吃掉 `<`**（历史事故导致大屏地图高度塌成 0）。用 `read`/`edit`/`write`，或 `.mjs` 里 `fs.readFileSync(p,'utf8')`。
- 写"防回归"探针时，**先确认断言点的元素/接口真实存在**：本次一开始断言了 `#m3Road`（HTML 里没有），得到"永远失败"的假警报；反过来也不能写成恒真断言（同一次也修掉了一个）。
- 大屏探针会读写服务器地图数据：跑之前先备份 `backend/data/map-recon.json` 并比对 sha256（本次前后一致）。
