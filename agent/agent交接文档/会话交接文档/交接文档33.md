## 一、项目结构：三大板块

**1. 小程序（用户端 + 商家端）**

- `用户端/`：学生下单。切店 → 加购 → 结算 → 微信支付 → 看订单与配送追踪 → 取货。
- `商家端/`：店主接单备货。商品、订单、批次卡上货、开舱关舱派发、店铺设置（本店取货点、起送价）。
- 两端都是原生小程序，`pages/` 四件套，接口清单在各自的 `utils/api.js`，请求封装在 `request.js`，后端地址在 `config.js` 的 `CLOUD_BASE`。

**2. 可视化大屏**

- `可视化大屏/`：挂在墙上常亮的那块屏。零构建 vanilla JS，`index.html` 按 `<script>` 顺序加载。
- `js/dashboard/`（外壳、接口、地图、视图）、`js/map3d-gl.js`（WebGL2 三维主渲染）、`js/scene3d/`、`js/gl3d/recon.js`（三维重构）、`assets/`（底图与标定）。
- 内容：三栏（车与批次 / 地图 / 日志）、车队卡片、批次路线、状态事件日志、店铺标识。

**3. 管理端（管理员网页 + 后端）**

- 同一个 Node 进程托管三端：`/api` 接口、`/admin/` 管理员网页、`/dashboard/` 大屏。
- `backend/server.js` 唯一入口；`backend/domains/{admin,delivery,goods,order,user}/` 每域 `routes.js` + `service.js` + `queries.js`；`backend/services/` 放跨域能力（平台对接 `platform*.js`、组单 `batch.js`、虚拟车、推送、运行时开关）。
- `管理员网页/`：原生 web，`admin.js` 装配，功能按块在 `js/parts/admin/`、`js/parts/map/`。
- 数据：内置 SQLite（`backend/data/lingdong.db`），`.env` 里配运行档（`RUN_MODE` + `PLATFORM_MOCK`）。

派发有两条路：平台 `deliveryTask/queue/create`（`delivery_mode` 为 `''` 或 `task`）、召唤 + 逐点推进（`delivery_mode` = `summon`，`SUMMON_DELIVERY=true`）。

## 二、规则

- **一个 Node 进程托管三端**，改后端要重启；本机 3000 被 `gitfox` 占用，本机测试后端走 `backend/tools/local-server.js`（默认 3100）。
- **前端零构建**：大屏和管理员网页不许引打包器 / npm；大屏 `index.html` 的 `?v=` 版本号改 JS 后要 bump。
- **大屏改动必须真浏览器回归**：`_tmp4\probes\verify\` 的 `verify_keys` / `verify_layout`（必要时 `verify_touch` / `verify_fix`）跑通、0 console 报错、末尾「校验一致 true」。`node --check` 不算验证。
- **小程序改完要在微信开发者工具真机过一遍**；双端 `config.js` 改成局域网 IP 后不要提交。
- **提交**：先得到负责人同意，只 `git add` 精确路径，同一次提交里带《git交接文档》。
- **中文文件不许用 shell 读写**（`Get-Content` / `>` 之类会按 GBK 解码、吃字符）；用编辑器或 Node 按字节读写。
- **探针和一次性脚本放 `_tmp4\probes\`**，不要留在仓库目录。
- **不同时连真实平台**：本机一律 `PLATFORM_MOCK=true`，平台实验只对 mock。
- **车的青色导航线 / 吸附网不能动**，灰色 OSM 层才是可重构对象。
- **不提前做多租户 / 多校区**，`可视化大屏/configs/default.js` 的模板不接。
