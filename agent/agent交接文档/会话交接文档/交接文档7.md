## 5. 关键业务流程（现况行为）

- **配送（Route B 直接下发，syncLoading=0）**：定型建任务 → 车自导航到上货点 → 任务状态 30=到达 → 开舱 loadingVerify → 关舱 drawerCtrl → 配送 loadingConfirm → 释放控制权。差异化：**一车多单批次**（≤12 件/仓，每单取餐码）。
- **订单状态**：0 待支付 / 1 待接单 / 2 配送中 / 3 已送达 / 4 已完成 / 5 已取消 / 6 配送异常 / 7 已退款；终态 [5, 7]。
- **批次状态**：0 组单中 / 1 待上货 / 2 配送中 / 3 已完成 / 4 已取消。
- **登录与邀请码**：商家端登录需商家邀请码（**一码一微信、首登绑定**）；老商家 openid 免码续登；未输码/错码返回 403（请填写/不正确/已绑定其他账号）；用户端登录不展示邀请码输入，填对码可升级商家。
- **优惠活动**：类型化 `custom`（自由展示）/ `discount`（商品折扣）/ `full_reduce`（满减阶梯）；**价格权威在后端**（order/create 落 `original_amount / discount_amount / activity_id`），前端仅展示估算。
- **平台适配**：底图签名「新鲜下载 + 失败重新签名重试」（签名约 14s 过期）；管理员可分页拉取平台任务。

## 7. 常用操作（接替者必读）

```bat
:: 启动后端（backend 目录）
node server.js

:: 邀请码维护（backend 目录）
node tools\merchant_invite.js add --name "店名" [--code 123456]   :: 生成随机码/指定固定码，明文只打印一次
node tools\merchant_invite.js list                                :: 看 id/商家/是否绑定/有效
node tools\merchant_invite.js revoke --id 1                       :: 吊销（active=0）
node tools\merchant_invite.js activate --id 1                     :: 重新启用
node tools\merchant_invite.js unbind --id 1                       :: 解绑，允许另一微信再用

:: 回归测试（backend 目录；全绿 exit 0，ExperimentalWarning 无害）
node test_batch_flow.js

:: 管理员页维护（需令牌）
::   POST /api/admin/reset        一键初始化
::   POST /api/admin/batch/cancel 取消批内全部活跃订单 + 批次置已取消
```

- 邀请码**首登绑定**：给商家前不要自己同码先试，否则码会绑到测试号（商家登录报「已绑定其他账号」）；同一码表内只能一条有效记录，换店名复用同码直接 `add --code 同码`（自动重新启用+清绑定+更新店名）。
- **git**：push 前 `git pull origin main`（有冲突先解）→ commit → 普通 push，**绝不 --force**；提交需用户确认。
- **bat 编码**：修改 `.bat` 后必须 **GBK + CRLF**（`[System.Text.Encoding]::GetEncoding(936)` 写入）；`.gitattributes` 已保证 checkout 恒 CRLF。
- **pwsh 内联 node** 会吃括号/引号：写临时脚本文件跑完即删，勿内联复杂脚本。
- **凭据**仅存 `backend/.env`（gitignored）；`merchant_invites` 只存哈希，明文找不回（丢了 revoke 重发）。日志已精简，勿加回刷屏日志。端口约定：3000 生产；3100 回归/临时验证。
