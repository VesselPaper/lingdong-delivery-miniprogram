## 二、已核实的结论（下个会话可直接引用，不必重查）

1. **`/admin/robot/cancel-tasks` 原语义是「取消不退钱」**：改前调 `applyOrderCancelled({reason})` 不传 `finalStatus` → 订单 `5 已取消`，无 refunds 记录、无退款调用；`refund` 语义要显式 `finalStatus: 7`。
2. **`activeOrdersByDevice`（`admin/queries.js:71`）的白名单是 `status IN (0,1,2,3,6)`，含 `3 已送达`** —— 所以「按设备取消」天然会波及「车到了、餐在舱里、用户还没取」的单；这是问题 d 的根因（`db.js:347-351` 注释里已有「已退款的餐还能开舱取走」的历史坑）。
3. **用户端能看到「为什么被取消」的唯一现成通道是售后记录**：`用户端/pages/refund/list.wxml` 渲染 `item.reason` + `item.merchant_reply`；订单详情 `detail.wxml:43` 只显示**用户自己申请取消**的 `cancel_request.reason`，自动取消不会显示。
4. **`PAY_MOCK=true` 下退款是账面行为**：`realRefundOrLocal` 仅 `pay_channel==='wxpay' && wxpay.enabled()` 才真退，否则日志 `[refund] … 仅本地标记已退款（无可退资金）`。
5. **「取餐超时驳回退款」不依赖批次状态**：`delivery/service.js → scanPickupTimeouts` 只查 `orders.status=3 AND picked_up_at IS NULL AND pickup_timeout_stage=…`，所以「批次置 4 + 已送达单保留」不会让这单卡死，它会自己走完退款。
6. **召唤的隐患仍在**：`/admin/robot/summon` 本地不落账；若平台把被中断任务置 `110/150` 回调，`platform-callbacks.js:56-61` 会 `cancelLocal({finalStatus:5})` → 订单变「已取消且不退款」。当前 `.env` 是 `SUMMON_DELIVERY` **关闭**（启动日志「召唤多单配送：关闭」），所以召唤确实是「打断」；一旦开启，召唤本身就是配送推进机制，语义会变。
7. **活性不变量抓不到「静默卡单」**：`batch.js:679-704` 只报 `ORDER_NO_BATCH / ORDER_BATCH_MISSING / ORDER_ORPHAN / ORDER_STUCK`（`ORDER_ORPHAN` 只看订单 `1/2`），「批次还在配送中、任务被中断」这种不会被报出来。
8. **管理页「配送数据」页已整页删除**（2026-10-12）：`管理员网页/index.html` 不再有 `data-page="data"` 导航项与 `#page-data`；`js/parts/admin/05-render-cards.js`（229 行）整个分片删除；导航三项＝总览 / 商家管理 / 设置。`admin.js` 产物 1381 行（`build.js` 的 `CUTS` 已按新分片重算），产物里 `renderDataPage / dataPanel / navTaskCount / dataTabs / ctxTask / actCloseVoid / orderTag / page-data` 等标识 **0 命中**。
9. **`05-render-cards.js` 与 `07-drawer.js` 之间有真依赖**：抽屉第 158 行调 `orderGoodsRows`（原定义在 05 分片，且是它全局唯一调用方），删分片会留下断链。已把它原样搬进 `07-drawer.js`。注意**跨分片的未定义引用 `node --check` 查不出来**（拼接后的 IIFE 语法完全合法），只能靠 `doc/…/06_构建机制.md` 的片间依赖表 + 浏览器实测。
10. **详情抽屉现在没有入口了**：`openDrawer` 的调用方原本全是配送数据页的卡片与右键菜单（均已删除），抽屉（状态时间线 / 实时位置 / 商品明细）与 `GET /admin/timeline` 目前前端无入口、**保留备用**；去留待用户拍板。
11. **管理员前端已不调用任何 `/admin/task/*`**：在 `管理员网页/js` 下 grep `'/task/cancel'|'/task/close'|'/task/void'|'/task/close-void'|'/precreate` 为 0 命中；接口在后端与 `doc/06` 里保留，并标注「管理页已无入口」。
