## 0. 为什么要回滚

- 曾尝试实现"同一批次多订单共享一个货仓、一次装货、多点连续投放"的多单 union 方案：
  `createTasksForBatch` 把同批次全部点位任务一次下发，并挂同一 `unionTaskId`（批次 id 派生数字）。
- **实测结论（平台边界）**：`unionTaskId` 平台按数字(int64)解析，字符串格式报 `For input string`；
  数字格式虽可过校验，但在**单货仓（一车一单）**机型下，同一舱存在多个任务会被平台拒绝
  （`DLV_MGR_0009 操作舱位已存在任务`），机器人不动。多单连投需要平台机型货仓为**多料（≥2 货仓）**类型，
  当前机型不满足。
- 用户决策：**放弃 union 多单接口**，配送逻辑**只能一单一单送**；先把稳定基线备份成 Git 分支，
  之后在备份分支基础上再改造成"召唤(lightTask) 直接控制"的多单配送。
