## 二、怎么用它（三条命令）

```
cd backend
node tools\local-server.js --fresh          # 重建测试库 + 造 3 家演示店 + 起服务（3100）
node tools\local-server.js                  # 复用已有测试库再起一次（数据保留）
node tools\local-server.js --port 3200      # 换端口
```

| 参数 | 作用 |
| --- | --- |
| `--port 3100` | 端口，默认 3100（本机 3000 被 `gitfox` 服务占着，非管理员起不来） |
| `--db <路径>` | 换库文件，默认 `backend/data/lingdong-test.db` |
| `--fresh` | 删库重建（含演示数据；`-wal`/`-shm` 一起删） |
| `--copy-real` | 用 `data/lingdong.db` 的副本起（真实数据的影子库，演练迁移/统计用） |
| `--no-seed` | 只起服务，不造多店铺演示数据 |

启动横幅会给：库路径、`/admin/`、`/dashboard/`、`/api` 地址、**本机网卡清单（标明哪张是无线/有线、哪张是 VPN/虚拟）**、3 家店与账号清单、小程序该改的那一行 `CLOUD_BASE`。

演示数据：`零栋铺子`（217 商品，营业）、`东苑超市`（6 商品，营业）、`南苑面馆`（3 商品，**歇业**，用来验"歇业店不能下单"）；账号 `LDPZmar1/2/3` 分别对应这三家店，管理员 `LDPZadmin`、学生 `LDPZstu1`，密码统一 `ldpzjkxy2026`（可用 `.env` 的 `BOOTSTRAP_*_PASSWORD` 覆盖）。

## 三、这一轮挖到的真 bug：重启把店主搬回 1 号店

**现象**：本机测试后端里 `LDPZmar2` / `LDPZmar3` 种到了 2/3 号店，登录后 `/merchant/shop` 却永远返回零栋铺子。

**根因（两处叠加）**：

1. `db.js` 启动自愈的 SQL 是 `INSERT OR IGNORE ... SELECT 1, u.id ...`，唯一索引却是 `(shop_id, user_id)` —— 换个店再插一次永远不冲突，于是**每次启动都给所有商家账号补一条 1 号店成员行**。
2. `shopOfUser` 当时按 `ORDER BY shop_id` 取最小，于是那一行 1 号店成员行赢过真正的归属，店主被静默改回 1 号店。

**为什么隔离测试没抓到**：测试每次新建临时库、只跑一次，正好躲开"第二次启动"这个条件。

**修法**：
- `services/shops.js` 新增 `backfillLegacyMembers(store)`：只补「`shop_members` 里一行都没有」的账号（`NOT EXISTS` 守卫），返回新增行数；
- `shopOfUser` 改 `ORDER BY id LIMIT 1`（以首条成员行为准，与店铺编号无关）；
- `db.js` 删掉内联 SQL，改调这个函数，实现只有一份；
- `test_shop_isolation.js` 新增第 **[12] 组 7 项断言**：自愈只补空账号、连跑两次幂等、自愈后 A/B 各在自己店；反向验证真·存量账号仍会被补进 1 号店。

**这条对生产也有意义**：云上只要重启一次（部署、改配置都会重启），任何已被搬过店的商家账号都会被打回 1 号店，而且**看不出报错**。修复随第五笔提交进仓库，但**要等云上重新部署才生效**。

## 五、本机环境的几条注意

1. **端口**：本地服务默认 **3100**；`test_shop_isolation.js` 固定用 **3110**，跑回归前确认 3110 空闲（我的本地服务一度也起在 3110，导致测试子进程 `EADDRINUSE` 死掉、健康检查却打到我的服务上，假通过后建表报错）。
2. **孤儿进程**：启动器 `spawn` 的 `node server.js` 在父进程被杀后可能继续占端口。重启前先按端口找进程：`Get-NetTCPConnection -LocalPort 3100 -State Listen` → `Stop-Process -Id <pid> -Force`。
3. **本机 WLAN 目前是断开的**（只有 PPPoE「宽带连接」和 VMware/Radmin 虚拟网卡在线），所以横幅会提示"没检测到可用的 Wi-Fi/有线网卡"。**手机预览前先把笔记本连上 Wi-Fi**，再重跑启动器拿地址。
4. **3000 仍被 `gitfox.exe` 占用**（非管理员起不来），本机后端一律别用 3000。
5. 跑回归**别用管道接输出**（`2>&1 |` 会把 SQLite 的 `ExperimentalWarning` 并进管道，pwsh 报假的 `exit code 1`）；用 `_tmp4/probes/tools/run_backend_suite.cjs` 或重定向到文件后看 `$LASTEXITCODE`。
