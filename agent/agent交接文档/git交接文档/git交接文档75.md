### 2. `backend/tools/selfcheck.js` —— 没有 .env 时不再假警报

**根因**：B 节发现 `.env` 不存在时只打印了一句"没关系"，但 C 节启动守卫用的是
**空的 `process.env`**（`spawnSync(..., env: process.env)`），于是 `runtime.check()`
必然判"运行模式与开关组合不合法"，输出红叉「✗ 会被拒绝启动」。

而实际上 `server.js` 启动时会先把 `.env.example` 复制成 `.env` 再加载，默认 demo + mock，
完全能起。新 clone 的人看到那句红叉会被直接劝退。

**改法**：`.env` 不存在时，把 `.env.example` 按同样规则读进 `process.env`，只用于校验，
并在输出里写明"已按 .env.example 的默认值进行校验，等同首次启动时实际生效的配置"。
