## 3. 遇到的问题 / 踩的坑

### P-1（严重）git 输出重定向把中文转成 UTF-16，踩了 `AGENTS.md` §9

为读远端 `AGENTS.md`，我用 `git show origin/main:AGENTS.md > file` 导出，结果 pwsh 把输出写成了 **UTF-16LE（BOM `ff fe`）**，`read` 工具判定为二进制无法读取，中文全部乱码。

- **这正是 `AGENTS.md` §9 明令禁止的**：「不要用 shell 读写中文文件……一律用编辑器 / `read` / `edit` / `write`，或写 `.mjs` 用 Node 按字节读写」。
- **教训**：需要看远端文件内容时，用 `git show <ref>:<path>` 配合 Node 按字节写盘，而不是 shell 重定向；或直接 `git log -p` 配合编辑器。
- **已确认无损害**：本次所有**源码改动**始终通过 `read`/`edit`/`write` 工具完成，事后用 `grep` 校验中文完好（`edit.js` 中「保存草稿」「请先上传活动图片」「第 N 位」等均正常）。临时导出文件已删除，仓库无残留。

### P-2（本次核心 bug）商家端活动列表显示「折扣未设置」，但库里折扣是好的

现象：商家端活动列表两条已发布活动都显示红字「折扣未设置」，而数据库里 `config` 明明是 `{"discount":0.9}`。

根因：**`config` 的数据形态两端不一致**——

| 来源 | 形态 | 按对象读 `cfg.discount` |
| --- | --- | --- |
| 用户端接口 `listActivitiesTyped` | 后端已 `JSON.parse` → 对象 | ✅ |
| 商家端接口 `merchantActivities` | **库里的原始 JSON 字符串** | ❌ → `undefined` → 兜底文案 |

用脚本实测复现：`config` 为字符串时输出「折扣未设置」，为对象时输出「9 折 · 全场商品」。

修法：在 `utils/promo.js` 的 `parseConfig()` 里统一收口（字符串/对象都能吃），**未改后端**（见 §6 遗留待办 7）。

### P-3（交互陷阱）已发布但无图的历史活动，连「仅保存」都会被拒

`#1 开学购！` 是**已发布 + 无图**。而后端对**已发布**活动的「仅保存」也校验图片（保存不能把已发布活动降级），因此商家编辑它时点「保存」或「发布」**都会失败**，但按钮文案没有提示这一点。

- 修法：编辑页对「已发布 + 无图」提前拦截并提示「请先上传活动图片」，同时顶部显示橙色说明条。
- 行为边界经脚本验证：草稿无图**放行**、纯展示/已发布/已下线无图**拦截**。

### P-4（工具环境）受限沙箱下两处命令失败
