## 二、对齐是怎么算的（关键，换图时要复现）

数据来源两条：平台 `building/mapInfo` 给 meta（世界米→雷达像素，权威）、OSM 给几何（经纬度）。

1. 取 14 个「平台取货点 ↔ OSM 同名楼栋」控制点，**相似变换 + ICP**（最近轮廓点）；
2. 残差呈系统性分布（舞蹈学院 0.8m、图书馆 2.7m vs 东苑一/二/三栋、A/C 教 14~22m），
   说明 OSM 与雷达图之间存在形变 → 改 **6 参数仿射**；
3. 再用「OSM 道路落在雷达可通行区内的比例」做**有界精化**：尺度 ±6%、旋转 ±4°、平移 ±30m。
   **不加界会把尺度炸到 396 px/m**（把所有路挤进走廊就能得高分），已踩过；
4. 最终 `20 px/m`、`18.61°`，道路压走廊、湖在环中央。

⚠ **图书馆→东苑那一段**：越凡重扫时这段本身就画错，与 OSM 真值差 15~25 m。
拟合时不让这批点参与（否则整张图的旋转/尺度被拖偏）。段内一维按 OSM 真值，需人工微调。

## 三、遇到的问题 / 踩的坑

1. **旧重构数据会毁掉新图**：服务器上还是东苑那份逐楼偏移，套到全校图上把楼搬错几十米。
   已加版本闸；`verify_keys` 里能看到 `addBlds 0 → 0`（服务器那份被正确拒绝）。
2. **默认视角必须跟着换**：`el 22 / zoom 0.85` 是东苑近视角，全校尺度下校园被压成一条薄带。
3. **楼高/车模是"世界尺寸"**：小图合适的值放到大图上只剩 1.5% 视野，整片校园塌成平板。
   两者都改成按标定跨度自适应。
4. **`num()` 被误删**：加自适应函数时把 `function num(...)` 的旧串一起替换掉了，
   `node --check` 能过但运行会炸（`num is not defined`）。教训：`node --check` 只查语法，不查未定义。
5. **`verify_labels.mjs` 的档位写死旧视角**：`[[4,0.76],[4,0.58],[3,0.47]]` 是按默认 0.85 排的，
   默认改 0.92 后到不了第三层 → 已改成 `[[5,0.65],[3,0.53],[2,0.46]]`。
   它还有另一处：`TARGET` 默认写死 3000，本机 3000 被 gitfox 占着，必须显式传 URL。
6. **Overpass 不稳定**：常 502，必须带 UA + 4 次退避重试；龙湖是 multipolygon relation，
   `out geom` 对 relation 返回 0 个点，要单独查 relation id 取 outer 成员。
7. **掩膜评分不加界会退化**：初版优化器把尺度缩到把所有道路挤进走廊，分数"变高"但变换全错。
