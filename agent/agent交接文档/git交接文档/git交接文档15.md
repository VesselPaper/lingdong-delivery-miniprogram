## 二、为什么这么改

**现象**：负责人反馈「点楼体透明没变化」，且此前提过"库房那边点位多、狭窄，车被建筑挡住看不清"。

**根因（代码 + 像素实测双重定位）**：
1. 大屏启动时 `resetView()` 把视角设成 **45°**（`map3d-gl.js` resetView 里 `view.el = 45`），而「楼体透明」淡出量是 `(el-45)/35` → **45° 时恒为 0**，屋顶照样写深度、照样把车吃掉 → 按钮在默认视角下是"死开关"。代码里声明的默认 `el: 65` 是死代码，实际没生效。
2. 车的光环/光柱原来只关 `depthMask`，**深度测试仍生效** → 车躲到楼后，标记一起被裁掉。
3. 校园尺度下车模本身小、光环线宽 1.6px、光柱顶端接近透明，1760 宽的大屏上在窄巷里根本看不见。

**像素实测（修复前，云端旧版）**：45° 点按钮只变 **0.34%**（= 动画噪声），75° 变 **5.81%**。

**改法**：淡出起点降到 20°（45° 即淡到 34% 且不写深度，20° 以内仍保持实心，保留极低视角观感）；光环/光柱关掉深度测试；车体加"穿透幽灵"；标记加屏幕像素下限 + 呼吸圈 + 顶端定位泡。

## 三、遇到的问题 / 踩的坑

1. **淡出公式的 45° 门槛恰好撞上启动视角** —— 最隐蔽的一条：只读代码容易漏（默认声明是 65°，实际是 resetView 的 45°），必须靠实测（像素差）才定位到。
2. **"同色叠同色"穿透方案**：车体再画一遍（关深度测试 + 35% 混合）。车可见时 `dst==src` → 像素不变、零影响；被挡时与建筑色 35% 混合 → 半透明车影。**不需要遮挡检测**，实现最简、行为可预期。
3. **呼吸圈相位时钟单位**：`_now` 是**秒**（`t = ts/1000`），第一次写成 `/1000 % 1` 会让呼吸圈几乎不动，已改为 `% 1`。
4. **验证方式**：不能在本机起第二个后端连真实平台（项目规矩），直接开云端页又跑的是旧文件 → 写了个**临时**只读服务 `_tmp4\probes\tools\serve_dashboard_local.mjs`：本机文件 + `/api` **只读代理**云端（GET 才放行，POST 一律 403）。用完已停。**用这种方式测不了 verify_keys/guard/fix**（它们要 POST 还原 recon 数据，借道代理会写生产）→ 这三个本次没跑；跑了的 `verify_layout` / `verify_labels` 是只读的，全部通过。
