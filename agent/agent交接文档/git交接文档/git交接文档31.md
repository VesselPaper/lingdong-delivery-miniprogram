## 二、为什么这么改（负责人 2026-10-12 要求）

- 之前微信登录只发 `code`，新用户昵称一律「微信用户」、**没有头像**；
- 负责人要求：**用户名和头像默认是用户的微信名/微信头像**；
- 微信平台规则（2021 起）：小程序**不能静默读取**用户微信昵称/头像，必须用户主动点一次 ——
  所以实现为登录页的「头像按钮点一下=微信头像」「昵称框点一下=微信昵称」，随登录建档，即"默认微信名/头像"。
- 老用户处理口径：只补默认值（空/占位），**不覆盖用户后来自己改的昵称头像**（否则每次登录都会把自设昵称改回微信名）。

## 三、遇到的问题 / 踩的坑

1. **头像在登录时没法走 `/user/avatar`**（那个接口要 auth，未登录无 token）→ 登录请求直接带 base64，后端在 `service.login` 里落盘（body limit 8mb 足够）。
2. **换图删旧图的逻辑原来内联在 routes.js**，登录也要用 → 抽成 `service.saveAvatar`，routes 与 login 共用一份，避免两处各写一套（迟早一处漏删旧图）。
3. **`type="nickname"` 的取值**：微信的"填入微信昵称"在输入法建议里，`bindinput` 与 `bindblur` 都要写才稳（部分基础库只在 blur 才拿到值）。
4. **老用户覆盖策略是设计决策**：沿用"默认"语义（只在空/占位时填），不是每次登录强制同步；已在提交说明里写清，避免后来人以为是漏改。
