## 二、遇到的问题 / 踩的坑

1. **本机模型明明是多模态，`read_image` 却一直拒绝**：根因不在模型，而在 `C:\Users\82652\.dsh\profiles\desktop\cordis.patch.yml`
   里没给该模型声明 `input: [text, image]`。补上声明后图片可读 —— 本次 34 张全部**人眼过目**过。
   注意 GUI 切换模型会重写这个文件，声明可能丢。
2. **只信视觉模型会翻车**：模型能判 `same/brand_only`，但会漏掉图上小字横幅。第一轮自动挑选的 21 张里，
   人眼刷掉 9 张：带「日期新鲜 / 多种口味 一口爆浆 / 0反式脂肪酸」的详情图、带 1688 店铺网址水印的手持图、
   把「辣翻天韩式辣鸡肉味」配成**榴莲火鸡面**、把「高汤辣牛肉汤面」配成**板面**、把「松松火山芝士」配成**爆浆牛角包**、
   带「49% 高蛋白 + 一口上瘾」的详情拼图。**结论：模型初筛 + 人眼拼图复核，两步都不能省。**
3. **API 限流伪装成「网络故障」**：并发 6 时 544 次调用里出现 **223 次 `fetch failed`**，看着像断网。
   降到并发 3 + 指数退避重试后，补跑 224 项**全部成功**。
4. **`max_tokens` 太小会让可见输出为空**：该模型会先产 `reasoning_content`，`max_tokens` 给 400 时
   `content` 为空、`finish_reason: length`。请求体加 `"thinking":{"type":"disabled"}` 后直接出 JSON。
5. **找到了门店的订货平台，但没用上**：`hnfx1.hndrp.com`（喜琳门配送中心）是门店供货平台，商品页自带条码与官方图。
   已爬完公开目录（26 分类 × 分页 = 234 请求，**2867 商品 / 2577 条条码**），但门店这 216 个商品**只有 24 个**
   在其公开货盘内、**21 个缺图商品一个都不在**；用户选择不登录平台，故未继续。爬取与比对脚本留在 `%TEMP%`（未进仓库）。
6. **`KK 醇萃浪帆黑巧味40g` 的 `KK` 其实是内部编码**：与 `DJ29E07朵蕾蜜…`、`GR226-01洁柔…`、`V1162 维达…` 一个套路；
   「醇萃浪帆」是每日黑巧的系列名，所以那张图**很可能就是真同款**（已按「疑似同款」登记）。
7. **`git pull --rebase` 遇到分叉 + 脏工作区**：远端已有 `6cab7c3`（优惠券全链路），本地还有未推送的 `b6198ae`
   和一堆别的会话没提交的改动。核对远端提交的 67 个文件后确认**没有碰** `用户端/utils/config.js`、管理员网页与 `doc/`，
   只有 `backend/db.js`、`商家端/utils/api.js`、`商家端/pages/goods/list.wxml` 与我的改动同名 → 用
   `git pull --rebase --autostash` 把其余改动暂存后 rebase，三个同名文件自动合并、**无冲突**，随后 autostash 自动恢复。
