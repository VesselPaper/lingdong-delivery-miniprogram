## 一、起因

负责人指出两处：
1. 右下角那个篮球场要建模；
2. 右下角十三栋下方还应该有个篮球场。

核查结果：

| 问题 | 核查 |
| --- | --- |
| 右下角篮球场 | OSM 里那块 **72×39m** 的多边形（way `1272677347`）**没有 `sport` 标签**，被归成 `pitch`（草地）→ 画成一片绿。它就在东苑十三栋东南约 74m |
| 十三栋下方那块 | **OSM 里根本没有**。当天拉的 OSM 数据是新的（`timestamp_osm_base` 2026-11-18T06:34Z），用 `leisure` / `sport` / `landuse` / `building+sport` 全标签面查了十三栋周边 100×200m，只有上述 5 个多边形，没有多出来的球场 |

结论：**不是 OSM 太老，是这两块没人画进 OSM**。所以走手动建模。

## 二、做法：引入「手写场地补丁」

新增 **仓库内**文件 `可视化大屏/assets/map-fields-extra.json`，两种改法，改完重跑 `emit_assets.mjs` 即可，**不用动代码**：

### 1. `reclassify` —— 按 osm_id 改判运动项目

```json
"reclassify": { "1272677347": "basketball" }
```

OSM 只画面、不写 `sport` 的场地，在这里指定项目后就会走标准球场建模。
右侧那块 72×39m 因此变成 **2×2 = 4 块篮球场**。

### 2. `fields` —— 新增 OSM 里没有的场地

按雷达像素坐标 + 尺寸放置，支持任意旋转：

```json
{ "name": "十三栋南侧篮球场", "kind": "court", "sport": "basketball",
  "cx": 11936, "cy": 23300, "ang": -64.9, "len": 28, "wid": 15 }
```

`ang` 取的是旁边那两片羽毛球场的长轴角度（-64.9°），让新场地跟它们朝向一致。

### 3. 配套：`__where()` 取坐标助手

大屏控制台执行 `__where()`，再在地图上点一下，就会打印该点的雷达像素坐标，
可以直接填进 `map-fields-extra.json` 的 `cx / cy`。这样以后补场地不用再来回问坐标。
