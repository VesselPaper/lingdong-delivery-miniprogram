## 一、负责人反馈了什么

> 操场你单独建模一下，现在你画的很难看，有两个操场画成了矩形，
> 还有一个操场稍微好一点，但是里面的矩形和外面的环形重叠了。质感都不好。

三条症状，根因是同一个**认知错误**：

| 症状 | 真正原因 |
| --- | --- |
| 两个操场画成矩形跑道 | 我用「把多边形朝质心内缩」来造分道，矩形内缩出来还是矩形环 |
| 一个操场内部矩形与外部环形重叠 | OSM 同时给了「球场矩形」和「跑道椭圆」两个面，我各画各的，椭圆内沿比球场小 → 必然穿插 |
| 质感差 | 跑道是平涂色块、没有真圆弧、没有标准球场白线 |

关键查证：**OSM 里那三块「大操场」的多边形其实是足球场本身**
（103×67m、107×68m、107×74m，正是标准 11 人制尺寸），跑道在它们外圈、不属于这个多边形。
所以跑道**往里缩**这个方向从根上就错了。

## 二、怎么重建的

**几何模型换成 stadium 形**（= 一条线段 ⊕ 一个圆盘，即"两段直线 + 两端半圆"）：

- 几何性质：向外偏移 d 只改端部半径、不改直段长度 → 分道带可以做到**严格等宽、彼此零重叠**；
- 端点天生是圆弧，不可能出现直角。

**参数在标定生成阶段算**（`emit_assets.mjs`）：

```
r0 = B + 1.5m 缓冲 + 2cm 余量
a0 = A - √(r0² - B²)        ← 由「角点必须在内沿之内」反解
```

其中 A/B 取**所有角点在本地坐标系里的真实极值**，不是"相邻边长的一半"——
实测「一号运动场」不是严格矩形，按相邻边算会让另一端的角点压到跑道上（就是那个 1.54m 的越界）。

**渲染**（`scene3d.js`）：

1. 跑道：整条铺深砖红底 → 8 条分道深浅交替 → 内外沿 + 8 条分道白线（半圆分段 22）；
2. 球场：矩形草坪 + 12 条剪草条纹 + 标准白线（边线 / 中线 / 中圈 9.15m / 两端禁区 16.5×40.32m / 球门区 5.5×18.32m / 点球点）；
3. 独立的 `leisure=track` 面**不再单独输出**——跑道已由球场参数生成，两者并存必然穿插。

顺带删掉因此失效的 `insetRing` / `ringBand` / `fieldCentroid` 三个辅助函数。

## 三、遇到的问题 / 踩的坑（重要）

1. **把 `emit_assets.mjs` 写坏了**：我用 `Set-Content -Encoding UTF8 -NoNewline` 做替换，
   整份文件塌成一行，`//` 行注释把后面的代码全部吃掉。这个脚本在 `_tmp4/`（不在仓库），**没有 git 备份**，
   只能按逻辑重写。
   → 已写进文件头注释：**改这个文件只能用 write/edit 工具或 Node 按字节读写，禁止 shell 重定向**。
2. **矩形假设导致的越界**：第一版用"最长边/相邻边"推 A/B，三块场地全部判越界
   （最小 -0.00m、最大 1.54m）。改成真实包围盒极值后才全部通过。
3. **输出取整会破坏几何约束**：参数保留两位小数后，原本刚好相切的角点会溢出几毫米，
   所以加了 2cm 安全余量。
