二、遇到的问题 / 踩的坑

1. **"文档撞号"不是文件冲突，是语义冲突。** 一开始只看到 git 报 4 个文件冲突，容易误判成
   "两边都改过同一文件、取一边即可"。实际是两条分支**各自新建了同名文件**（merge-base 里
   根本不存在这些路径），内容记录的是**不同的提交**。只看 diff 取一边 = 直接丢掉另一条线的
   项目历史。必须对比 merge-base 才能定性：`git show <base>:<path>` 报
   "exists on disk, but not in '<base>'" 就说明这是"两侧各自新增"。
   （用了 `_tmp4/probes/tools/branch_file_diff.mjs` 与 `show_side.mjs` 两个只读探针判定。）

2. **远端同号文档里已经写过一次撞号处理。** 远端的 `git交接文档15.md` 第 3 行就写着
   "本文件在本地提交时编号为 11；推送前 rebase 发现远端已有同名的 git交接文档11.md……
   为避免撞号，rebase 时把本文件顺延为 15"。也就是说成员那边**已经踩过一次同样的坑**，
   只是他们当时是"把 11 顺延到 15"，而这次我们是"把 11/13/14/15 一起顺延到 36~39"。
   这说明编号撞号的根因是**两条线在同一个基线上并行编号**，不是偶发失误。

3. **三份会话文档一直在工作区没入库。** `交接文档20/21/22` 只存在于本机，`git status` 里
   长期是 `??`。此前几轮会话都没有提交它们（因为都在"等用户确认提交清单"这一步停下）。
   这属于真实风险：换台机器/重装就丢了。
