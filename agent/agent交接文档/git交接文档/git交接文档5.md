## 二、为什么改

后端已于 2026-10-12 部署到阿里云 ECS（`47.108.151.96:3000`，systemd 单元 `lingdong`，代码在 `/opt/lingdong/releases/<时间戳>`，数据在 `/opt/lingdong/shared`）。目标是**成员 clone 下来不改任何地址**就能在微信开发者工具里跑、也能扫码在手机上预览，因此把云端地址做成仓库默认值。

## 三、遇到的问题 / 踩的坑

1. **仓库里曾经提交过负责人的本机局域网 IP**：HEAD 版两个 `config.js` 都写着 `BASES.develop = 'http://192.168.70.50:3000/api'`（注释标着 2026-10-07 当前 WLAN IP）。成员拉下来会连到负责人的电脑，换网络即失效。本次删除并收敛为一处常量。
2. **旧注释提到 `utils/push.js` 自动推导 WebSocket 地址，但用户端根本没有这个文件**（只有商家端有 `utils/push.js`），注释已改写，不再提这件事。
3. **云地址是 `http + IP`**：微信的体验版 / 正式版**不认**（必须 https 域名），只有开发版（开发者工具、扫码预览）能用。所以 `trial` / `release` 继续留 `PROD_BASE` 占位符，等域名备案后再填。
4. **仓库记忆 §8.6 与本次改动直接冲突**：老规矩写"线上/生产相关的凭据、IP 一律不进仓库"，而本次把云端 IP 写进了仓库。已向负责人说明并获同意：改为分清"地址"与"凭据"——地址是所有人小程序都要连的公开接口地址，可以进；密钥、口令、`appid`/`secret`、`.env` 本体仍一律不进。
5. 打包/部署脚本用 PowerShell 写时踩到 GBK 解码问题（本机是 PowerShell 5.1，含中文的 `.ps1` 会解析失败），已改为 `.mjs` 由 Node 执行；这条已写进项目记忆的禁忌。
