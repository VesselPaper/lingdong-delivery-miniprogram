## 二、遇到的问题 / 踩的坑（重要）

**本机推 GitHub 必须走 `127.0.0.1:7890` 代理，直连会被重置。**

时间线（2026-10-14）：
1. 之前会话里代理 7890 是通的，git 配置了 `http.proxy=https://127.0.0.1:7890`（历史结论：直连 push 被挡）。
2. 今天 7890 端口一度连不上（代理客户端没开）→ 误判为「死代理」，`git config --global --unset` 删掉了代理配置。
3. 删掉后**前两次推送直连成功了**（`32f577b`、`9df74bb`）—— 于是以为直连可以。
4. 第三次推送开始 `Connection reset` / 443 超时，反复失败约 5 次。
5. 排查发现：`Test-NetConnection github.com:443` 显示**能连**，但 git 传输阶段被重置（典型的 GFW 对 HTTPS 大流量重置）。
6. 同时发现 7890 端口**又通了**（代理客户端已重新打开）→ 把代理配置加回去，推送立刻成功。

**结论**：这台机器在 GitHub 直连时「能握手、传不动」，`git push` 必须走 7890 代理。
**别再删代理配置** —— 端口暂时不通是代理客户端没开，等它开了就好，不要 unset。
若端口又不通：先 `Test-NetConnection 127.0.0.1 -Port 7890` 确认代理客户端是否在跑，而不是改 git 配置。
