## 二、踩的坑（重点）

### 1. 用三角扇拼径向渐变 = 放射状条纹

第一版想用「中心亮、外圈暗」的径向渐变给地面做聚光感，做法是 44 段 × 3 圈三角扇。
每段是单色填充，结果出现明显的放射状条纹和同心环带。负责人反馈「不仅没有好看，而且很杂乱」。

教训：**用平色三角形拼渐变必然出条纹**，想要平滑渐变只能用贴图。

### 2. 几何地台的边缘一定是硬折线

改成「按校区边界多边形铺一层深色地台」后，边缘仍是一条生硬折线，截图里像一张深色纸片压在地图上。
多边形顶点再多也解决不了，除非做羽化 —— 而羽化只能靠贴图的透明通道。

最终方案：整块地面交给一张带 alpha 羽化的贴图，几何地台删除。

### 3. 湖面暗纹的真凶是 z-fighting，不是自交

湖面上一直有一片沿三角形边界的花纹。我一开始判断是「按形心收缩出内圈轮廓导致多边形自交」，
两次改法都没解决。后来写了个 A/B 探针（`probe_lake_ab.mjs`）：关掉风格地面贴图，湖面立刻干净。

真正原因：地面在 y=0、水面在 y=0.55，只差 0.55 个世界单位。默认视角相机距校园约 25000 单位，
24 位深度缓冲在这个距离上的精度只有几十个单位量级，两者根本分不开。

修法：地面是背景，不参与深度比较 —— 关掉深度测试、最先绘制，后面的几何直接盖上去。

顺带一个教训：诊断脚本里用 `await import()` 读 CommonJS 的 `scene3d.js`，拿到的是 `{ default: ... }`，
`S.triangulate` 是 `undefined`，于是误判成「三角化 0 个三角形、覆盖 0%」。
改用 `createRequire` 后实测三个水体覆盖都是 100%。

## 三、其他调整

- 道路从亮白 (0.86,0.92,0.98) 降到浅灰蓝 (0.62,0.71,0.80)，宽度 4.8/3.6 m 收到 4.4/3.2 m —— 原来的亮白线在深底上像粉笔划痕，是最显乱的来源之一；
- 楼名保持上一轮的限量策略：远景 14 条、中景 22、近景 40，按「面积 × 送餐楼权重 2.4」排序；
- 楼体：墙面不透明度 0.26 → 0.70，屋顶提亮成受光面，腰线与女儿墙的不透明度分别提到 0.34 / 0.78。
