## 6. 关键操作（邀请码维护，接替者必读）

```bat
cd backend
node tools\merchant_invite.js add --name "零栋铺子"      :: 生成随机码，明文只打印这一次
node tools\merchant_invite.js add --name "东苑1栋" --code 123456   :: 指定固定码
node tools\merchant_invite.js list                      :: 看 id/商家/是否绑定/有效
node tools\merchant_invite.js revoke --id 1             :: 吊销（作废，active=0）
node tools\merchant_invite.js unbind --id 1             :: 解绑，允许另一微信再用
node tools\merchant_invite.js activate --id 1           :: 重新启用
```

- 同一码表里只能一条有效记录：`revoke` 只是 `active=0`；换店名复用同码直接再 `add --code 同码`（工具自动重新启用 + 清绑定 + 更新店名，不 UNIQUE 报错）。
- **首次绑定**：真实登录态下一码一 openid；给商家前不要自己同码先试，否则码会绑到测试号（商家登录报「已绑定其他账号」）。
- **重启后端才生效**：关旧进程 → 双击根目录 `启动服务器.bat`；重启日志显示 `商家邀请码已启用：N 个有效`。

## 7. 工具与坑

- **bat 编码**：修改 `.bat` 后必须 **GBK + CRLF**（`[System.Text.Encoding]::GetEncoding(936)` 写入，行尾 `\r\n`）。`.gitattributes` 已保证 checkout 恒 CRLF。
- **git push**：push 前 `git pull origin main`（有冲突先解）→ commit → 普通 push，**绝不 --force**。
- **pwsh 内联 node** 会吃括号：写临时 `backend/_xxx.js` 跑完即删，勿内联复杂脚本。
- **凭据**仅存 `backend/.env`（gitignored），勿入库勿外泄；`merchant_invites` 只有哈希，明文找不回（丢了就 revoke 重发）。
- 日志已精简：不要加回派车/召唤/轮询刷屏日志。端口约定：3000 生产；3100 回归/临时验证。
