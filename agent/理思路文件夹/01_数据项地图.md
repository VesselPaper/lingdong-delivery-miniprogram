# 01 · 数据项地图（16 张表 → 5 个域）

> 数据来源：`backend/db.js`（建表 + migrate 追加列）。列名以代码为准，这里标注「建表即有 / 迁移追加」。
> 用途：定义每个域的专属表边界；02/03/04 链路文档把每条链路落到表；05 据此拆分模块。

---

## 1. 域归属总表

| 域 | 专属表（写权限） | 可读 | 对应路由前缀 |
|---|---|---|---|
| **user** | users、addresses、cart | — | /api/auth、/api/user/*、/api/cart/*、/api/address/* |
| **goods** | goods、shops、activities | — | /api/goods/*、/api/activity/*、/api/shop/status、/api/merchant/goods、/api/merchant/activities、/api/merchant/upload |
| **order** | orders、order_items、refunds、cancel_requests、pay_notifications | users(读 openid) | /api/order/*、/api/refund/*、/api/merchant/order/*、/api/merchant/refunds、/api/merchant/cancel-requests、/api/pay/notify |
| **delivery** | delivery_batches、delivery_tasks、landmarks | orders（读）、order_items（读件数） | /api/delivery/*、/api/merchant/delivery/*、/api/merchant/device/*、/api/merchant/map、/api/platform/* |
| **admin** | audit_logs、meta | 全部表（只读聚合） | /api/admin/*、/api/dashboard/* |

> 注意：orders 是 order 域专属，但 delivery 域大量读 orders（track、monitor、批次详情、回调、定时器）。
> 规则：**写 orders 只能来自 order 域逻辑（applyOrderCancelled 等）或 delivery 域通过 order 域 service 调用**；
> delivery 域对 orders 以只读查询为主（状态推进走 platform.applyStatus → 该函数在 delivery 域内，但订单状态迁移规则 canMoveOrderStatus 属订单状态机，归 order 域或 delivery 域需在 05 定案）。

## 2. 逐表明细

### 2.1 users（user 域）
- 建表：id / openid(UNIQUE) / nickname / avatar / phone / role(student|merchant) / created_at
- 迁移追加：order_read_at（我的页订单红点已读时间）
- 读：auth 中间件（token=openid 查用户）、order/pay JOIN users 取 openid
- 写：登录注册、/api/user/profile PUT、商家角色升级
- 注：**token = openid 本身**（demo 模式为 demo_+sha1(code)）

### 2.2 addresses（user 域）
- 建表：id / user_id / contact_name / contact_phone / landmark_id / landmark_name / detail / is_default / created_at
- 迁移修正：landmark_id 存成 "2.0" 时规范化为 "2"
- 路由：/api/address/list、/save、/delete

### 2.3 cart（user 域）
- 建表：id / user_id / goods_id / quantity / selected / created_at
- 路由：/api/cart/list、/add、/update、/remove
- 跨域：/api/order/create 下单成功后按 goods_id 删购物车（order 域写 user 域表 → 05 需定案：order.service 调用 user.service.removeCartItems）

### 2.4 landmarks（delivery 域）
- 建表：id / name / building / floor / type(deliverPoint|loadingPoint) / sort / platform_building_id / platform_map_id / platform_landmark_id
- 迁移追加：pos_x / pos_y（REAL，地图坐标）
- 读：/api/landmarks（匿名裁剪平台内部 ID）、订单点位校验、track 地图、planRoute、robotAtLoadingPoint
- 写：种子数据（db.js seed）、/api/merchant/landmarks/sync、/api/admin/landmarks/sync

### 2.5 goods（goods 域）
- 建表：id / name / price / original_price / image / category / stock / status / description / sales / created_at
- 路由：/api/goods/categories、/list、/detail；/api/merchant/goods 全套（增删改/库存/状态/分类）
- 跨域写：order 域下单扣 stock、goodsStats 结算 sales/回补 stock（goodsStats 是公共 service，归 goods 域）

### 2.6 shops（goods 域）
- 建表：id / name / business_status(open|closed) / auto_accept / updated_at
- 路由：/api/shop/status（公开）、/api/merchant/shop（GET/PUT）
- 读：下单门禁、maybeAutoAccept、自动派车扫描

### 2.7 activities（goods 域）
- 建表：id / title / subtitle / image / link / status / sort / created_at
- 路由：/api/activity/list（公开）、/api/merchant/activities 全套

### 2.8 orders（order 域）
- 建表：id / order_no(UNIQUE) / user_id / landmark_id / landmark_name / contact_name / contact_phone / total_amount / status(0-7) / remark / pickup_code / delivery_task_id / batch_id / picked_up_at / created_at / updated_at
- 迁移追加（多）：goods_settled / daily_seq / exception_handled / cancelled_at / batch_removed_at / stock_restored_at / pay_channel / transaction_id / pickup_opened_at / pickup_open_count / delivered_at / picking_up_at / pickup_timeout_stage / pickup_revisit_at
- **状态机**：0待支付 →1待接单 →2配送中 →3已送达 →4已完成；旁路 5已取消 / 6配送异常 / 7已退款（迁移规则 canMoveOrderStatus 在 platform.js:852，订单状态机归 order 域，05 定案迁移）
- 写：下单、支付、接单(并入批次)、平台回调推进、取餐关舱、取消/退款、取餐超时驳回

### 2.9 order_items（order 域）
- 建表：id / order_id / goods_id / goods_name / goods_image / price / quantity
- 写：下单时批量插入；读：订单详情、商家订单列表、批次详情

### 2.10 delivery_batches（delivery 域）
- 建表：id / batch_no(UNIQUE) / status(0-4) / status_text / device_sn / loading_landmark_id / route(JSON) / total_orders / picked_orders / created_at / updated_at / dispatched_at / completed_at
- 迁移追加：daily_seq / total_items / mock_arrive_at / ctrl_id
- 状态机：0组单中 →1待上货 →2配送中 →3已完成；异常 4已取消
- 写：best-fit 组单/新建、派车抢占(0→1)、开舱写 ctrl_id、开始配送(2)、取餐完成(3)、清理置4

### 2.11 delivery_tasks（delivery 域）
- 建表：id / order_id / batch_id / platform_task_id / device_sn / task_status(0-150) / status_text / position / updated_at
- 迁移追加：batch_id / void_at / recall_status / recall_error
- **任务状态码**（platformStatusText）：0排队中 10已接收 20去上货点 30到达上货点 40上货中 50已上货 60去取货点 70到达取货点 80完成 90上货失败 100取货失败 110取消 120上货挂起 130下货挂起 140待完善 150关闭
- 写：派车创建、开舱/关舱/配送流转、回调 applyStatus、取消作废(110+void_at)、召回标记

### 2.12 refunds（order 域）
- 建表：id / order_id / user_id / type(refund|complaint) / reason / amount / status(0待处理 2拒绝 3退款 4已处理) / merchant_reply / created_at / handled_at
- 迁移追加：wx_refund_no
- 路由：/api/refund/apply、/list；/api/merchant/refunds、/detail、/handle

### 2.13 cancel_requests（order 域）
- 建表：id / order_id / user_id / reason / status(0待处理 2拒绝 3同意) / merchant_reply / created_at / handled_at
- 路由：/api/order/cancel-request、/list；/api/merchant/cancel-requests、/detail、/handle

### 2.14 pay_notifications（order 域）
- 迁移建表：id / event_id(UNIQUE) / out_trade_no / trade_state / amount_total / created_at
- 写：/api/pay/notify 微信支付回调幂等记录

### 2.15 audit_logs（admin 域）
- 迁移建表：id / user_id / user_role / action / target / detail / created_at
- 写：audit() 函数（server.js:96）—— 商家敏感操作 + 管理员操作全部落审计
- 目前 audit() 定义在 server.js，被各路由调用 → 05 需把 audit 挪到公共模块

### 2.16 meta（admin 域）
- 迁移建表：key(PRIMARY) / value
- 写：一次性迁移标记（merchant_role_reset_at 等）
- 用途：migrate() 一次性安全修正的记录

## 3. 跨表关系图（文字版）

```
users 1──N addresses / cart / orders
orders 1──N order_items
goods 1──N order_items（goods_id 引用）
orders N──1 delivery_batches（orders.batch_id）
orders 1──1 delivery_tasks（orders.delivery_task_id；tasks 另有 order_id）
delivery_batches 1──N delivery_tasks（tasks.batch_id）
landmarks ← orders.landmark_id / batches.loading_landmark_id / route[].landmark_id（文本引用）
orders 1──N refunds / cancel_requests（order_id）
pay_notifications ← orders.order_no（out_trade_no）
```

## 4. 域间耦合点（05 拆分时必须处理）

| 耦合 | 方向 | 处理方式（05 详述） |
|---|---|---|
| 下单扣库存/删购物车 | order → goods / user | order.service 调 goods.service.deductStock + user.service.removeCart |
| 取消/退款回补库存+摘批次 | order → goods / delivery | orderCancel.service 调 goodsStats + batch |
| 接单并入批次 | order → delivery | merchant/order/confirm 调 delivery.service.addToBatch |
| 自动接单 | order → delivery/shop | maybeAutoAccept 调 batch.addOrderToBatch |
| 批次/任务读订单明细 | delivery → order | delivery.queries 只读 orders/order_items（只读不写） |
| 平台回调推进订单状态 | delivery → order | applyStatus 写 orders.status → 归 order 域状态机，由 delivery 域回调触发 |
| 取餐超时驳回（取消退款） | delivery → order | scanPickupTimeouts 调 applyOrderCancelled（order 域） |
| 派车回滚/异常处理 | delivery → order | exception/retry、refund 调 batch + orderCancel |
| admin reset | admin → 全部 | admin.service 调各域 service（orderCancel/batch/platform） |
| 大屏聚合 | admin → 全部 | 只读 SQL 聚合（可保留内联，05 定案） |
