# 02 · 链路追踪 · 用户端（按钮 → 前端 → 后端 → 数据库）

> 追踪方法：页面按钮/事件 → 页面 js（文件:行号）→ utils/api.js key → URL → server.js 路由（行号）→ 逻辑 → 数据表。
> 全部行号基于当前代码快照。本文件覆盖用户端全部 20 个页面 + 公共工具。

---

## 0. 公共请求层

- `用户端/utils/config.js`：baseUrl = `http://10.75.178.169:3000/api`（校园网 IP，换网络必改）
- `用户端/utils/request.js`：
  - `request.get/post/put/del(url, data)` → `wx.request({ url: baseUrl+url, header: {Authorization: 'Bearer '+token} })`
  - 成功判定：`statusCode===200 && data.code===0` → resolve(data.data)（递归 normalize /uploads/ 路径）
  - 401 → 清 token 跳登录页；其他错误 → 3s toast + reject(err)（err.code / err.reason）
- `用户端/utils/api.js`：全部 key → URL（见各链路引用）

## 1. 登录（pages/user/login.js）

- **按钮**：登录按钮 → `login()` → `request.post(api.login)`（key `login='/auth/login'`）
- **请求体**：`{ code, nickname, client:'user' }`
- **后端**：`server.js:115 POST /api/auth/login`
  - 真实微信登录（WX_APPID/WX_SECRET 就绪时）code2session；否则 demo 模式 openid = `demo_`+sha1(code)
  - 查/建 `users`，新用户 role 按 wantsMerchant（临时放开：client=merchant 即商家）
  - 返回 `{ token: openid, user, runtime:{mode, device_mock, pay_mock, login} }`
- **表**：users（读/写 openid、nickname、role）
- **前端后续**：存 token 与 runtimeFlags 到 storage

## 5. 确认订单（pages/order/confirm.js）★核心链路

- **按钮**：「提交订单」→ `submit()`（confirm.js:190）
  - 前端校验：店铺营业中、选了点位、姓名、手机号 `/^1\d{10}$/`
  - 件数 >12 → toast「将自动拆分为多个订单分批配送」
- **请求**：`request.post(api.orderCreate, {landmark_id, landmark_name, remark, contact_name, contact_phone, address_id, items:[{goods_id, quantity}]})`
  - key `orderCreate='/order/create'`（api.js:22）
- **后端**：`server.js:450 POST /api/order/create`
  1. 店铺歇业拦截（读 shops）
  2. 校验收餐人姓名/手机号/送达点位存在（读 landmarks type=deliverPoint）
  3. 逐行校验数量、商品存在、库存充足（读 goods）
  4. 总件数 > `batch.BATCH_MAX_ITEMS(12)` → `splitOrderChunks` 贪心拆单
  5. 每 chunk 插入 `orders`（status=0 待支付、生成 order_no=LD+时间戳、pickup_code=4位、daily_seq）
  6. 每 chunk 插入 `order_items` + 条件扣减 `goods.stock`
  7. 删除 `cart` 中本次下单商品
  8. 返回单订单 or `{orders:[], split:true}`
- **前端后续**：`pay.payOrder(oid)`（utils/pay.js）逐单支付
- **表**：shops(读)、landmarks(读)、goods(读+扣 stock)、orders(写)、order_items(写)、cart(删)

## 6. 支付（utils/pay.js ← pages/order/confirm.js 调用）

- `pay.payOrder(orderId)` → `request.post(api.orderPay, {id})`（key `orderPay='/order/pay'` server.js:526）
- **后端逻辑**：非真实支付档（PAY_MOCK=true）→ 直接 `orders.status=1`（pay_channel='mock'）→ `maybeAutoAccept`（见商家端接单链路）；真实档 → wxpay.jsapiPay 返回支付参数，前端 wx.requestPayment
- **表**：orders（status 0→1、pay_channel）、users(读 openid)、shops(读，自动接单判断)
- **微信回调**：`POST /api/pay/notify`（server.js:562）验签→幂等（写 pay_notifications）→金额比对→CAS 置 1→maybeAutoAccept

## 8. 取消订单（pages/order/detail.js 内按钮）

- **按钮**：「取消订单」→ `request.post(api.orderCancel, {id})`（key `orderCancel='/order/cancel'` server.js:686）
- **后端**：状态白名单（0/1/2 可取消，3/4/6 走退款）、免费窗口内（FREE_CANCEL_WINDOW_MS 10min）才允许直接取消 → `applyOrderCancelled(order)`
- **applyOrderCancelled（server.js:378）**：
  - `orderCancel.cancelLocal(store, order, opts)`（services/orderCancel.js:60）：
    - `claimCancelled` CAS：orders.status→5 + cancelled_at（并发/幂等锁）
    - `voidTasks`：本单 delivery_tasks 非终态全部置 110 + void_at
    - `goodsStats.restoreStock`：未结算则回补 goods.stock（stock_restored_at 幂等）
    - `batch.removeOrderFromBatch`：批次计数回退（batch_removed_at 幂等，空批次置4）
    - `stopMock`：停掉模拟推进定时器
  - 之后对每个被作废任务：排队中(<10)走 `platform.cancelQueueTask`；已上货走 `platform.closeTask`（真机召回），结果写 recall_status/recall_error
- **表**：orders、delivery_tasks、goods、delivery_batches

## 12. 配送追踪（pages/delivery/track.js）★核心链路

- **入口**：订单详情/列表点「追踪」→ `request.get(api.deliveryTrack, {order_id})`（key `deliveryTrack='/delivery/track'` server.js:873）
- **后端逻辑**：
  1. 读 orders、delivery_tasks（本地）
  2. `platform.getDevicePosition(store, task.id)`（platform.js:995）：EvizServer 代理 → 解析 robotpose → `robotposeToMeters` 相似变换 → 米制坐标（3s 缓存）
  3. 归一化为地图百分比坐标（8% 内边距，bbox 来自 `platform.getMapBbox`）
  4. 组装 map：bbox + 全部带坐标点位（landmarks 读 pos_x/pos_y）+ 批次 route 停靠点（读 delivery_batches.route JSON + landmarks）
  5. batch 信息：同批订单总数/已取数（orders 聚合）
  6. 文案：无任务/取餐超时阶段特化（读 orders.pickup_timeout_stage/picking_up_at）
- **表**：orders、delivery_tasks、delivery_batches、landmarks（读）；平台数据（position/map）

## 13. 取餐页（pages/delivery/pickup.js、scanPickup.js）★核心链路

两条入口：
- 订单页进入：`api.pickupScan` POST `/delivery/pickup-scan`（server.js:1017）→ pickupContext（读 orders/delivery_tasks/delivery_batches 同批订单）
- 扫车码进入：`wx.scanCode` → `scan.parseDeviceSn` → `api.pickupByScan` POST `/delivery/pickup-by-scan`（server.js:1039，按 user+device_sn+status=3 自动匹配本人订单，匹配不到前端回退输码）→ 或 `api.pickupByCode` POST `/delivery/pickup-by-code`（server.js:1025，user+取餐码+device_sn 校验）

**开舱（取餐）**：
- **按钮**：「打开舱门」→ `openBin()`（pickup.js:38 / scanPickup.js:97）→ `request.post(api.pickupOpen, {order_id})`（key `pickupOpen='/delivery/pickup-open'` server.js:1057）
- **后端**：
  1. 订单归属 + status∈{3,4}
  2. 重开限时：pickup_opened_at + PICKUP_REOPEN_WINDOW_MS(10min) 内才允许
  3. CAS 抢占：`pickup_open_count<MAX(3)` 且 status∈{3,4} → 置 pickup_opened_at（首次）、pickup_open_count+1、picking_up_at=now（「正在取餐」计时暂停）
  4. 任务就绪（device_sn+platform_task_id）→ `platform.unloadingVerify`（platform.js:1297，unloading/verify 开舱）
- **表**：orders（pickup_opened_at/pickup_open_count/picking_up_at）、delivery_tasks(读)

**关舱（取走）**：
- **按钮**：「关闭舱门」→ `closeBin()` → `request.post(api.pickupClose, {order_id})`（key `pickupClose='/delivery/pickup-close'` server.js:1090）
- **后端**：`platform.unloadingConfirm`（关舱返回）→ 清 picking_up_at → `batch.markOrderPicked`（orders.status→4 + picked_up_at；goodsStats.settleSales 结算销量；delivery_batches.picked_orders+1；maybeCompleteBatch → 批次置3）
- **表**：orders、goods（sales+）、delivery_batches（picked_orders、status）

**40s 自动关舱**：前端倒计时到 0 显示 autoClosed（可 reopen）；平台侧 40s 未调用自动关舱，任务流转 80 由 applyStatus/onTaskStatus 走同一路径标记已取走。
